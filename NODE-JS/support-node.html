01

C'est quoi Node.js ?

Fondamentaux

Node.js est un environnement d'exécution JavaScript basé sur le moteur V8 de Chrome. Il permet de faire tourner du JavaScript en dehors du navigateur — sur un serveur, en ligne de commande, etc.

Analogie : le navigateur est un interprète JS pour l'interface utilisateur. Node.js est un interprète JS pour le serveur. C'est le même langage (JS) mais dans des environnements différents — pas de window, pas de DOM, mais accès au système de fichiers, au réseau, aux processus…
Non-bloquant
Node utilise un modèle asynchrone et non-bloquant. Pendant qu'il attend une réponse BDD, il traite d'autres requêtes. Idéal pour les APIs avec beaucoup de requêtes simultanées.
Single thread
Un seul fil d'exécution (contrairement à PHP/Java). L'Event Loop gère la concurrence de façon asynchrone avec des callbacks, Promises et async/await.
NPM
Node Package Manager — le plus grand registre de paquets au monde. Des centaines de milliers de librairies disponibles avec npm install.
Cas d'usage
APIs REST, applications temps réel (chat, notifications), outils CLI, microservices. Utilisé par Netflix, LinkedIn, Uber, PayPal…

Installation & NVM

Installe Node.js via NVM (Node Version Manager) — cela permet de gérer plusieurs versions de Node sur la même machine et de switcher facilement selon les projets.

terminal — installation NVM
# ── Mac / Linux ── (coller dans le terminal)
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash

# Recharger le shell
source ~/.zshrc   # ou ~/.bashrc selon ton shell

# Installer la dernière version LTS de Node
nvm install --lts
nvm use --lts

# ── Windows ── : télécharger nvm-windows
# https://github.com/coreybutler/nvm-windows/releases

# Vérifier les installations
node --version    # v20.x.x
npm  --version    # 10.x.x
terminal — commandes NVM utiles
# Lister les versions installées
nvm list

# Installer une version spécifique
nvm install 18

# Changer de version pour le projet courant
nvm use 18

# Version par défaut
nvm alias default 20

# Exécuter un fichier JS
node app.js

# REPL interactif Node.js (comme la console du navigateur)
node

Modules — CommonJS & ES Modules

Essentiel

Node.js organise le code en modules. Il existe deux systèmes : CommonJS (l'historique, avec require) et ES Modules (le moderne, avec import/export). Comprendre les deux est indispensable.

commonJS — require/module.exports (encore très utilisé)
//  utils.js  (on exporte)
function additionner(a, b) {
    return a + b;
}

const PI = 3.14159;

module.exports = { additionner, PI };

//  app.js  (on importe)
const { additionner, PI } = require('./utils');
console.log(additionner(3, 4)); // 7

// Importer un module natif Node.js
const path = require('path');
const fs   = require('fs');
const http = require('http');

// Importer un paquet npm
const express = require('express');
ES Modules — import/export (moderne, nécessite "type":"module" dans package.json)
//  utils.js  (on exporte)
export function additionner(a, b) { return a + b; }
export const PI = 3.14159;
export default function main() { console.log('main'); }

//  app.js  (on importe)
import main, { additionner, PI } from './utils.js';
// Avec ESM, l'extension .js est OBLIGATOIRE dans l'import

// Import d'un module natif
import { readFile } from 'fs/promises';
import path from 'path';
Quelle syntaxe choisir ? Pour les nouveaux projets, préfère ES Modules (import/export) — c'est le standard moderne JS. Pour travailler avec des tutoriels existants ou des projets anciens, tu verras souvent require. Avec Express, les deux fonctionnent.
modules natifs Node.js — path & os
const path = require('path');

// Construire un chemin de façon cross-platform (Mac/Windows)
const fichier = path.join(__dirname, 'data', 'users.json');
// → /home/thomas/projet/data/users.json

console.log(path.basename(fichier));  // 'users.json'
console.log(path.dirname(fichier));   // '/home/thomas/projet/data'
console.log(path.extname(fichier));   // '.json'
console.log(path.resolve('./app.js')); // chemin absolu

const os = require('os');
console.log(os.platform());  // 'darwin' / 'linux' / 'win32'
console.log(os.homedir());   // '/Users/thomas'
console.log(os.cpus().length); // nombre de CPUs

NPM & package.json

package.json est le fichier de configuration de tout projet Node.js. Il liste les dépendances, les scripts et les métadonnées du projet. C'est l'équivalent du composer.json en PHP.

terminal — commandes NPM essentielles
# Initialiser un projet (crée package.json)
npm init -y     ← -y accepte tous les paramètres par défaut

# Installer un paquet (dépendance de production)
npm install express
npm i express    ← raccourci

# Installer un paquet de développement uniquement
npm install --save-dev nodemon
npm i -D nodemon  ← raccourci

# Installer toutes les dépendances d'un projet existant
npm install ← lit le package.json

# Désinstaller un paquet
npm uninstall express

# Lancer un script défini dans package.json
npm run dev
npm start

# Voir les paquets installés
npm list
npm list --depth=0  ← seulement le premier niveau

# Mettre à jour les paquets
npm update
package.json — structure complète annotée
{
  "name": "mon-api",
  "version": "1.0.0",
  "description": "API REST DWWM",
  "main": "src/app.js",     // point d'entrée
  "type": "module",         // activer ES Modules

  "scripts": {
    "start": "node src/app.js",
    "dev":   "nodemon src/app.js",    // redémarre automatiquement
    "test":  "jest"
  },

  "dependencies": {
    "express":  "^4.18.2",   // ^ = mise à jour mineure OK
    "dotenv":   "^16.3.1",
    "mysql2":   "^3.6.0"
  },

  "devDependencies": {
    "nodemon": "^3.0.1"     // seulement en développement
  }
}
Toujours ajouter node_modules/ dans ton .gitignore ! Ce dossier peut peser des centaines de Mo. Tes collègues peuvent le recréer avec npm install depuis le package.json.

Async, Promises & async/await

Clé de Node.js

Toutes les opérations lentes (fichiers, BDD, réseau) sont asynchrones en Node.js. Il faut les gérer avec des Promises ou async/await.

JS — les 3 façons de gérer l'asynchrone
// ── 1. Callback (ancien style — à éviter) ──
fs.readFile('data.json', 'utf8', (err, data) => {
    if (err) throw err;
    console.log(data);
});

//  2. Promise 
fs.promises.readFile('data.json', 'utf8')
    .then(data => console.log(data))
    .catch(err => console.error(err));

//  3. async/await (style recommandé) ──
async function lireFichier() {
    try {
        const data = await fs.promises.readFile('data.json', 'utf8');
        const json = JSON.parse(data);
        console.log(json);
    } catch (err) {
        console.error('Erreur :', err.message);
    }
}
lireFichier();

// Exécuter plusieurs opérations en parallèle
async function parallelFetch() {
    const [users, posts] = await Promise.all([
        fetch('https://api.example.com/users').then(r => r.json()),
        fetch('https://api.example.com/posts').then(r => r.json()),
    ]);
    // Les deux requêtes partent en même temps !
}

Module fs — Fichiers & dossiers

Node.js — lire, écrire, gérer des fichiers
import { readFile, writeFile, appendFile, unlink, readdir, mkdir } from 'fs/promises';
import { existsSync } from 'fs';

// Lire un fichier texte
const contenu = await readFile('./data/users.txt', 'utf8');

// Lire un fichier JSON
const raw   = await readFile('./data/users.json', 'utf8');
const users = JSON.parse(raw);

// Écrire dans un fichier (écrase si existe)
await writeFile('./data/output.json', JSON.stringify(users, null, 2), 'utf8');

// Ajouter à la fin d'un fichier (logs)
await appendFile('./logs/app.log', `[${new Date().toISOString()}] Connexion\n`);

// Vérifier l'existence (synchrone)
if (existsSync('./data/users.json')) {
    console.log('fichier trouvé');
}

// Lister le contenu d'un dossier
const fichiers = await readdir('./data');
console.log(fichiers); // ['users.json', 'output.json']

// Créer un dossier (recursive: true évite l'erreur si existe déjà)
await mkdir('./logs/2024', { recursive: true });

// Supprimer un fichier
await unlink('./data/temp.txt');

Serveur HTTP natif

Node.js peut créer un serveur HTTP sans aucune dépendance. C'est pédagogique pour comprendre le fonctionnement d'Express, mais en pratique on utilise Express pour sa simplicité.

server.js — serveur HTTP minimal
import { createServer } from 'http';

const PORT = 3000;

const server = createServer((req, res) => {
    // req = requête (URL, méthode, headers, body…)
    // res = réponse (on écrit dedans)

    const url = req.url;
    const method = req.method;

    if (url === '/' && method === 'GET') {
        res.writeHead(200, { 'Content-Type': 'application/json' });
        res.end(JSON.stringify({ message: 'Bienvenue !' }));

    } else if (url === '/users' && method === 'GET') {
        const users = [{ id: 1, nom: 'Alice' }];
        res.writeHead(200, { 'Content-Type': 'application/json' });
        res.end(JSON.stringify(users));

    } else {
        res.writeHead(404, { 'Content-Type': 'application/json' });
        res.end(JSON.stringify({ erreur: 'Route introuvable' }));
    }
});

server.listen(PORT, () => {
    console.log(`🚀 Serveur démarré sur http://localhost:${PORT}`);
});
🔍
Tu vois à quel point le routage natif devient vite verbeux avec des if/else. Express résout exactement ce problème avec un système de routes élégant. C'est pour ça qu'on l'utilise !

Variables d'environnement & dotenv

Sécurité

Les variables d'environnement permettent de stocker des informations sensibles (mots de passe BDD, clés API, port) en dehors du code source, dans un fichier .env ignoré par Git.

.env — variables d'environnement
# .env  ← à mettre dans .gitignore OBLIGATOIREMENT
PORT=3000
NODE_ENV=development

DB_HOST=localhost
DB_PORT=3306
DB_NAME=blog_dwwm
DB_USER=root
DB_PASS=mon_mot_de_passe

JWT_SECRET=une_clé_secrète_très_longue_et_aléatoire
app.js — charger dotenv (Node < 20) ou directement (Node 20+)
// ── Méthode 1 : paquet dotenv (toutes versions) ──
npm i dotenv

import 'dotenv/config';         // ESM
// OU
require('dotenv').config();    // CommonJS

//  Méthode 2 : Node 20+ (sans paquet) 
node --env-file=.env app.js

//  Accéder aux variables 
const PORT   = process.env.PORT   || 3000;
const DB_HOST = process.env.DB_HOST;

console.log(process.env.NODE_ENV); // 'development'

//  Bonne pratique : créer un .env.example 
# .env.example  ← celui-ci EST dans git (sans les vraies valeurs)
PORT=3000
DB_HOST=localhost
DB_PASS= ← vide, chaque dev met la sienne

Debug & Nodemon

terminal + package.json — setup développement
# Nodemon : redémarre automatiquement à chaque sauvegarde
npm i -D nodemon

# Dans package.json :
"scripts": {
    "dev": "nodemon --env-file=.env src/app.js",
    "start": "node src/app.js"
}

# Lancer en mode développement
npm run dev

# ── Débogage avec VS Code ──
# Créer .vscode/launch.json
{
    "version": "0.2.0",
    "configurations": [{
        "type": "node",
        "request": "launch",
        "name": "Debug Node",
        "program": "${workspaceFolder}/src/app.js",
        "envFile": "${workspaceFolder}/.env",
        "skipFiles": ["<node_internals>/**"]
    }]
}
🐛
console.log vs debugger : console.log suffit pour 90% des cas. Pour inspecter des objets complexes utilise console.dir(obj, {"{"}depth:null{"}"} ). Le debugger VS Code avec breakpoints est indispensable pour les bugs difficiles à trouver.
