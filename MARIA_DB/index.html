01

C'est quoi MariaDB ?

MariaDB est un système de gestion de base de données relationnelle (SGBDR) open source, fork de MySQL. On y stocke des données sous forme de tables (lignes + colonnes) et on les manipule avec le langage SQL.

Base de données
Conteneur de toutes les tables d'une application. Ex : boutique_db
Table
Un tableau de données. Chaque ligne = un enregistrement. Ex : client
🔑
Clé primaire (PK)
Identifiant unique de chaque ligne. Ex : id_client = 1
🔗
Clé étrangère (FK)
Lien entre deux tables. Ex : id_client dans COMMANDE
🐬
MariaDB vs MySQL : les commandes SQL sont quasi-identiques. Tout ce que tu apprends ici fonctionne sur MySQL aussi. MariaDB est installé par défaut avec XAMPP, WAMP, et la plupart des hébergements.

Avant d'écrire du SQL, il faut se connecter au serveur MariaDB. Voici les deux façons : en ligne de commande ou via une interface graphique.

Se connecter à MariaDB
$mysql -u root -p
↳ -u root = nom d'utilisateur "root"
↳ -p = demander le mot de passe

Interface graphique : tu peux aussi utiliser phpMyAdmin (inclus dans XAMPP) ou DBeaver (gratuit, recommandé) pour visualiser les tables et exécuter du SQL avec une interface.
Commandes utiles dans le terminal MariaDB
MariaDB [(none)]> SHOW DATABASES;
↳ lister toutes les bases de données

MariaDB [(none)]> USE boutique_db;
↳ sélectionner une base pour travailler dedans

MariaDB [boutique_db]> SHOW TABLES;
↳ lister les tables de la base active

MariaDB [boutique_db]> DESCRIBE client;
↳ afficher la structure d'une table

↳ quitter le terminal MariaDB
Le point-virgule est obligatoire ! Chaque requête SQL doit se terminer par ;. Sans ça, MariaDB attend la suite et ne s'exécute pas.
03

Créer la base de données

La première étape est de créer un conteneur qui accueillera toutes nos tables. On appelle ça la base de données.

Créer et sélectionner la baseSQL
-- Créer la base de données
CREATE DATABASE boutique_db
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

-- La sélectionner pour travailler dedans
USE boutique_db;

-- Version sécurisée : ne pas planter si elle existe déjà
CREATE DATABASE IF NOT EXISTS boutique_db;
utf8mb4 — l'encodage qui supporte tous les caractères : accents français, emojis, caractères asiatiques… Toujours l'utiliser plutôt que utf8 seul qui est incomplet.
Supprimer / renommerSQL
-- Supprimer une base (ATTENTION : irréversible !)
DROP DATABASE IF EXISTS boutique_db;

-- Lister toutes les bases disponibles
SHOW DATABASES;
04

Définir le schéma — CREATE TABLE

Le schéma c'est la structure de chaque table : les colonnes, leurs types, leurs contraintes. On le définit avec CREATE TABLE. Voici le schéma complet de notre boutique.

Table clientSQL
CREATE TABLE client (
    id_client   INT           AUTO_INCREMENT PRIMARY KEY,  ← clé primaire
    nomVARCHAR(100) NOT NULL,
    prenom      VARCHAR(100) NOT NULL,
    emailVARCHAR(150) NOT NULL UNIQUE,← unique
    telephoneVARCHAR(20),
    adresseTEXT,
    date_inscription DATETIME DEFAULT NOW()← valeur auto
);
Table categorieSQL
CREATE TABLE categorie (
    id_categorie  INTAUTO_INCREMENT PRIMARY KEY,
    nom VARCHAR(100) NOT NULL UNIQUE,
    description   TEXT
);
Table produit — avec clé étrangèreSQL
CREATE TABLE produit (
    id_produit   INT              AUTO_INCREMENT PRIMARY KEY,
    nomVARCHAR(200)    NOT NULL,
    prix DECIMAL(10,2)  NOT NULL,
    stock  INT  DEFAULT 0,
    description  TEXT,
    id_categorie INT NOT NULL,
    FOREIGN KEY (id_categorie) REFERENCES categorie(id_categorie)
);
Table commande + Table commande_produit (N,N)SQL
CREATE TABLE commande (
    id_commande   INT         AUTO_INCREMENT PRIMARY KEY,
    date_commande DATETIME    DEFAULT NOW(),
    statut        ENUM('en_attente','validee','expediee','livree') DEFAULT 'en_attente',
    montant_total DECIMAL(10,2),
    id_client     INT         NOT NULL,
    FOREIGN KEY (id_client) REFERENCES client(id_client)
);

-- Table intermédiaire issue de l'association N,N
CREATE TABLE commande_produit (
    id_commande  INT  NOT NULL,
    id_produit   INT  NOT NULL,
    quantite     INT  NOT NULL DEFAULT 1,
    PRIMARY KEY (id_commande, id_produit),  ← clé composite
    FOREIGN KEY (id_commande) REFERENCES commande(id_commande),
    FOREIGN KEY (id_produit)  REFERENCES produit(id_produit)
);

Types de données & Contraintes

Chaque colonne a un type (quel genre de données) et des contraintes (règles à respecter).

TypeUtilisationExemple
INTNombre entier42, -5, 0
DECIMAL(10,2)Nombre décimal précis (prix)29.99, 1299.00
VARCHAR(n)Texte court variable, max n caractères'Alice', 'Paris'
TEXTTexte long (description, contenu)Un long paragraphe…
DATETIMEDate et heure2025-03-11 14:30:00
DATEDate seule2025-03-11
BOOLEANVrai / Faux (TINYINT(1) en interne)TRUE, FALSE
ENUM('a','b')Valeur parmi une liste fixe'en_attente', 'validee'
ContrainteRôle
PRIMARY KEYIdentifiant unique de la ligne — obligatoire, pas de doublons, pas de NULL
AUTO_INCREMENTMariaDB génère l'id automatiquement (1, 2, 3…)
NOT NULLLa colonne ne peut pas être vide — obligatoire
UNIQUEPas deux lignes avec la même valeur (email unique)
DEFAULT valeurValeur utilisée si on ne précise rien à l'insertion
FOREIGN KEYLien vers la PK d'une autre table — intégrité référentielle
06 — CREATE

INSERT — Ajouter des données

C
CREATE → INSERT INTO … VALUES …
INSERT — syntaxe complèteSQL
-- Insérer un seul enregistrement
INSERT INTO client (nom, prenom, email, telephone)
VALUES ('Dupont', 'Alice', 'alice@email.com', '0612345678');

-- Insérer plusieurs enregistrements en une seule requête
INSERT INTO categorie (nom, description)
VALUES
    ('Audio',       'Casques, enceintes, écouteurs'),
    ('Accessoires', 'Claviers, souris, câbles'),
    ('Écrans',      'Moniteurs et écrans PC');

-- Insérer un produit avec clé étrangère
INSERT INTO produit (nom, prix, stock, id_categorie)
VALUES ('Casque Sony WH-1000XM5', 279.99, 12, 1);
id_client non précisé ? Pas de problème — il est AUTO_INCREMENT donc MariaDB lui attribue automatiquement la prochaine valeur disponible (1, 2, 3…). Ne pas l'inclure dans la liste des colonnes.
Erreur fréquente
INSERT INTO client
VALUES ('Dupont', 'Alice');
← sans préciser les colonnes
→ MariaDB attend TOUTES les colonnes
dans l'ordre exact du CREATE TABLE
Bonne pratique
INSERT INTO client (nom, prenom, email)
VALUES ('Dupont', 'Alice', 'a@b.fr');
← toujours nommer les colonnes
→ plus lisible, plus sûr
07 — READ

SELECT — Lire les données

R
READ → SELECT … FROM … WHERE …
SELECT — du basique au filtréSQL
-- Tout sélectionner (éviter en production)
SELECT * FROM client;

-- Sélectionner des colonnes précises
SELECT nom, prenom, email FROM client;

-- Filtrer avec WHERE
SELECT * FROM client
WHERE nom = 'Dupont';

-- Plusieurs conditions
SELECT * FROM produit
WHERE prix < 100 AND stock > 0;

-- Trier les résultats
SELECT nom, prix FROM produit
ORDER BY prix ASC;    -- ASC = croissant, DESC = décroissant

-- Limiter le nombre de résultats
SELECT * FROM produit
ORDER BY prix DESC
LIMIT 5;   -- les 5 produits les plus chers
WHERE — opérateurs de filtrageSQL
-- Égalité / différence
WHERE statut = 'validee'
WHERE statut != 'livree'

-- Comparaisons numériques
WHERE prix >= 50 AND prix <= 200
WHERE prix BETWEEN 50 AND 200    ← équivalent, plus lisible

-- Recherche dans une liste
WHERE statut IN ('validee', 'expediee')

-- Recherche textuelle (% = n'importe quoi)
WHERE nom LIKE '%sony%'      ← contient "sony"
WHERE email LIKE '%@gmail.com' ← se termine par @gmail.com

-- Valeur nulle
WHERE telephone IS NULL
WHERE telephone IS NOT NULL
Fonctions d'agrégationSQL
-- Compter les lignes
SELECT COUNT(*) FROM client;
SELECT COUNT(*) FROM produit WHERE stock = 0;

-- Min, Max, Moyenne, Somme
SELECT
    MIN(prix)  AS prix_minimum,
    MAX(prix)  AS prix_maximum,
    AVG(prix)  AS prix_moyen,
    SUM(stock) AS stock_total
FROM produit;

-- Grouper par catégorie
SELECT id_categorie, COUNT(*) AS nb_produits
FROM produit
GROUP BY id_categorie;
08 — UPDATE

UPDATE — Modifier des données

U
UPDATE → UPDATE … SET … WHERE …
UPDATE — modifier des lignesSQL
-- Modifier un seul champ
UPDATE client
SET email = 'nouvelle@adresse.com'
WHERE id_client = 1;

-- Modifier plusieurs champs à la fois
UPDATE produit
SET
    prix  = 249.99,
    stock = stock - 1    ← décrémenter le stock
WHERE id_produit = 3;

-- Modifier plusieurs lignes en une seule requête
UPDATE commande
SET statut = 'expediee'
WHERE statut = 'validee'
  AND date_commande < '2025-01-01';
TOUJOURS mettre un WHERE ! Un UPDATE sans WHERE modifie toutes les lignes de la table. C'est l'une des erreurs les plus catastrophiques en SQL. Avant d'exécuter, vérifier avec un SELECT la condition.
DANGER — sans WHERE
UPDATE client
SET email = 'hacker@evil.com';
↳ TOUS les clients ont maintenant
  la même adresse email !
Correct — avec WHERE
UPDATE client
SET email = 'alice@new.fr'
WHERE id_client = 1;
↳ Seul le client n°1 est modifié
09 — DELETE

DELETE — Supprimer des données

D
DELETE → DELETE FROM … WHERE …
DELETE — supprimer des lignesSQL
-- Supprimer un enregistrement précis
DELETE FROM client
WHERE id_client = 5;

-- Supprimer selon une condition
DELETE FROM produit
WHERE stock = 0 AND prix < 10;

-- Vider toute la table (garder la structure)
TRUNCATE TABLE produit;   ← remet aussi l'AUTO_INCREMENT à 1

-- Supprimer la table entièrement (structure + données)
DROP TABLE IF EXISTS produit;
Même règle qu'UPDATE : un DELETE sans WHERE supprime toutes les lignes. Idem pour les clés étrangères — impossible de supprimer un client qui a des commandes (contrainte FK). Il faut supprimer les commandes d'abord.
Résumé CRUD
C — INSERT
Ajouter des lignes
R — SELECT
Lire des lignes
U — UPDATE
Modifier des lignes
D — DELETE
Supprimer des lignes
10

Jointures — lier plusieurs tables

Dans une vraie base, les données sont réparties dans plusieurs tables. Les jointures permettent de les combiner dans une seule requête SELECT.

INNER JOIN — le plus courantSQL
-- Afficher chaque commande avec le nom du client
SELECT
    c.id_commande,
    c.date_commande,
    c.statut,
    cl.nomAS nom_client,
    cl.emailAS email_client
FROM commande c
INNER JOIN client cl ON c.id_client = cl.id_client
WHERE c.statut = 'en_attente';
JOIN sur 3 tables — commande + produits + clientSQL
SELECT
    cl.nomAS client,
    co.date_commande,
    p.nomAS produit,
    cp.quantite,
    p.prixAS prix_unitaire
FROM commande_produit cp
INNER JOIN commande co ON cp.id_commande = co.id_commande
INNER JOIN produit  p  ON cp.id_produit  = p.id_produit
INNER JOIN client   cl ON co.id_client   = cl.id_client
ORDER BY co.date_commande DESC;
INNER JOIN vs LEFT JOIN : INNER JOIN retourne uniquement les lignes qui ont une correspondance dans les deux tables. LEFT JOIN retourne toutes les lignes de la table de gauche, même si aucune correspondance n'existe à droite (valeur NULL).
LEFT JOIN — inclure les produits sans catégorieSQL
-- Tous les produits, même sans catégorie
SELECT
    p.nomAS produit,
    p.prix,
    cat.nomAS categorie   ← NULL si pas de catégorie
FROM produit p
LEFT JOIN categorie cat ON p.id_categorie = cat.id_categorie;
11

Bonnes pratiques

Nommage des tables
Toujours en minuscules avec underscores.
Noms au singulier : client pas clients.
Préfixer les FK : id_client.
Toujours un WHERE
Pour UPDATE et DELETE, toujours vérifier avec un SELECT avant d'exécuter.
Utiliser l'id comme critère de préférence.
Ordre de création
Créer les tables référencées en premier.
categorie avant produit.
client avant commande.
Commentaires SQL

-- 5. Données de test
