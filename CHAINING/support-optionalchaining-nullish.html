?. & ??

Optional Chaining · Nullish Coalescing · Securiser les donnees

01

Le probleme qu'ils resolvent

Quand tu travailles avec des donnees d'une API, tu n'as jamais la garantie que toutes les proprietes existent. Une propriete peut etre undefined, null, ou tout simplement absente.

Acceder a une propriete sur undefined ou null provoque une TypeError qui plante toute ton application. Ces deux operateurs ont ete crees exactement pour eviter ca.

le-probleme.js 
// Reponse d'API — user.address est parfois absent
const user = {
  nom:  "Alice",
  // address n'est pas la
};

// Sans protection — CRASH !
console.log(user.address.city);
// TypeError: Cannot read properties of undefined (reading 'city')

// L'ancienne facon de se proteger — verbeux et laid
const city = user && user.address && user.address.city;

// La nouvelle facon — propre et lisible
const cityPropre = user?.address?.city;
02

Les deux operateurs en un coup d'oeil

?. Optional Chaining

Acces securise a une propriete. Si la valeur a gauche est null ou undefined, retourne undefined au lieu de planter.

?? Nullish Coalescing

Valeur de secours. Retourne la valeur de droite uniquement si la valeur de gauche est null ou undefined. Pas si c'est 0 ou "".

01

Principe de base

Le ?. dit : "si la valeur a ma gauche est null ou undefined, arrete-toi et retourne undefined". Il court-circuite le reste de l'expression sans planter.

optional-base.js 
const user = {
  nom: "Bob",
  // address est absent
};

// Sans ?.  → TypeError et crash
user.address.city;

// Avec ?.  → retourne undefined, pas de crash
user?.address;             // undefined
user?.address?.city;       // undefined (s'arrete au premier undefined)
user?.address?.city?.toUpperCase(); // undefined (chaine complete securisee)

// Si la propriete EXISTE, on continue normalement
const user2 = { nom: "Alice", address: { city: "Lyon" } };
user2?.address?.city; // "Lyon" — fonctionne normalement
02

Appel de methode optionnel

On peut aussi utiliser ?. pour appeler une methode qui pourrait ne pas exister. Si la methode est undefined, l'appel est simplement ignore.

methode-optionnelle.js 
const player = {
  nom: "Alice",
  // la methode "saluer" n'existe pas toujours
};

const player2 = {
  nom:    "Bob",
  saluer: () => "Bonjour !"
};

// Sans ?.() → TypeError si la methode n'existe pas
player.saluer();  // TypeError: player.saluer is not a function

// Avec ?.() → retourne undefined si la methode est absente
player?.saluer();  // undefined — pas de crash
player2?.saluer(); // "Bonjour !" — fonctionne

// Exemple concret : callback optionnel
function traiter(data, onSuccess) {
  // onSuccess peut ne pas etre fourni
  onSuccess?.(data); // appelee seulement si elle existe
}
03

Acces optionnel a un index de tableau

tableau-optionnel.js 
const users = null;  // tableau absent (vient d'une API)

// Sans ?. → TypeError
users[0];         // TypeError: Cannot read properties of null

// Avec ?.[] → undefined si le tableau est null/undefined
users?.[0];       // undefined
users?.[0]?.nom; // undefined (chaine securisee)

// Cas reel : premier element d'une liste d'une API
const data = { posts: [{ title: "Hello" }] };
const premiertitle = data?.posts?.[0]?.title;
console.log(premiertitle); // "Hello"
Recap des 3 syntaxes
obj?.prop — acces a une propriete
obj?.method() — appel de methode
arr?.[index] — acces a un index de tableau
01

Principe de base

Le ?? retourne la valeur de droite uniquement si la valeur de gauche est null ou undefined. C'est tout. Pas si c'est 0, "", false — c'est son avantage cle sur le ||.

nullish-base.js 
// null et undefined → retourne la valeur de droite
null      ?? "defaut"   // "defaut"
undefined ?? "defaut"   // "defaut"

// 0, "", false → retourne la valeur de GAUCHE (elle existe !)
0         ?? "defaut"   // 0     ← 0 est une valeur valide
""        ?? "defaut"   // ""    ← chaine vide valide
false     ?? "defaut"   // false ← false est une valeur valide

// Concretement
const score = 0;
const affiche = score ?? "Pas de score";
console.log(affiche); // 0 — pas "Pas de score"
02

?? vs || — la difference fondamentale

C'est le piege le plus courant. Le || traite toutes les valeurs falsy comme absentes (0, "", false, NaN...). Le ?? ne traite comme absentes que null et undefined. En pratique, cela fait une enorme difference.

|| — se trompe sur 0 et ""

or-logique.js 
const config = {
  volume:   0,
  pseudo:   "",
  actif:    false
};

// || considere 0, "", false comme "absent"
const vol  = config.volume  || 50;   // 50  ← FAUX
const name = config.pseudo  || "Inconnu"; // "Inconnu" ← FAUX
const ok   = config.actif   || true;  // true ← FAUX

// || ecrase les vraies valeurs 0, "" et false !

?? — respecte 0, "" et false

nullish.js 
const config = {
  volume:   0,
  pseudo:   "",
  actif:    false
};

// ?? ne reagit qu'a null et undefined
const vol  = config.volume  ?? 50;        // 0  ← CORRECT
const name = config.pseudo  ?? "Inconnu";  // "" ← CORRECT
const ok   = config.actif   ?? true;       // false ← CORRECT

// ?? respecte toutes les valeurs intentionnelles

01

?. et ?? ensemble

Les deux operateurs sont faits pour etre combines. Le ?. securise l'acces, le ?? gere la valeur de remplacement quand le resultat est undefined. C'est le combo parfait pour travailler avec des APIs.

combo-parfait.js 
const user = {
  nom: "Alice",
  // address, bio, score sont absents
};

// ?.  → "ne plante pas si absent"
// ??  → "donne cette valeur si le resultat est null/undefined"

const ville  = user?.address?.city   ?? "Ville inconnue";
const bio    = user?.bio              ?? "Pas de bio";
const score  = user?.stats?.score   ?? 0;
const avatar = user?.photos?.[0]?.url ?? "/images/default.png";

console.log(ville);  // "Ville inconnue"
console.log(bio);    // "Pas de bio"
console.log(score);  // 0
console.log(avatar); // "/images/default.png"
02

Affectation avec ??= (bonus ES2021)

L'operateur ??= assigne une valeur a une variable seulement si elle est nulle ou indefinie. C'est un raccourci pour x = x ?? valeur.

affectation-nullish.js 
let pseudo = null;
let score  = 0;
let nom    = "Alice";

// ??= assigne uniquement si null ou undefined
pseudo ??= "Anonyme";  // pseudo = "Anonyme"  (etait null)
score  ??= 100;        // score  = 0          (0 n'est pas nullish)
nom    ??= "Inconnu";  // nom    = "Alice"     (deja defini)

console.log(pseudo); // "Anonyme"
console.log(score);  // 0
console.log(nom);    // "Alice"

// Equivalent long :
pseudo = pseudo ?? "Anonyme";
03

Avec la destructuration (etape 2)

On peut combiner ?., ?? et la destructuration. C'est exactement comme ca qu'on ecrit du code moderne en JS ou React.

triple-combo.js 
const apiData = {
  user: {
    nom:   "Alice",
    score: 0,
    // address absent
    // role absent
  }
};

// 1. Destructuration pour extraire user
const { user } = apiData;

// 2. ?. pour l'acces securise
// 3. ?? pour la valeur de secours
const ville  = user?.address?.city   ?? "NC";
const role   = user?.role             ?? "visiteur";
const score  = user?.score            ?? "aucun score";

console.log(ville);  // "NC"
console.log(role);   // "visiteur"
console.log(score);  // 0  ← ?? respecte 0, pas de valeur de remplacement
Pieges

Les erreurs classiques

Piege 1 — confondre ?? et ||

piege-1.js 
const produit = { nom: "Souris", stock: 0, actif: false };

//  MAUVAIS — || ecrase les valeurs 0 et false
const stock = produit.stock  || "Rupture"; // "Rupture" — FAUX, stock = 0
const actif = produit.actif  || true;      // true — FAUX, actif = false

//  BON — ?? respecte 0 et false
const stock2 = produit.stock ?? "Rupture"; // 0     — correct
const actif2 = produit.actif ?? true;      // false — correct

Piege 2 — ?. ne protege pas contre toutes les erreurs

piege-2.js 
const user = null;

//  ?. protege contre null et undefined
user?.nom;      // undefined — pas de crash

//  Si la valeur est un mauvais type, ?. ne peut rien
const n = 42;
n.toUpperCase(); // TypeError: n.toUpperCase is not a function
// ?. ne protege pas contre les types incompatibles

//  Pour ca, on utilise un check de type ou try/catch
typeof n === "string" ? n.toUpperCase() : "pas une chaine";

Piege 3 — Melanger ?? et && sans parentheses

piege-3.js 
// Syntaxe interdite — JS refuse ce melange sans parentheses
const x = null || "defaut" ?? "autre";
// SyntaxError: Unexpected token '??'

// Mettre des parentheses pour etre explicite
const y = (null || "defaut") ?? "autre";  // "defaut"
const z = null || ("defaut" ?? "autre"); // "defaut"

Piege 4 — Ne pas mettre ?. sur toute la chaine

piege-4.js 
const data = { user: null };

//  ?. sur le premier niveau mais pas le second → crash quand meme
data?.user.address.city;
// TypeError: Cannot read properties of null (reading 'address')
// data?.user retourne null, puis null.address plante

//  ?. sur chaque niveau potentiellement absent
data?.user?.address?.city; // undefined — securise a chaque etape
Regle a retenir
Le ?. court-circuite uniquement le niveau ou il est place. Chaque propriete potentiellement null ou undefined dans la chaine doit avoir son propre ?.
01

Traitement d'une reponse API complete

api-securisee.js 
// Reponse typique d'une API — certains champs peuvent manquer
async function afficherProfil(userId) {
  try {
    const res  = await fetch(`https://jsonplaceholder.typicode.com/users/${userId}`);
    const user = await res.json();

    // Destructuration + acces securise + valeurs de remplacement
    const {
      name:    nom,
      email,
      phone,
      address: adresseObj,
      company: companyObj
    } = user;

    // Optional chaining pour les sous-proprietes
    const ville   = adresseObj?.city        ?? "Ville non renseignee";
    const societe = companyObj?.name        ?? "Independant";
    const geo     = adresseObj?.geo         ?? null;
    const lat     = geo?.lat               ?? "N/A";

    console.log("Nom     :", nom    ?? "Inconnu");
    console.log("Email   :", email  ?? "Non fourni");
    console.log("Ville   :", ville);
    console.log("Societe :", societe);
    console.log("Lat     :", lat);

  } catch (err) {
    console.error(err.message);
  }
}

afficherProfil(1);
02

Fonction utilitaire de securisation

safe-get.js 
// Pattern courant : fonction qui securise l'acces a une propriete profonde
function safeGet(obj, chemin, defaut = null) {
  return chemin
    .split(".")
    .reduce((acc, key) => acc?.[key], obj)
    ?? defaut;
}

const data = {
  user: {
    profil: {
      nom: "Alice"
      // bio absent
    }
  }
};

safeGet(data, "user.profil.nom", "NC");      // "Alice"
safeGet(data, "user.profil.bio", "NC");      // "NC"
safeGet(data, "user.adresse.ville", "NC");   // "NC"

}

renderCard(null);         // affiche la card avec toutes les valeurs par defaut
renderCard({ nom: "Bob" }); // affiche Bob avec les defaults pour le reste

// BONUS : fonction de formatage reutilisable
function formatUser(user) {
  const { name, email, address, company } = user;

  return {
    nom:     name                      ?? "Inconnu",
    email:   email                     ?? "Non fourni",
    ville:   address?.city            ?? "NC",
    lat:     address?.geo?.lat        ?? "N/A",
    lng:     address?.geo?.lng        ?? "N/A",
    societe: company?.name            ?? "Independant",
    secteur: company?.bs              ?? "Non precise",
  };
}

async function getUser(id) {
  try {
    const res  = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);

    if (!res.ok) throw new Error(`HTTP ${res.status}`);

    const userData = await res.json();

    // On formate pour avoir un objet propre et securise
    const user = formatUser(userData);

    console.log("Nom     :", user.nom);
    console.log("Email   :", user.email);
    console.log("Ville   :", user.ville);
    console.log("GPS     :", user.lat, user.lng);
    console.log("Societe :", user.societe);

  } catch (err) {
    // ?.message car err lui-meme pourrait ne pas avoir .message
    console.error("Erreur :", err?.message ?? "Erreur inconnue");
  }
}
