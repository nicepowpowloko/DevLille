01

Async / Promises

CONCEPT Quelle est la difference entre une fonction async et une fonction normale ? Que retourne une fonction async qui fait return 42 ?
Reponse
Reponse attendue
Une fonction async retourne toujours une Promise, meme si tu retournes une valeur simple. return 42 dans une fonction async est equivalent a return Promise.resolve(42). Pour recuperer la valeur 42, tu dois utiliser await ou .then() sur l'appel de la fonction.

Une fonction normale retourne la valeur directement, sans enveloppe. C'est la difference fondamentale.
CODE Qu'affiche ce code dans la console ? Dans quel ordre ?
ordre-execution.js 
console.log("A");

async function maFonction() {
  console.log("B");
  await Promise.resolve();
  console.log("C");
}

maFonction();
console.log("D");
Reponse
Piege d'execution
L'ordre est : A → B → D → C

Pourquoi ? console.log("A") s'execute en premier, c'est du code synchrone. Ensuite maFonction() est appelee : elle execute console.log("B") de facon synchrone jusqu'au premier await. Le await suspend la fonction et rend le controle au code appelant. Donc console.log("D") s'execute. Une fois la microtache resolue, la fonction reprend et console.log("C") s'execute en dernier.
PIEGE Ce code a un bug. Lequel ? Que va-t-il se passer a l'execution ?
bug-fetch.js 
async function getData() {
  const response = await fetch("https://api.github.com/users/torvalds");
  const data = response.json();
  console.log(data.name);
}

getData();
Reponse
Bug : await manquant
Le await est absent devant response.json(). .json() retourne une Promise, pas directement l'objet. Sans await, data est un objet Promise {pending} et non les donnees JSON. Donc data.name retourne undefined.

Correction : const data = await response.json();
CONCEPT Quelle est la difference entre Promise.all() et plusieurs await sequentiels ? Quand utiliser l'un ou l'autre ?
Reponse
Reponse cle
Plusieurs await sequentiels executent les Promises l'une apres l'autre : si chacune prend 1 seconde, le total est 3 secondes. C'est necessaire quand la deuxieme depend du resultat de la premiere.

Promise.all() lance toutes les Promises en parallele et attend que toutes soient resolues. Meme exemple : 1 seconde au total. A utiliser quand les requetes sont independantes. Attention : si une seule echoue, tout le Promise.all() est rejete.
PIEGE fetch() rejette-t-il sa Promise quand le serveur repond avec un code 404 ?
Reponse
Non — piege classique
Non. C'est l'un des pieges les plus frequents avec fetch(). La Promise est rejetee uniquement en cas d'erreur reseau (pas de connexion, timeout, CORS). Pour un 404 ou un 500, la Promise est fulfilled — mais avec response.ok === false et response.status === 404.

C'est pourquoi il faut toujours faire if (!response.ok) throw new Error(...) apres le premier await fetch().
02

Destructuration

CODE Qu'affiche ce code ? Explique chaque ligne.
destr-quiz.js 
const [a, b, c = 99] = [1, 2];
console.log(a, b, c);

const { x, y = 10, z = 20 } = { x: 5, y: null };
console.log(x, y, z);
Reponse
Piege sur null
Ligne 1 affiche : 1 2 99 — c vaut 99 car l'index 2 est undefined dans le tableau source.

Ligne 2 affiche : 5 null 20 — et c'est le piege ! y vaut null et non 10. La valeur par defaut ne s'applique que si la valeur est undefined. null est une valeur explicite et ne declenche pas la valeur par defaut.
PIEGE Apres cette ligne, peut-on acceder a la variable adresse ?
destr-nested.js 
const { nom, adresse: { ville, pays } } = user;
Reponse
Non — variable inexistante
Non. Dans une destructuration imbriquee { adresse: { ville, pays } }, le mot adresse est un chemin d'acces, pas une variable declaree. Seules ville et pays existent comme variables apres cette ligne. Essayer d'acceder a adresse provoque une ReferenceError.

Pour garder aussi l'objet complet : const { nom, adresse, adresse: { ville, pays } } = user;
CODE Que valent a et b apres cette ligne ?
swap.js 
let a = 10, b = 20;
[a, b] = [b, a];
console.log(a, b);
Reponse
20 10
C'est le pattern classique pour echanger deux variables sans variable temporaire. Le tableau [b, a] est cree d'abord avec les valeurs actuelles ([20, 10]), puis destructure dans [a, b]. Resultat : a = 20 et b = 10.
CONCEPT Quelle est la syntaxe pour renommer user_name en username tout en lui donnant une valeur par defaut de "anonyme" si absent ?
Reponse
Syntaxe combinee
const { user_name: username = "anonyme" } = obj;

La syntaxe est : propriete : nouveauNom = valeurParDefaut. Les deux-points permettent le renommage, le signe egal donne la valeur par defaut. L'ordre est important : d'abord le renommage, ensuite la valeur par defaut.
03

Optional Chaining et Nullish

CODE Qu'affichent ces quatre lignes ?
nullish-quiz.js 
console.log(0         ?? "defaut");
console.log(""        ?? "defaut");
console.log(null      ?? "defaut");
console.log(undefined ?? "defaut");
console.log(false     || "defaut");
console.log(false     ?? "defaut");
Reponse
Piege ?? vs ||
0 — ?? ne reagit pas a 0
"" — ?? ne reagit pas a la chaine vide
"defaut" — null est nullish
"defaut" — undefined est nullish
"defaut" — || reagit a false (valeur falsy)
false — ?? ne reagit pas a false
PIEGE Ce code va-t-il planter ? Si oui, pourquoi ? Comment le corriger ?
chain-piege.js 
const data = { user: null };
const ville = data?.user.address.city;
Reponse
Oui ca plante
data?.user retourne null. Mais il n'y a plus de ?. apres — donc null.address provoque une TypeError. Le ?. court-circuite uniquement le niveau ou il est place.

Correction : data?.user?.address?.city — chaque niveau potentiellement absent doit avoir son propre ?.
CONCEPT Explique en une phrase quand utiliser ?? plutot que ||.
Reponse
Regle d'or
Utilise ?? quand tu veux une valeur de secours uniquement si la valeur est absente (null/undefined), pas quand elle est simplement "falsy" — car 0, "" et false sont des valeurs intentionnelles valides que || ecraserait a tort.
PIEGE Ce code provoque une SyntaxError. Pourquoi et comment le corriger ?
syntax-error.js 
const val = null || "fallback" ?? "autre";
Reponse
SyntaxError intentionnelle
JS interdit de melanger || ou && avec ?? sans parentheses explicites. C'est une protection pour eviter les ambiguites de priorite d'operateurs. La correction est d'ajouter des parentheses :

const val = (null || "fallback") ?? "autre";
ou : const val = null || ("fallback" ?? "autre");
04

Set et Map

CODE Qu'affiche ce code ? Explique.
set-quiz.js 
const s = new Set([1, 2, 2, 3, 3, 3]);
s.add(2);
console.log(s.size);
console.log(s.length);
Reponse
Deux pieges en un
s.size affiche 3 — le Set contient seulement {1, 2, 3}, les doublons sont ignores a la creation, et .add(2) est aussi ignore puisque 2 existe deja.

s.length affiche undefined — Set n'a pas de propriete .length, seulement .size. C'est un piege classique, ne pas confondre avec les tableaux.
PIEGE Ce Set contient-il deux elements ou un seul ? Pourquoi ?
set-reference.js 
const s = new Set();
s.add({ nom: "Alice" });
s.add({ nom: "Alice" });
console.log(s.size);
Reponse
2 — pas de deduplication
2 elements. Set utilise l'egalite de reference (===) pour comparer les valeurs. Les deux objets { nom: "Alice" } sont syntaxiquement identiques mais ce sont deux objets differents en memoire — deux references distinctes. Set les considere donc comme deux valeurs differentes.

La deduplication ne fonctionne nativement qu'avec les primitives (numbers, strings, booleans).
CODE Qu'affiche ce code ? Attention au parametre du forEach.
map-foreach.js 
const map = new Map([["a", 1], ["b", 2]]);

map.forEach((cle, valeur) => {
  console.log(cle, valeur);
});
Reponse
Ordre inverse des parametres
Affiche : 1 "a" puis 2 "b" — alors qu'on s'attendrait au contraire.

Dans le .forEach() d'une Map, le premier parametre est la valeur et le deuxieme est la cle. C'est l'inverse de l'intuition. Dans l'exemple, les variables sont nommees cle et valeur mais dans les faits cle recoit la valeur et valeur recoit la cle.

Pour eviter la confusion, prefere for (const [cle, valeur] of map) ou nomme correctement : .forEach((value, key) => ...)
CONCEPT Quand choisirais-tu un Map plutot qu'un objet pour stocker des donnees cle/valeur ?
Reponse
3 criteres a citer
1. Les cles ne sont pas des strings — un objet ne peut avoir que des strings ou Symbols comme cles. Map accepte n'importe quel type, y compris des objets ou des fonctions.

2. L'ordre d'insertion est important — Map garantit l'ordre d'insertion, les objets ont un ordre partiel et impredictible pour les cles non-numeriques.

3. Beaucoup d'ajouts/suppressions frequents — Map est optimise pour ca, et .size est direct contrairement a Object.keys(obj).length.
05

Questions transversales

CONCEPT En trois phrases maximum, explique ce qu'est le modele asynchrone de JavaScript et pourquoi il est necessaire.
Reponse
Reponse de reference
JavaScript est mono-thread : il ne peut executer qu'une instruction a la fois. Sans asynchrone, toute operation longue (appel reseau, acces disque) bloquerait le thread principal et figerait l'interface. L'asynchrone permet de lancer ces operations et d'etre notifie quand elles se terminent, sans bloquer l'execution du reste du code.
PIEGE Quelle est la difference entre == et === ? Pourquoi faut-il toujours utiliser === ?
Reponse
Egalite stricte vs laxiste
== fait une coercition de type avant la comparaison : il convertit les valeurs pour les rendre comparables. Cela cree des surprises : 0 == false est true, "" == false est true, null == undefined est true.

=== compare le type ET la valeur sans aucune conversion. C'est predictible et explicite. En JS moderne, on utilise toujours === sauf cas tres specifique.
CONCEPT Quelle est la difference entre let, const et var ? Lequel utiliser et pourquoi ?
Reponse
Reponse attendue en entretien
var a une portee de fonction (ou globale) et est hissee (hoisting) en haut de la fonction. Ca cree des comportements surprenants dans les boucles et les blocs. A eviter.

let a une portee de bloc ({ }), n'est pas hissee de la meme facon. A utiliser pour les variables qui peuvent changer.

const a une portee de bloc et ne peut pas etre reassignee. Attention : pour les objets et tableaux, le contenu peut changer, seule la reference est constante. A utiliser par defaut — ca documente l'intention.
PIEGE const arr = [1, 2, 3]. Peut-on faire arr.push(4) ? Et arr = [1, 2, 3, 4] ?
Reponse
const ne protege pas le contenu
arr.push(4) : oui, ca fonctionne. const empeche la reassignation de la variable elle-meme, pas la modification du contenu de l'objet ou tableau pointe. La reference reste la meme.

arr = [1, 2, 3, 4] : non, TypeError. Ici on essaie de reassigner la variable arr vers un nouveau tableau — c'est interdit avec const.
CONCEPT C'est quoi le principe du try/catch et pourquoi est-il important dans le contexte des appels API ?
Reponse
Gestion d'erreur
try/catch permet d'intercepter les erreurs qui se produisent dans le bloc try pour les gerer dans le bloc catch sans que l'application plante. Sans lui, une erreur non geree stoppe l'execution et peut casser toute l'interface.

Pour les appels API c'est critique : le reseau peut etre coupe, le serveur peut etre en erreur, les donnees peuvent etre malformees. Tout appel await fetch() doit etre dans un try/catch.

Analyse de code complete

Pour chacun des blocs suivants, lis le code attentivement et dis ce qu'il fait, identifie les bugs eventuels, et propose une version corrigee si necessaire. Prends le temps d'analyser avant de cliquer.

ANALYSE Identifie le ou les problemes dans ce code. Qu'est-ce qui ne va pas ?
analyse-1.js 
async function chargerUsers() {
  const users = [];

  const ids = [1, 2, 3];
  ids.forEach(async (id) => {
    const res  = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);
    const user = await res.json();
    users.push(user);
  });

  console.log(users.length); // Attendu : 3
  return users;
}

chargerUsers();
Reponse
Bug : await dans forEach ne fonctionne pas comme attendu
forEach n'attend pas les callbacks async. Chaque iteration lance les fetches mais forEach ne retourne pas de Promise et ne peut pas etre awaited. Le console.log s'execute avant que les fetches soient termines. users.length affichera probablement 0.

Correction — deux options :
1. for...of sequentiel :
for (const id of ids) { const res = await fetch(...); ... }

2. Promise.all en parallele (meilleur) :
const users = await Promise.all(ids.map(async (id) => { ... }));
ANALYSE Ce code fonctionne-t-il ? Si non, trouve les deux problemes.
analyse-2.js 
const config = {
  host:   "localhost",
  port:   3000,
  debug:  false,
  retries: 0
};

const {
  host,
  port    = 8080,
  debug   = true,
  retries = 3,
  timeout = 5000
} = config;

console.log(port, debug, retries, timeout);
Reponse
Piege sur valeurs par defaut
Le code ne plante pas mais les valeurs ne sont pas celles attendues :

port = 3000 (pas 8080 — la valeur existe dans config)
debug = false (pas true — false est une valeur valide, pas undefined)
retries = 0 (pas 3 — 0 est une valeur valide, pas undefined)
timeout = 5000 (correct — absent dans config, defaut utilise)

La valeur par defaut ne s'applique que si la propriete est undefined. false et 0 ne declenchent pas le defaut.
ANALYSE Lis ce code et dis ce qu'il affiche. Est-ce correct ? Que pourrait-on ameliorer ?
analyse-3.js 
const utilisateurs = [
  { id: 1, nom: "Alice", score: 0  },
  { id: 2, nom: "Bob",   score: null },
  { id: 3, nom: "Clara"              },
];

const resultats = utilisateurs.map((u) => ({
  nom:    u.nom   || "Inconnu",
  score:  u.score || 0,
  statut: u.score > 50 ? "OK" : "KO"
}));

console.log(resultats);
Reponse
Plusieurs problemes subtils
Alice : score = 0, mais 0 || 0 donne 0 — par chance ca semble correct. Mais 0 > 50 est false donc statut = "KO". Correct.

Bob : score = null, null || 0 donne 0. Mais c'est grace au || pas au ??. Et null > 50 est false, statut = "KO".

Clara : score absent → undefined || 0 donne 0. Statut = "KO".

Amelioration : remplacer || par ?? pour score afin de respecter explicitement les valeurs 0 intentionnelles. Et utiliser u?.score pour securiser l'acces.
