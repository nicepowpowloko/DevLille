Introduction aux Sauvegardes Docker

La sauvegarde dans Docker est un aspect crucial pour assurer la pérennité et la sécurité de vos applications conteneurisées. Contrairement aux serveurs traditionnels, Docker fonctionne avec des couches éphémères qui peuvent être supprimées à tout moment.

Objectifs d'apprentissage

  • Comprendre l'importance des sauvegardes Docker
  • Maîtriser les différentes techniques de backup
  • Savoir restaurer des données en cas de problème
  • Mettre en place une stratégie de sauvegarde efficace

Qu'est-ce qu'une sauvegarde Docker ?

Une sauvegarde Docker consiste à préserver l'état de vos conteneurs, volumes et images pour pouvoir les restaurer en cas de :

  • Panne matérielle : disque dur défaillant, serveur en panne
  • Erreur humaine : suppression accidentelle de données
  • Corruption de données : fichiers endommagés
  • Migration : déplacement vers un nouveau serveur
  • Mise à jour ratée : problème lors d'un update

Pourquoi Sauvegarder Docker ?

Particularités de Docker

Docker a des caractéristiques spécifiques qui rendent les sauvegardes essentielles :

Nature Éphémère des Conteneurs

Les conteneurs Docker sont conçus pour être immutables et remplaçables. Toute donnée stockée dans un conteneur (hors volumes) est perdue lorsque le conteneur est supprimé.

# Créer un conteneur avec des données
docker run -d --name temp_container nginx
docker exec temp_container bash -c "echo 'Données importantes' > /tmp/data.txt"

# Les données sont dans le conteneur
docker exec temp_container cat /tmp/data.txt
# Affiche: Données importantes

# Supprimer le conteneur
docker rm -f temp_container

# Les données sont perdues définitivement !
Explication : Les données stockées directement dans le conteneur (sans volume) sont perdues lors de sa suppression. C'est pourquoi on utilise des volumes pour la persistance.

Les Trois Piliers à Sauvegarder

Élément Description Priorité Fréquence recommandée
Volumes Données persistantes des applications (BDD, fichiers utilisateurs) Critique Quotidienne ou continue
Images Applications et environnements configurés Importante À chaque version
Configurations docker-compose.yml, variables d'environnement Importante À chaque modification

Attention aux Conteneurs

On ne sauvegarde généralement pas les conteneurs eux-mêmes, mais plutôt :

  • Les volumes qui contiennent leurs données
  • Les images qui permettent de les recréer
  • Les configurations (docker-compose.yml)

Types de Sauvegarde Docker

Sauvegarde Complète (Full Backup)

Sauvegarde totale de tous les éléments Docker à un instant T.

Avantages :
  • Restauration complète possible
  • Simple à gérer
  • Idéal pour migration
Inconvénients :
  • Très volumineuse
  • Temps de backup long
  • Consomme beaucoup d'espace

Sauvegarde Incrémentale

Sauvegarde uniquement les modifications depuis la dernière sauvegarde.

Avantages :
  • Rapide à exécuter
  • Économe en espace
  • Idéal pour sauvegardes fréquentes
Inconvénients :
  • Restauration plus complexe
  • Dépendance entre sauvegardes

Sauvegarde Différentielle

Sauvegarde les modifications depuis la dernière sauvegarde complète.

Exemple de Stratégie Hybride

# Dimanche : Sauvegarde COMPLÈTE
docker-backup-full.sh

# Lundi à Samedi : Sauvegardes INCRÉMENTIELLES
docker-backup-incremental.sh

# Résultat :
# - 1 sauvegarde complète par semaine
# - 6 sauvegardes incrémentielles
# - Optimisation espace/sécurité

Sauvegarder les Volumes Docker

Les volumes sont l'élément le plus critique à sauvegarder car ils contiennent vos données persistantes (bases de données, fichiers utilisateurs, configurations).

Lister les Volumes Existants

# Lister tous les volumes
docker volume ls

# Inspecter un volume spécifique
docker volume inspect mon_volume

# Afficher l'emplacement physique du volume
docker volume inspect mon_volume --format '{{ .Mountpoint }}'
Résultat typique : /var/lib/docker/volumes/mon_volume/_data
C'est ici que Docker stocke physiquement les données du volume sur votre système.

Méthode 1 : Sauvegarde avec tar (Recommandée)

Principe

On utilise un conteneur temporaire pour créer une archive tar du volume.

# Sauvegarder un volume dans un fichier tar.gz
docker run --rm \
  -v mon_volume:/data \
  -v $(pwd):/backup \
  ubuntu tar czf /backup/mon_volume_backup.tar.gz -C /data .

Décortiquons cette commande :

  • docker run --rm : Créer un conteneur temporaire qui s'auto-détruira
  • -v mon_volume:/data : Monter le volume à sauvegarder dans /data
  • -v $(pwd):/backup : Monter le répertoire actuel dans /backup
  • ubuntu : Utiliser l'image Ubuntu comme base
  • tar czf : Créer une archive compressée (c=create, z=gzip, f=file)
  • /backup/mon_volume_backup.tar.gz : Destination de l'archive
  • -C /data . : Compresser tout le contenu de /data

Restaurer un Volume

# 1. Créer un nouveau volume (si nécessaire)
docker volume create mon_volume_restaure

# 2. Restaurer les données depuis l'archive
docker run --rm \
  -v mon_volume_restaure:/data \
  -v $(pwd):/backup \
  ubuntu tar xzf /backup/mon_volume_backup.tar.gz -C /data

Explication de la restauration :

  • tar xzf : Extraire une archive (x=extract, z=gzip, f=file)
  • Les données sont extraites dans le nouveau volume
  • Le conteneur temporaire est supprimé automatiquement (--rm)

Méthode 2 : Copie Directe (Pour Tests)

Utilisation Limitée

Cette méthode copie directement les fichiers du volume. Attention : cela peut causer des problèmes de permissions et n'est pas recommandé en production.

# Trouver l'emplacement du volume
VOLUME_PATH=$(docker volume inspect mon_volume --format '{{ .Mountpoint }}')

# Copier les données (nécessite sudo)
sudo cp -r $VOLUME_PATH /chemin/vers/backup/

# Problèmes potentiels :
# - Nécessite les droits root
# - Problèmes de permissions possibles
# - Pas de compression automatique

Méthode 3 : Backup MySQL/PostgreSQL Spécifique

Sauvegarde de Base de Données MySQL

# Sauvegarder une base MySQL
docker exec mon_container_mysql \
  mysqldump -u root -pMotDePasse ma_base \
  > backup_mysql_$(date +%Y%m%d).sql
Explication :
  • docker exec : Exécuter une commande dans un conteneur en cours
  • mysqldump : Outil de sauvegarde MySQL
  • $(date +%Y%m%d) : Ajouter la date au nom (ex: 20250209)
  • Résultat : fichier SQL réimportable facilement

Restaurer MySQL

# Restaurer la base de données
docker exec -i mon_container_mysql \
  mysql -u root -pMotDePasse ma_base \
  < backup_mysql_20250209.sql

Sauvegarde PostgreSQL

# Sauvegarder PostgreSQL
docker exec mon_container_postgres \
  pg_dump -U postgres ma_base \
  > backup_postgres_$(date +%Y%m%d).sql

# Restaurer PostgreSQL
docker exec -i mon_container_postgres \
  psql -U postgres ma_base \
  < backup_postgres_20250209.sql

Automatiser les Sauvegardes avec Cron

#!/bin/bash
# Script: docker-volume-backup.sh
# Description: Sauvegarde automatique des volumes Docker

# Variables
BACKUP_DIR="/backups/docker"
DATE=$(date +%Y%m%d_%H%M%S)
VOLUME_NAME="mon_volume_important"

# Créer le dossier de backup
mkdir -p $BACKUP_DIR

# Sauvegarder le volume
docker run --rm \
  -v $VOLUME_NAME:/data \
  -v $BACKUP_DIR:/backup \
  ubuntu tar czf /backup/${VOLUME_NAME}_${DATE}.tar.gz -C /data .

# Nettoyer les anciennes sauvegardes (garder 7 jours)
find $BACKUP_DIR -name "${VOLUME_NAME}_*.tar.gz" -mtime +7 -delete

echo "Sauvegarde terminée: ${VOLUME_NAME}_${DATE}.tar.gz"

Configuration Cron

# Éditer le crontab
crontab -e

# Ajouter cette ligne pour backup quotidien à 2h du matin
0 2 * * * /scripts/docker-volume-backup.sh >> /var/log/docker-backup.log 2>&1

Sauvegarder les Conteneurs

Note Importante

On ne sauvegarde généralement pas les conteneurs directement, mais on peut créer une image depuis un conteneur pour capturer son état actuel. Cependant, il est préférable de sauvegarder les volumes et de recréer les conteneurs depuis leurs images officielles.

Créer une Image depuis un Conteneur

# Créer une image depuis un conteneur en cours d'exécution
docker commit mon_conteneur mon_image_backup:v1

# Avec un message de commit
docker commit -m "Backup avant mise à jour" \
  -a "Votre Nom" \
  mon_conteneur \
  mon_image_backup:v1
Paramètres :
  • -m : Message décrivant le commit
  • -a : Auteur du commit
  • mon_conteneur : Conteneur source
  • mon_image_backup:v1 : Nom et tag de la nouvelle image

Exporter un Conteneur

# Exporter le système de fichiers d'un conteneur
docker export mon_conteneur > conteneur_backup.tar

# Ou avec compression
docker export mon_conteneur | gzip > conteneur_backup.tar.gz

Différence Export vs Commit

  • docker export : Exporte uniquement le système de fichiers (pas d'historique, pas de métadonnées)
  • docker commit : Crée une image complète avec historique et métadonnées
  • Recommandation : Utilisez commit pour préserver l'historique

Restaurer depuis un Export

# Importer depuis un tar (crée une image)
docker import conteneur_backup.tar mon_image_restauree:v1

# Créer un conteneur depuis l'image restaurée
docker run -d --name conteneur_restaure mon_image_restauree:v1

Sauvegarder les Images Docker

Les images sont vos applications conteneurisées. Les sauvegarder permet de :

  • Migrer vers un autre serveur sans connexion internet
  • Conserver une version spécifique d'une application
  • Distribuer votre application sans registre Docker

Sauvegarder une Image

# Sauvegarder une seule image
docker save nginx:latest > nginx_backup.tar

# Avec compression (recommandé)
docker save nginx:latest | gzip > nginx_backup.tar.gz

# Sauvegarder plusieurs images en une fois
docker save nginx:latest mysql:8.0 redis:alpine > multi_images_backup.tar

Comparaison de Taille

Format Taille Temps
Sans compression (.tar) ~150 MB Rapide
Avec gzip (.tar.gz) ~50 MB Moyen
Économie ~66% +30% temps

Restaurer une Image

# Charger une image depuis un fichier tar
docker load < nginx_backup.tar

# Ou depuis un fichier compressé
docker load < nginx_backup.tar.gz

# Vérifier que l'image est bien chargée
docker images | grep nginx

Sauvegarder Toutes les Images

Script Complet de Sauvegarde d'Images

#!/bin/bash
# Script: backup-all-images.sh
# Sauvegarde toutes les images Docker locales

BACKUP_DIR="/backups/docker-images"
DATE=$(date +%Y%m%d)

# Créer le dossier
mkdir -p $BACKUP_DIR

# Lister toutes les images
echo "Recherche des images Docker..."
docker images --format "{{.Repository}}:{{.Tag}}" | grep -v "" > /tmp/images_list.txt

# Compter les images
IMAGE_COUNT=$(wc -l < /tmp/images_list.txt)
echo "$IMAGE_COUNT images trouvées"

# Sauvegarder chaque image
COUNTER=1
while IFS= read -r image; do
    # Remplacer les / par _ dans le nom du fichier
    filename=$(echo "$image" | tr '/:' '__')
    
    echo "[$COUNTER/$IMAGE_COUNT] Sauvegarde de $image..."
    
    docker save "$image" | gzip > "$BACKUP_DIR/${filename}_${DATE}.tar.gz"
    
    if [ $? -eq 0 ]; then
        echo "  Succès"
    else
        echo "   Erreur"
    fi
    
    ((COUNTER++))
done < /tmp/images_list.txt

echo "Sauvegarde terminée dans $BACKUP_DIR"

# Nettoyer le fichier temporaire
rm /tmp/images_list.txt

Utilisation du Script

# Rendre le script exécutable
chmod +x backup-all-images.sh

# Exécuter
./backup-all-images.sh

# Résultat : toutes vos images sauvegardées dans /backups/docker-images/

Script de Restauration

#!/bin/bash
# Script: restore-all-images.sh
# Restaure toutes les images Docker depuis un dossier

BACKUP_DIR="/backups/docker-images"

echo "Restauration des images depuis $BACKUP_DIR"

# Trouver tous les fichiers .tar.gz
find $BACKUP_DIR -name "*.tar.gz" | while read -r file; do
    echo "Chargement de $(basename $file)..."
    docker load < "$file"
    
    if [ $? -eq 0 ]; then
        echo "   Image chargée avec succès"
    else
        echo "   Erreur lors du chargement"
    fi
done

echo "Restauration terminée"
docker images

Stratégies de Sauvegarde Docker

Règle 3-2-1

La Règle d'Or des Backups

  • 3 copies de vos données (1 originale + 2 backups)
  • 2 supports différents (disque dur + cloud par exemple)
  • 1 copie hors site (protection contre incendie, vol, etc.)

Fréquences Recommandées

Type de Donnée Fréquence Rétention Méthode
Base de données critique Toutes les 4h ou continue 30 jours mysqldump + stockage cloud
Volumes applicatifs Quotidienne (nuit) 14 jours tar + compression
Images Docker À chaque version 3 dernières versions docker save
Configurations À chaque modification Illimité Git

Architecture de Sauvegarde Complète

Structure Organisée

/backups/
├── daily/              # Sauvegardes quotidiennes (7 jours)
│   ├── volumes/
│   ├── databases/
│   └── configs/
├── weekly/             # Sauvegardes hebdomadaires (4 semaines)
│   └── full/
├── monthly/            # Sauvegardes mensuelles (12 mois)
│   └── archives/
└── scripts/            # Scripts d'automatisation
    ├── backup-daily.sh
    ├── backup-weekly.sh
    └── restore.sh

Script de Sauvegarde Complète Automatisée

#!/bin/bash
# Script: docker-backup-complete.sh
# Sauvegarde complète automatisée de l'environnement Docker

# Configuration
BACKUP_ROOT="/backups/docker"
DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_DIR="$BACKUP_ROOT/backup_$DATE"
LOG_FILE="$BACKUP_ROOT/backup.log"

# Fonction de log
log() {
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] $1" | tee -a $LOG_FILE
}

# Créer le dossier de backup
mkdir -p $BACKUP_DIR/{volumes,images,configs}

log "Démarrage de la sauvegarde complète"

# 1. SAUVEGARDER LES VOLUMES
log "Sauvegarde des volumes..."
docker volume ls -q | while read volume; do
    log "  - Volume: $volume"
    docker run --rm \
        -v $volume:/data \
        -v $BACKUP_DIR/volumes:/backup \
        ubuntu tar czf /backup/${volume}.tar.gz -C /data .
done

# 2. SAUVEGARDER LES BASES DE DONNÉES
log "Sauvegarde des bases de données..."

# MySQL
if docker ps --format '{{.Names}}' | grep -q mysql; then
    MYSQL_CONTAINER=$(docker ps --format '{{.Names}}' | grep mysql | head -1)
    log "  - MySQL: $MYSQL_CONTAINER"
    docker exec $MYSQL_CONTAINER sh -c \
        'mysqldump -u root -p$MYSQL_ROOT_PASSWORD --all-databases' \
        > $BACKUP_DIR/configs/mysql_dump_$DATE.sql
fi

# PostgreSQL
if docker ps --format '{{.Names}}' | grep -q postgres; then
    POSTGRES_CONTAINER=$(docker ps --format '{{.Names}}' | grep postgres | head -1)
    log "  - PostgreSQL: $POSTGRES_CONTAINER"
    docker exec $POSTGRES_CONTAINER sh -c \
        'pg_dumpall -U postgres' \
        > $BACKUP_DIR/configs/postgres_dump_$DATE.sql
fi

# 3. SAUVEGARDER LES IMAGES PERSONNALISÉES
log "Sauvegarde des images personnalisées..."
docker images --filter "dangling=false" --format "{{.Repository}}:{{.Tag}}" | \
grep -v "^" | \
while read image; do
    # Sauvegarder uniquement vos images (pas les officielles)
    if [[ $image != *"/"* ]] || [[ $image == "localhost/"* ]]; then
        filename=$(echo $image | tr '/:' '__')
        log "  - Image: $image"
        docker save $image | gzip > $BACKUP_DIR/images/${filename}.tar.gz
    fi
done

# 4. SAUVEGARDER LES CONFIGURATIONS
log "Sauvegarde des configurations..."

# Docker Compose files
find /opt/docker -name "docker-compose.yml" -o -name "docker-compose.yaml" | \
while read compose_file; do
    cp $compose_file $BACKUP_DIR/configs/
    log "  - Copie: $compose_file"
done

# Variables d'environnement
find /opt/docker -name ".env" | while read env_file; do
    cp $env_file $BACKUP_DIR/configs/
    log "  - Copie: $env_file"
done

# 5. CRÉER UN MANIFESTE
log "Création du manifeste..."
cat > $BACKUP_DIR/MANIFEST.txt << EOF

SAUVEGARDE DOCKER - $(date)


DATE: $DATE
SERVEUR: $(hostname)

VOLUMES SAUVEGARDÉS:
$(docker volume ls --format "- {{.Name}}")

CONTENEURS ACTIFS:
$(docker ps --format "- {{.Names}} ({{.Image}})")

IMAGES SAUVEGARDÉES:
$(ls -lh $BACKUP_DIR/images/ 2>/dev/null || echo "Aucune")

TAILLE TOTALE: $(du -sh $BACKUP_DIR | cut -f1)
EOF

# 6. COMPRESSION FINALE (optionnel)
log "Compression de la sauvegarde..."
tar czf "$BACKUP_ROOT/backup_$DATE.tar.gz" -C $BACKUP_ROOT backup_$DATE
rm -rf $BACKUP_DIR

# 7. NETTOYAGE DES ANCIENNES SAUVEGARDES
log "Nettoyage des sauvegardes de plus de 7 jours..."
find $BACKUP_ROOT -name "backup_*.tar.gz" -mtime +7 -delete

# 8. UPLOAD VERS CLOUD (optionnel)
# Décommentez si vous utilisez AWS S3, Google Cloud Storage, etc.
# log " Upload vers le cloud..."
# aws s3 cp "$BACKUP_ROOT/backup_$DATE.tar.gz" s3://mon-bucket/backups/

log " Sauvegarde terminée avec succès!"
log " Fichier: backup_$DATE.tar.gz"
log " Taille: $(du -sh "$BACKUP_ROOT/backup_$DATE.tar.gz" | cut -f1)"

Configuration Cron pour Automatisation

# Éditer le crontab
sudo crontab -e

Script de Vérification de Sauvegarde

#!/bin/bash
# Script: check-backup-health.sh
# Vérifie l'intégrité des sauvegardes

BACKUP_ROOT="/backups/docker"

echo "Vérification des sauvegardes Docker"
echo ""

# Vérifier la présence de sauvegardes récentes
LATEST_BACKUP=$(find $BACKUP_ROOT -name "backup_*.tar.gz" -mtime -1 | head -1)

if [ -z "$LATEST_BACKUP" ]; then
    echo " ALERTE: Aucune sauvegarde récente trouvée !"
    exit 1
else
    echo " Dernière sauvegarde: $(basename $LATEST_BACKUP)"
    echo " Date: $(stat -c %y "$LATEST_BACKUP" | cut -d' ' -f1)"
    echo "Taille: $(du -sh "$LATEST_BACKUP" | cut -f1)"
fi

# Vérifier l'intégrité de l'archive
echo ""
echo " Test d'intégrité..."
if tar tzf "$LATEST_BACKUP" > /dev/null 2>&1; then
    echo " Archive valide"
else
    echo " ALERTE: Archive corrompue !"
    exit 1
fi

# Compter les sauvegardes disponibles
BACKUP_COUNT=$(find $BACKUP_ROOT -name "backup_*.tar.gz" | wc -l)
echo ""
echo " Statistiques:"
echo "   - Nombre de sauvegardes: $BACKUP_COUNT"
echo "   - Espace utilisé: $(du -sh $BACKUP_ROOT | cut -f1)"

echo ""
echo " Vérification terminée avec succès"

Exercices Pratiques

Exercice 1 : Sauvegarde Basique d'un Volume

Objectif

Créer un volume avec des données, le sauvegarder, supprimer le volume, puis le restaurer.

Étapes

# 1. Créer un volume
docker volume create mon_volume_test

# 2. Ajouter des données dans le volume
docker run --rm -v mon_volume_test:/data ubuntu bash -c \
  "echo 'Données importantes' > /data/fichier.txt && \
   echo 'Autre fichier' > /data/fichier2.txt && \
   mkdir -p /data/dossier && \
   echo 'Contenu dossier' > /data/dossier/info.txt"

# 3. Vérifier le contenu
docker run --rm -v mon_volume_test:/data ubuntu ls -laR /data

# 4. Sauvegarder le volume
docker run --rm \
  -v mon_volume_test:/data \
  -v $(pwd):/backup \
  ubuntu tar czf /backup/test_backup.tar.gz -C /data .

# 5. Supprimer le volume
docker volume rm mon_volume_test

# 6. Créer un nouveau volume et restaurer
docker volume create mon_volume_restaure
docker run --rm \
  -v mon_volume_restaure:/data \
  -v $(pwd):/backup \
  ubuntu tar xzf /backup/test_backup.tar.gz -C /data

# 7. Vérifier que tout est restauré
docker run --rm -v mon_volume_restaure:/data ubuntu ls -laR /data

Exercice 2 : Sauvegarde d'une Application WordPress

Objectif

Déployer WordPress avec Docker, sauvegarder les données et la base MySQL, puis restaurer le tout.

Étape 1 : Déployer WordPress

# Créer un docker-compose.yml
cat > docker-compose.yml << 'EOF'
version: '3'

services:
  db:
    image: mysql:8.0
    volumes:
      - db_data:/var/lib/mysql
    environment:
      MYSQL_ROOT_PASSWORD: root_password
      MYSQL_DATABASE: wordpress
      MYSQL_USER: wp_user
      MYSQL_PASSWORD: wp_password

  wordpress:
    image: wordpress:latest
    ports:
      - "8080:80"
    volumes:
      - wp_content:/var/www/html/wp-content
    environment:
      WORDPRESS_DB_HOST: db
      WORDPRESS_DB_USER: wp_user
      WORDPRESS_DB_PASSWORD: wp_password
      WORDPRESS_DB_NAME: wordpress

volumes:
  db_data:
  wp_content:
EOF

# Démarrer WordPress
docker-compose up -d

# Attendre le démarrage
sleep 30

# Vérifier que ça fonctionne
curl -I http://localhost:8080

Étape 2 : Sauvegarder

#!/bin/bash
# Créer un dossier de backup
mkdir -p wordpress_backup

# 1. Sauvegarder la base de données MySQL
docker-compose exec -T db mysqldump \
  -u wp_user -pwp_password wordpress \
  > wordpress_backup/database.sql

# 2. Sauvegarder les fichiers WordPress
docker run --rm \
  -v $(docker volume ls -q | grep wp_content):/data \
  -v $(pwd)/wordpress_backup:/backup \
  ubuntu tar czf /backup/wp_content.tar.gz -C /data .

echo " Sauvegarde WordPress terminée"
ls -lh wordpress_backup/

Étape 3 : Restaurer

#!/bin/bash
# Arrêter et nettoyer
docker-compose down -v

# Redémarrer avec de nouveaux volumes
docker-compose up -d
sleep 30

# Restaurer la base de données
docker-compose exec -T db mysql \
  -u wp_user -pwp_password wordpress \
  < wordpress_backup/database.sql

# Restaurer les fichiers
docker run --rm \
  -v $(docker volume ls -q | grep wp_content):/data \
  -v $(pwd)/wordpress_backup:/backup \
  ubuntu tar xzf /backup/wp_content.tar.gz -C /data

# Redémarrer pour prendre en compte les changements
docker-compose restart

echo " Restauration terminée"
echo " Accédez à http://localhost:8080"

Exercice 3 : Automatisation Complète

Objectif

Créer un système de sauvegarde automatisé avec rotation des backups.

#!/bin/bash
# Script: auto-backup-wordpress.sh

BACKUP_ROOT="/backups/wordpress"
DATE=$(date +%Y%m%d_%H%M%S)
RETENTION_DAYS=7

# Créer la structure
mkdir -p $BACKUP_ROOT/{daily,weekly,monthly}

# Déterminer le type de backup
DAY_OF_WEEK=$(date +%u)  # 1-7 (1=lundi)
DAY_OF_MONTH=$(date +%d) # 01-31

if [ "$DAY_OF_MONTH" == "01" ]; then
    BACKUP_DIR="$BACKUP_ROOT/monthly/backup_$DATE"
    RETENTION=365
elif [ "$DAY_OF_WEEK" == "7" ]; then
    BACKUP_DIR="$BACKUP_ROOT/weekly/backup_$DATE"
    RETENTION=28
else
    BACKUP_DIR="$BACKUP_ROOT/daily/backup_$DATE"
    RETENTION=$RETENTION_DAYS
fi

# Créer le dossier
mkdir -p $BACKUP_DIR

# Backup MySQL
docker-compose exec -T db mysqldump \
  -u wp_user -pwp_password wordpress \
  | gzip > $BACKUP_DIR/database.sql.gz

# Backup fichiers
docker run --rm \
  -v $(docker volume ls -q | grep wp_content):/data \
  -v $BACKUP_DIR:/backup \
  ubuntu tar czf /backup/wp_content.tar.gz -C /data .

# Créer un checksum
cd $BACKUP_DIR
sha256sum * > CHECKSUMS.txt

# Nettoyer les anciennes sauvegardes
find $BACKUP_ROOT/daily -name "backup_*" -mtime +$RETENTION_DAYS -exec rm -rf {} \;
find $BACKUP_ROOT/weekly -name "backup_*" -mtime +28 -exec rm -rf {} \;
find $BACKUP_ROOT/monthly -name "backup_*" -mtime +365 -exec rm -rf {} \;

echo " Backup WordPress terminé: $BACKUP_DIR"

Exercice 4 : Test de Restauration d'Urgence

Scénario

Simuler une catastrophe totale et restaurer l'environnement complet.

Checklist de Restauration

  1. Arrêter tous les conteneurs
  2. Supprimer tous les volumes
  3. Supprimer toutes les images personnalisées
  4. Restaurer depuis la dernière sauvegarde
  5. Vérifier que tout fonctionne
#!/bin/bash
# disaster-recovery-test.sh

echo " SIMULATION DE CATASTROPHE"
echo ""
read -p "Êtes-vous sûr ? (oui/non) " confirm

if [ "$confirm" != "oui" ]; then
    echo "Annulé."
    exit 0
fi

# 1. Sauvegarder l'état actuel
echo " Sauvegarde de sécurité..."
./docker-backup-complete.sh

# 2. DESTRUCTION TOTALE
echo " Destruction de l'environnement..."
docker-compose down -v
docker system prune -af --volumes

# 3. RESTAURATION
echo " Restauration depuis backup..."
LATEST_BACKUP=$(ls -t /backups/docker/backup_*.tar.gz | head -1)

tar xzf $LATEST_BACKUP -C /tmp/
cd /tmp/backup_*

# Restaurer les volumes
for volume_file in volumes/*.tar.gz; do
    volume_name=$(basename $volume_file .tar.gz)
    docker volume create $volume_name
    docker run --rm \
        -v $volume_name:/data \
        -v $(pwd)/volumes:/backup \
        ubuntu tar xzf /backup/$(basename $volume_file) -C /data
done

# Restaurer les images
for image_file in images/*.tar.gz; do
    docker load < $image_file
done

# Restaurer la configuration
cp configs/docker-compose.yml /opt/docker/

# 4. REDÉMARRAGE
cd /opt/docker
docker-compose up -d

# 5. VÉRIFICATION
echo " Vérification..."
sleep 10
docker-compose ps
curl -I http://localhost:8080

echo " Restauration terminée !"

Bonnes Pratiques et Conseils

À FAIRE

  • Tester régulièrement vos procédures de restauration
  • Automatiser les sauvegardes avec cron
  • Chiffrer les backups contenant des données sensibles
  • Documenter vos procédures de backup/restore
  • Monitorer l'espace disque disponible
  • Versionner vos docker-compose.yml avec Git
  • Stocker hors site au moins une copie
  • Nettoyer régulièrement les anciennes sauvegardes

À ÉVITER

  • Ne jamais sauvegarder uniquement sur le même serveur
  • Ne pas stocker de mots de passe en clair dans les scripts
  • Ne pas faire de backup pendant que les bases de données écrivent
  • Ne jamais considérer qu'un backup non testé fonctionne
  • Ne pas oublier de vérifier l'intégrité des archives
  • Ne pas négliger la documentation de restauration

Sécurité des Sauvegardes

Chiffrement avec GPG

# Générer une clé GPG (si nécessaire)
gpg --gen-key

# Sauvegarder et chiffrer
docker run --rm \
  -v mon_volume:/data \
  -v $(pwd):/backup \
  ubuntu tar czf - -C /data . | \
  gpg --encrypt --recipient [email protected] > backup_encrypted.tar.gz.gpg

# Déchiffrer et restaurer
gpg --decrypt backup_encrypted.tar.gz.gpg | \
docker run --rm -i \
  -v mon_volume_restore:/data \
  ubuntu tar xzf - -C /data

Monitoring des Sauvegardes

#!/bin/bash
# healthcheck-backups.sh

# Vérifier l'âge de la dernière sauvegarde
LATEST=$(find /backups -name "*.tar.gz" -mtime -1 | wc -l)

if [ $LATEST -eq 0 ]; then
    echo " CRITIQUE: Pas de sauvegarde depuis 24h"
    # Envoyer une alerte
    curl -X POST "https://hooks.slack.com/services/YOUR/WEBHOOK/URL" \
      -d '{"text":" Docker backup failed"}'
    exit 1
fi

echo " Backups OK"
