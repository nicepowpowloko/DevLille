Module 1 : Introduction

Les 3 piliers (CIA Triad)

  • Confidentialité - Seules les personnes autorisées accèdent aux données
  • Intégrité - Les données ne sont pas modifiées sans autorisation
  • Disponibilité - Les services sont accessibles quand nécessaire

Menaces courantes

Attaque Impact
SQL InjectionVol/modification de données
XSSVol de sessions, phishing
CSRFActions non autorisées
DDoSIndisponibilité du service

Règles de base

  • Ne JAMAIS faire confiance aux entrées utilisateur
  • Toujours valider ET assainir les données
  • Utiliser HTTPS partout
  • Hasher les mots de passe (bcrypt/Argon2)
  • Maintenir les dépendances à jour

Module 2 : OWASP Top 10

Les 10 vulnérabilités critiques

  1. Broken Access Control - Contrôles d'accès défaillants
  2. Cryptographic Failures - Chiffrement faible ou absent
  3. Injection - SQL, NoSQL, OS Command injection
  4. Insecure Design - Conception non sécurisée
  5. Security Misconfiguration - Mauvaise configuration
  6. Vulnerable Components - Dépendances obsolètes
  7. Authentication Failures - Authentification faible
  8. Integrity Failures - Intégrité non vérifiée
  9. Logging Failures - Logs insuffisants
  10. SSRF - Server-Side Request Forgery

Exemple : Broken Access Control

//  VULNÉRABLE
app.get('/user/:id', (req, res) => {
    const user = db.getUser(req.params.id);
    res.json(user); // Pas de vérification !
});

//  SÉCURISÉ
app.get('/user/:id', (req, res) => {
    if (req.user.id !== req.params.id && !req.user.isAdmin) {
        return res.status(403).json({ error: 'Accès interdit' });
    }
    const user = db.getUser(req.params.id);
    res.json(user);
});

Module 3 : Validation des Données

Règle d'or

Ne JAMAIS faire confiance aux données utilisateur !

Validation vs Assainissement

  • Validation - Vérifier que les données sont valides (rejeter si non)
  • Assainissement - Nettoyer les données dangereuses

Exemple avec express-validator

const { body, validationResult } = require('express-validator');

app.post('/register',
    body('email').isEmail().normalizeEmail(),
    body('password').isLength({ min: 8 }),
    (req, res) => {
        const errors = validationResult(req);
        if (!errors.isEmpty()) {
            return res.status(400).json({ errors: errors.array() });
        }
        // Traitement...
    }
);

Échappement HTML

function escapeHTML(str) {
    const map = {
        '&': '&', '<': '<', '>': '>',
        '"': '"', "'": '''
    };
    return str.replace(/[&<>"']/g, c => map[c]);
}

Module 4 : Injections SQL

Qu'est-ce qu'une injection SQL ?

Insertion de code SQL malveillant dans les requêtes pour manipuler la base de données.

Attaque typique

//  VULNÉRABLE
const query = `SELECT * FROM users WHERE username='${username}'`;

// Attaquant envoie : username = "admin'--"
// Résultat : SELECT * FROM users WHERE username='admin'--'
// Le -- commente le reste → connexion sans mot de passe !

Solution : Requêtes préparées

//  SÉCURISÉ
const query = 'SELECT * FROM users WHERE username = ?';
db.query(query, [username]);

Protection

  • TOUJOURS utiliser des requêtes préparées
  • JAMAIS de concaténation de strings SQL
  • Utiliser un ORM (Sequelize, Prisma)
  • Moindre privilège pour le compte DB

Module 5 : XSS (Cross-Site Scripting)

Types de XSS

  • Réfléchi (Reflected) - Code dans l'URL, exécuté immédiatement
  • Stocké (Stored) - Code enregistré en DB, affecte tous les visiteurs
  • DOM-based - Vulnérabilité côté client

XSS Réfléchi

//  VULNÉRABLE
app.get('/search', (req, res) => {
    res.send(`<h1>Résultats : ${req.query.q}</h1>`);
});

//  SÉCURISÉ
app.get('/search', (req, res) => {
    const safe = escapeHTML(req.query.q);
    res.send(`<h1>Résultats : ${safe}</h1>`);
});

Protection

  1. Échapper les données - Utiliser escapeHTML()
  2. CSP - Content Security Policy
  3. HttpOnly cookies - Empêche l'accès JS
  4. textContent vs innerHTML
// CSP avec helmet
const helmet = require('helmet');
app.use(helmet.contentSecurityPolicy({
    directives: {
        defaultSrc: ["'self'"],
        scriptSrc: ["'self'"]
    }
}));

Module 6 : CSRF

Qu'est-ce que le CSRF ?

Force un utilisateur authentifié à exécuter des actions non désirées.

Protection : Token CSRF

const csrf = require('csurf');
const csrfProtection = csrf({ cookie: true });

app.get('/form', csrfProtection, (req, res) => {
    res.send(`
        <form method="POST">
            <input type="hidden" name="_csrf" value="${req.csrfToken()}">
            <button>Submit</button>
        </form>
    `);
});

app.post('/form', csrfProtection, (req, res) => {
    // Token vérifié automatiquement
});

SameSite Cookie

app.use(session({
    cookie: {
        httpOnly: true,
        secure: true,
        sameSite: 'strict' // Protection CSRF
    }
}));

Module 7 : Mots de Passe

Règles absolues

  • JAMAIS en clair "Si quelqu'un accède à ta base de données (piratage, employé malveillant, backup volé), tous les mots de passe sont lisibles"
  • JAMAIS MD5 ou SHA1 "
  • TOUJOURS bcrypt ou Argon2 " ~1000 hashs/seconde " " Résistant aux GPU:utilise beaucoup de mémoire
  • Avec MD5 " Pirate essaie 1 milliard de mots de passe → 1 000 000 000 ÷ 50 000 000 000 = 0.02 seconde → Il craque "Password123!" INSTANTANÉMENT
  • Avec bcrypt " Pirate essaie 1 milliard de mots de passe → 1 000 000 000 ÷ 1000 = 1 000 000 secondes → = 11.5 JOURS !

Solution : bcrypt

const bcrypt = require('bcrypt');

// Inscription
const hash = await bcrypt.hash(password, 12);
await db.createUser({ username, password: hash });

// Connexion
const user = await db.findUser(username);
const isValid = await bcrypt.compare(password, user.password);
if (isValid) {
    req.session.userId = user.id;
}

Politique robuste

  • Minimum 12 caractères
  • Majuscules + minuscules + chiffres + spéciaux
  • Pas de mots du dictionnaire
  • Rate limiting (5 tentatives max)

Module 8 : Sessions

Configuration sécurisée

app.use(session({
    secret: process.env.SESSION_SECRET,
    cookie: {
        httpOnly: true,    // Protection XSS
        secure: true,      // HTTPS uniquement
        sameSite: 'strict', // Protection CSRF
        maxAge: 3600000    // 1 heure
    }
}));

Gestion sécurisée

// Connexion : régénérer l'ID
app.post('/login', async (req, res) => {
    const user = await authenticate(req.body);
    if (user) {
        req.session.regenerate((err) => {
            req.session.userId = user.id;
            res.json({ success: true });
        });
    }
});

// Déconnexion : détruire
app.post('/logout', (req, res) => {
    req.session.destroy();
    res.clearCookie('sessionId');
});

Authentification 2FA

// Générer un secret
const secret = speakeasy.generateSecret({ name: 'MonApp' });

// Vérifier le code
const verified = speakeasy.totp.verify({
    secret: secret.base32,

JWT (JSON Web Tokens)

const jwt = require('jsonwebtoken');

// Générer
const token = jwt.sign(
    { userId: user.id },
    process.env.JWT_SECRET,
    { expiresIn: '1h' }
);

// Vérifier
jwt.verify(token, process.env.JWT_SECRET, (err, decoded) => {
    if (!err) {
        req.user = decoded;
    }
});

Module 10 : HTTPS

Pourquoi HTTPS ?

  • Chiffre toutes les communications
  • Protège contre Man-in-the-Middle
  • Nécessaire pour : cookies Secure, HTTP/2, PWA
  • Obligatoire pour la conformité RGPD

Obtenir un certificat SSL

# Let's Encrypt (gratuit)
sudo certbot --nginx -d monsite.com

# Renouvellement auto
sudo certbot renew --dry-run

Configuration Node.js

const https = require('https');
const fs = require('fs');

const options = {
    key: fs.readFileSync('privkey.pem'),
    cert: fs.readFileSync('fullchain.pem')
};

https.createServer(options, app).listen(443);

En-têtes de sécurité

const helmet = require('helmet');
app.use(helmet()); // Active HSTS, CSP, etc.

Rate Limiting

const rateLimit = require('express-rate-limit');

const limiter = rateLimit({
    windowMs: 15 * 60 * 1000, // 15 min
    max: 100 // 100 requêtes max
});

app.use('/api/', limiter);

CORS sécurisé

const cors = require('cors');

app.use(cors({
    origin: 'https://monsite.com',
    credentials: true,
    methods: ['GET', 'POST']
}));

Bonnes pratiques API

  • Utiliser JWT avec expiration courte
  • Rate limiting par IP et par utilisateur
  • CORS whitelist strict
  • Validation stricte des entrées
  • Versionner l'API (/api/v1/)

Module 12 : RGPD

Principes du RGPD

  • Consentement - Explicite et libre
  • Minimisation - Collecter le strict nécessaire
  • Finalité - Objectif clair et légitime
  • Durée limitée - Suppression après usage
  • Sécurité - Protection des données
  • Transparence - Informer les utilisateurs

Données sensibles

Nécessitent une protection renforcée :

  • Origine ethnique, opinions politiques
  • Santé, données génétiques
  • Orientation sexuelle
  • Données bancaires

Droits des utilisateurs

Droit Action technique
Accès Export des données utilisateur
Rectification Modification des données
Suppression Anonymisation/suppression
Portabilité Export au format JSON/CSV

Export des données

app.get('/api/my-data', requireAuth, async (req, res) => {
    const userData = await db.getUserData(req.user.id);
    res.json({
        profile: userData.profile,
        orders: userData.orders,
        messages: userData.messages
    });
});

Suppression de compte

app.delete('/api/account', requireAuth, async (req, res) => {
    // Anonymiser ou supprimer
    await db.deleteUser(req.user.id);
    req.session.destroy();
    res.json({ success: true });
});

Obligations légales

  • Déclarer les traitements à la CNIL si nécessaire
  • Nommer un DPO si > 250 employés
  • Notifier les violations sous 72h
  • Amendes jusqu'à 20M€ ou 4% du CA
