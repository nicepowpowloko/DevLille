EXO-01 Creer la table utilisateurs CREATE TABLE / types de colonnes

Dans phpMyAdmin, onglet SQL, cree une table utilisateurs dans ta base avec les colonnes : id (cle primaire auto-increment), nom (varchar 100), email (varchar 150 unique), age (int), actif (tinyint, valeur par defaut 1), cree_le (datetime, CURRENT_TIMESTAMP). Verifie ensuite dans l'onglet Structure que tout est correct.

Objectifs

  • Utiliser INT AUTO_INCREMENT PRIMARY KEY pour l'id
  • Definir les bons types : VARCHAR, INT, TINYINT, DATETIME
  • Ajouter une contrainte UNIQUE sur l'email
  • Definir une valeur par defaut avec DEFAULT
Solution
-- Solution complete
CREATE TABLE utilisateurs (
  id     INT AUTO_INCREMENT PRIMARY KEY,
  nom     VARCHAR(100) NOT NULL,
  email   VARCHAR(150) NOT NULL UNIQUE,
  age     INT,
  actif   TINYINT DEFAULT 1,
  cree_le DATETIME DEFAULT CURRENT_TIMESTAMP
);

EXO-03 Lire des donnees avec SELECT SELECT / * / colonnes specifiques

Sur la table utilisateurs, ecris trois requetes distinctes : 1) selectionne toutes les colonnes de tous les utilisateurs, 2) selectionne uniquement le nom et l'email, 3) selectionne les utilisateurs de plus de 25 ans avec WHERE, tries par age croissant avec ORDER BY.

Objectifs

  • Selectionner toutes les colonnes : SELECT *
  • Selectionner des colonnes precises : SELECT col1, col2
  • Filtrer avec WHERE age > 25
  • Trier avec ORDER BY age ASC
Solution
-- 1. Toutes les colonnes
SELECT * FROM utilisateurs;

-- 2. Colonnes specifiques
SELECT nom, email FROM utilisateurs;

-- 3. Filtrer et trier
SELECT nom, age FROM utilisateurs
WHERE age > 25
ORDER BY age ASC;
SELECT * SELECT col1, col2 WHERE ORDER BY ASC / DESC

EXO-04 Modifier des donnees UPDATE / SET / WHERE

Sur la table utilisateurs, ecris trois requetes UPDATE : 1) change l'age d'Alice a 29, 2) desactive tous les utilisateurs de moins de 25 ans (mettre actif = 0), 3) change l'email de Bob. Verifie apres chaque requete dans l'onglet Parcourir.

Objectifs

  • Syntaxe : UPDATE table SET col = val WHERE condition
  • Modifier plusieurs colonnes a la fois : SET col1 = v1, col2 = v2
  • Ne jamais oublier le WHERE sinon toutes les lignes sont modifiees
  • Cibler par id pour etre precis
Solution
-- 1. Modifier l'age d'Alice

-- 2. Desactiver les moins de 25 ans
UPDATE utilisateurs SET actif = 0 WHERE age < 25;

UPDATE utilisateurs SET email = 'bob.dupont@nouveau.fr' WHERE id = 2;

EXO-07 Liaison de tables avec JOIN INNER JOIN / LEFT JOIN / cle etrangere

Utilise les tables utilisateurs et commandes crees precedemment. Ecris trois requetes JOIN : 1) affiche le nom de l'utilisateur avec chacune de ses commandes (INNER JOIN), 2) affiche tous les utilisateurs meme ceux sans commande (LEFT JOIN), 3) affiche le nom et le total des commandes par utilisateur.

Objectifs

  • Comprendre la cle etrangere : commandes.utilisateur_id reference utilisateurs.id
  • INNER JOIN : seulement les lignes qui correspondent dans les deux tables
  • LEFT JOIN : toutes les lignes de gauche, meme sans correspondance a droite
  • Combiner JOIN + GROUP BY + SUM()
Solution
-- INNER JOIN
SELECT u.nom, c.montant, c.statut
FROM utilisateurs u
INNER JOIN commandes c ON u.id = c.utilisateur_id;

-- LEFT JOIN
SELECT u.nom, c.montant
FROM utilisateurs u
LEFT JOIN commandes c ON u.id = c.utilisateur_id;

-- JOIN + GROUP BY
SELECT u.nom, SUM(c.montant) AS total
FROM utilisateurs u
INNER JOIN commandes c ON u.id = c.utilisateur_id
GROUP BY u.id, u.nom;
INNER JOIN LEFT JOIN ON u.id = c.user_id alias u / c JOIN + GROUP BY
EXO-08 Requetes imbriquees et HAVING sous-requete / HAVING / LIMIT / OFFSET

Avec les tables utilisateurs et commandes, ecris quatre requetes avancees : 1) affiche les utilisateurs ayant passe au moins 2 commandes avec HAVING, 2) affiche les 2 commandes les plus chere avec ORDER BY ... LIMIT, 3) selectionne les utilisateurs dont l'id est dans une sous-requete, 4) pagine les resultats avec LIMIT et OFFSET.

Objectifs

  • Filtrer apres GROUP BY : HAVING COUNT(*) >= 2
  • Limiter les resultats : LIMIT 2
  • Paginer : LIMIT 5 OFFSET 10 (page 3 avec 5 resultats/page)
  • Sous-requete : WHERE id IN (SELECT utilisateur_id FROM commandes)
Solution
-- HAVING
SELECT u.nom, COUNT(c.id) AS nb_commandes
FROM utilisateurs u
INNER JOIN commandes c ON u.id = c.utilisateur_id
GROUP BY u.id HAVING COUNT(c.id) >= 2;

-- LIMIT
SELECT * FROM commandes ORDER BY montant DESC LIMIT 2;

-- Sous-requete
SELECT nom FROM utilisateurs WHERE id IN (SELECT utilisateur_id FROM commandes);

-- Pagination page 2
SELECT * FROM commandes ORDER BY id LIMIT 2 OFFSET 2;
HAVING LIMIT OFFSET sous-requete IN pagination
EXO-09 Schema complet e-commerce CREATE TABLE / FK / JOIN multi-tables Bonus

Exercice bonus. Cree un schema e-commerce avec 3 tables liees : categories (id, nom), produits (id, nom, prix, stock, categorie_id FK), commande_produits (id, commande_id, produit_id, quantite). Insere des donnees dans chaque table. Ecris une requete JOIN sur les 3 tables pour afficher : nom du produit, categorie, quantite commandee, sous-total.

Objectifs

  • Creer des cles etrangeres : FOREIGN KEY (col) REFERENCES table(id)
  • Inserer dans le bon ordre (categorie avant produit)
  • JOIN sur 3 tables en chainant les ON
  • Calculer un sous-total : quantite * prix AS sous_total
Solution
-- Inserer dans l'ordre : categories -> produits -> commande_produits
INSERT INTO categories (nom) VALUES ('Electronique'), ('Vetements'), ('Alimentation');

INSERT INTO produits (nom, prix, stock, categorie_id) VALUES
  ('Clavier Pro', 49.90, 10, 1),
  ('T-shirt blanc', 24.90, 50, 2),
  ('Cafe Ethiopia', 12.50, 200, 3);

-- JOIN 3 tables
SELECT p.nom AS produit, cat.nom AS categorie,
       cp.quantite, (p.prix * cp.quantite) AS sous_total
FROM commande_produits cp
INNER JOIN produits p ON cp.produit_id = p.id
INNER JOIN categories cat ON p.categorie_id = cat.id;
