Le patron MVC (Model View Controller) separe les donnees, l'affichage et la logique. On va construire un mini-framework MVC maison en PHP pur — sans Symfony ni Laravel — pour comprendre comment ca fonctionne vraiment.

Le patron MVC

MVC divise l'application en trois couches independantes. Chaque couche a une responsabilite unique et ne connait pas les details internes des autres.

M — Model Acces aux donnees (PDO, BDD). Ne sait rien de l'affichage. V — View Templates HTML/PHP. Ne sait rien de la BDD. C — Controller Chef d'orchestre : recoit la requete, appelle le Model, transmet les donnees a la View, renvoie la reponse.
i
Pourquoi MVC ? Sans separation, un fichier PHP melange requetes SQL, HTML et logique. On ne peut rien tester, rien reutiliser, rien changer sans tout casser. MVC rend chaque partie independante, testable et modifiable sans impacter les autres.

Etape 1

Structure de projet

On va construire un projet avec cette structure. Chaque dossier a un role strict. Le dossier public/ est le seul accessible depuis le navigateur — tous les autres sont proteges.

  app/                     <-- code de l'application
    Controllers/

      ProduitModel.php
    Views/
      layout.php            template principal
      produits/
        index.php           liste

        show.php            detail

public/ est la seule racine web. Configurer Apache (WAMP/MAMP/Laragon) pour que le DocumentRoot pointe sur public/. Ainsi app/, core/ et config/ ne sont jamais accessibles directement depuis le navigateur.

Etape 2

Front controller + .htaccess

Le front controller est le point d'entree unique. Toutes les requetes arrivent sur public/index.php grace au fichier .htaccess qui redirige tout. Puis le routeur analyse l'URL et decide quel controller appeler.

public/.htaccess — redirection URL RewritingConfig
# public/.htaccess — redirige tout vers index.php
Options -Indexes
RewriteEngine On

# Laisser passer les fichiers physiques (CSS, JS, images)
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d

# Tout le reste vers index.php
RewriteRule ^(.*)$ index.php [QSA,L]
public/index.php — front controllerPHP
<?php
// public/index.php — FRONT CONTROLLER
// Tout passe par ici. Il orchestre le demarrage.

define('ROOT', dirname(__DIR__));

// Autoloader Composer
require_once ROOT . '/vendor/autoload.php';

// Variables d'environnement
use Dotenv\Dotenv;
Dotenv::createImmutable(ROOT)->load();

// Demarrer le routeur
use Core\Router;

$router = new Router();

// Declaration des routes
$router->get('/',                      'ProduitController@index');
$router->get('/produits',             'ProduitController@index');
$router->get('/produits/create',      'ProduitController@create');
$router->post('/produits/store',      'ProduitController@store');
$router->get('/produits/{id}',        'ProduitController@show');
$router->get('/produits/{id}/edit',   'ProduitController@edit');
$router->post('/produits/{id}/update', 'ProduitController@update');
$router->post('/produits/{id}/delete', 'ProduitController@delete');

$router->dispatch($_SERVER['REQUEST_URI'], $_SERVER['REQUEST_METHOD']);
!
Convention "Controller@methode". La chaine ProduitController@index indique : classe ProduitController, methode index. Le routeur va splitter cette chaine pour instancier la classe et appeler la methode.
03
Etape 3

Router

Le Router analyse l'URL et le verbe HTTP (GET/POST). Il compare l'URL aux routes enregistrees, extrait les parametres dynamiques {id}, puis instancie le controller et appelle la methode.

core/Router.php — routeur avec parametresPHP
<?php
namespace Core;

class Router {

    private array $routes = [];

    public function get(string $uri, string $action): void {
        $this->routes['GET'][$uri] = $action;
    }

    public function post(string $uri, string $action): void {
        $this->routes['POST'][$uri] = $action;
    }

    public function dispatch(string $uri, string $method): void {
        // Nettoyer l'URI (enlever query string et slash final)
        $uri = strtok($uri, '?');
        $uri = rtrim($uri, '/') ?: '/';

        foreach ($this->routes[$method] ?? [] as $pattern => $action) {
            $regex = preg_replace('#\{[a-z]+\}#', '([^/]+)', $pattern);
            if (preg_match('#^' . $regex . '$#', $uri, $matches)) {
                array_shift($matches);  // enlever le match complet
                $this->call($action, $matches);
                return;
            }
        }

        // Aucune route trouvee : 404
        http_response_code(404);
        echo '<h1>404 — Page introuvable</h1>';
    }

    private function call(string $action, array $params): void {
        [$class, $method] = explode('@', $action);
        $fqcn = 'App\\Controllers\\' . $class;
        $controller = new $fqcn();
        $controller->{$method}(...$params);
    }
}

// Routes avec parametres dynamiques :
// /produits/{id} => regex /produits/([^/]+)
// /produits/42    => $matches[0] = "42"
i
Parametres dynamiques. La route /produits/{id} est convertie en regex /produits/([^/]+). Si l'URL est /produits/42, le match donne $matches = ['42']. Ces valeurs sont passees comme arguments a la methode du controller.

Etape 4

Controller

Le controller de base fournit les methodes render() et redirect(). Les controllers concrets l'etendent et definissent les actions. Chaque action = une methode publique.

app/Controllers/Controller.php — classe de basePHP
<?php
namespace App\Controllers;

abstract class Controller {

    /**
     * Rendre une vue en lui passant des donnees.
     */
    protected function render(string $view, array $data = []): void {
        // extract(data) transforme les cles en variables PHP
        extract($data);

        // Chemin vers le fichier de vue
        $viewPath = ROOT . '/app/Views/' . $view . '.php';

        if (!file_exists($viewPath)) {
            throw new \RuntimeException('Vue introuvable : ' . $view);
        }

        // Inclure le layout qui lui-meme inclura la vue
        $content = $viewPath;
        require ROOT . '/app/Views/layout.php';
    }

    protected function redirect(string $url): void {
        header('Location: ' . $url);
        exit;
    }
}
app/Controllers/ProduitController.phpPHP
<?php
namespace App\Controllers;

use App\Models\ProduitModel;

class ProduitController extends Controller {

    private ProduitModel $model;

    public function __construct() {
        $this->model = new ProduitModel();
    }

    // GET /produits
    public function index(): void {
        $produits = $this->model->findAll();
        $this->render('produits/index', [
            'titre'    => 'Catalogue',
            'produits' => $produits,
        ]);
    }

    // GET /produits/{id}
    public function show(string $id): void {
        $produit = $this->model->findById((int)$id);
        if (!$produit) { http_response_code(404); return; }
        $this->render('produits/show', [
            'titre'   => $produit['nom'],
            'produit' => $produit,
        ]);
    }

    // GET /produits/create
    public function create(): void {
        $this->render('produits/create', ['titre' => 'Nouveau produit']);
    }
}
+
extract($data) est cle. La methode render() appelle extract(['titre' => 'Catalogue', 'produits' => [...]]). Cela cree les variables $titre et $produits disponibles dans le fichier de vue inclus juste apres.

Etape 5

Model

Le Model de base fournit les methodes CRUD generiques via la propriete $table. Chaque Model concret etend cette base et ajoute ses requetes metier specifiques.

app/Models/Model.php — base CRUDPHP
<?php
namespace App\Models;

use \PDO;
use \PDOException;

abstract class Model {

    protected PDO $pdo;
    protected string $table = '';

    public function __construct() {
        $this->pdo = $this->connect();
    }

    private function connect(): PDO {
        $dsn = 'mysql:host=' . getenv('DB_HOST')
             . ';port='   . getenv('DB_PORT')
             . ';dbname=' . getenv('DB_NAME')
             . ';charset=utf8mb4';
        return new PDO($dsn, getenv('DB_USER'), getenv('DB_PASS'), [
            PDO::ATTR_ERRMODE           => PDO::ERRMODE_EXCEPTION,
            PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
        ]);
    }

    // Methodes CRUD generiques
    public function findAll(): array {
        return $this->pdo->query('SELECT * FROM ' . $this->table)->fetchAll();
    }

    public function findById(int $id): ?array {
        $stmt = $this->pdo->prepare('SELECT * FROM ' . $this->table . ' WHERE id = ?');
        $stmt->execute([$id]);
        return $stmt->fetch() ?: null;
    }

    public function delete(int $id): bool {
        $stmt = $this->pdo->prepare('DELETE FROM ' . $this->table . ' WHERE id = ?');
        return $stmt->execute([$id]);
    }
}
app/Models/ProduitModel.phpPHP
<?php
namespace App\Models;

class ProduitModel extends Model {

    protected string $table = 'produits';

    // Requete metier specifique aux produits
    public function findAllWithCategorie(): array {
        $sql = 'SELECT p.*, c.nom AS categorie
               FROM produits p
               LEFT JOIN categories c ON p.categorie_id = c.id
               ORDER BY p.nom';
        return $this->pdo->query($sql)->fetchAll();
    }

    public function create(array $data): int {
        $stmt = $this->pdo->prepare(
            'INSERT INTO produits (nom, prix, stock, categorie_id)
             VALUES (:nom, :prix, :stock, :categorie_id)'
        );
        $stmt->execute($data);
        return (int)$this->pdo->lastInsertId();
    }

    public function update(int $id, array $data): bool {
        $data['id'] = $id;
        $stmt = $this->pdo->prepare(
            'UPDATE produits SET nom=:nom, prix=:prix, stock=:stock WHERE id=:id'
        );
        return $stmt->execute($data);
    }
}
!
La propriete $table est la seule chose a definir. Grace a la classe de base, un ProduitModel obtient findAll(), findById() et delete() gratuitement. Il n'ajoute que les requetes specifiques aux produits.

Vues PHP

Les vues sont de simples fichiers PHP/HTML. Le layout est le gabarit principal (nav, head, body). La vue partielle est injectee dans le layout via la variable $content. htmlspecialchars() protege contre les XSS.

    <meta charset="UTF-8">

    <link rel="stylesheet" href="/assets/css/style.css">
</head>
<body>
<nav>
    <a href="/">Accueil</a>
    <a href="/produits">Produits</a>

!
Toujours echapper les donnees affichees. htmlspecialchars($var) transforme <script> en texte inoffensif. Sans ca, si un nom de produit contient du JS, il s'executera dans le navigateur (XSS). Regles : echapper toute donnee venant de la BDD ou de l'utilisateur avant de l'afficher.

Etape 7

CRUD complet dans le Controller

Voici les actions CRUD completes du controller : store (creation), edit (formulaire edition), update (traitement edition) et delete. On applique le PRG pattern (Post/Redirect/Get) pour eviter la resoumission du formulaire au rafraichissement.

ProduitController.php — actions store / edit / update / deletePHP
<?php
// Suite de ProduitController.php

    // POST /produits/store — traiter le formulaire
    public function store(): void {
        // Valider les donnees
        $nom   = trim($_POST['nom'] ?? '');
        $prix  = (float)($_POST['prix'] ?? 0);
        $stock = (int)($_POST['stock'] ?? 0);

        if (empty($nom) || $prix <= 0) {
            $this->render('produits/create', [
                'titre'  => 'Nouveau produit',
                'errors' => ['Nom et prix requis'],
                'old'    => $_POST,
            ]);
            return;
        }

        // Creer en BDD
        $id = $this->model->create([
            'nom'          => $nom,
            'prix'         => $prix,
            'stock'        => $stock,
            'categorie_id' => $_POST['categorie_id'] ?? null,
        ]);

        // Rediriger apres succes (PRG pattern)
        $this->redirect('/produits/' . $id);
    }

    // GET /produits/{id}/edit
    public function edit(string $id): void {
        $produit = $this->model->findById((int)$id);
        if (!$produit) { http_response_code(404); return; }
        $this->render('produits/edit', [
            'titre'   => 'Modifier : ' . $produit['nom'],
            'produit' => $produit,
        ]);
    }

    // POST /produits/{id}/update
    public function update(string $id): void {
        $this->model->update((int)$id, [
            'nom'  => trim($_POST['nom']),
            'prix' => (float)$_POST['prix'],
            'stock'=> (int)$_POST['stock'],
        ]);
        $this->redirect('/produits/' . $id);
    }

    // POST /produits/{id}/delete
    public function delete(string $id): void {
        $this->model->delete((int)$id);
        $this->redirect('/produits');
    }
i
PRG Pattern — Post Redirect Get. Apres un POST reussi, on ne rend pas directement une vue : on fait un redirect(). Ainsi si l'utilisateur rafraichit la page, il recharge un GET et non le POST. Sans ca, le formulaire est resoumis et le produit cree deux fois.

Etape 8

Formulaire avec validation

Le formulaire de creation illustre deux bonnes pratiques : afficher les erreurs de validation au-dessus du formulaire, et repeupler les champs avec les valeurs precedentes (old input) pour que l'utilisateur ne ressaisisse pas tout.

app/Views/produits/create.php — formulaire avec validationHTML
<!-- app/Views/produits/create.php -->
<h1><?= htmlspecialchars($titre) ?></h1>

<!-- Afficher les erreurs de validation -->
<?php if (!empty($errors)): ?>
    <ul class="errors">
    <?php foreach ($errors as $err): ?>
        <li><?= htmlspecialchars($err) ?></li>
    <?php endforeach; ?>
    </ul>
<?php endif; ?>

<form method="post" action="/produits/store">

    <label>Nom
        <input type="text" name="nom"
               value="<?= htmlspecialchars($old['nom'] ?? '') ?>"
               required>
    </label>

    <label>Prix (EUR)
        <input type="number" name="prix" step="0.01" min="0"
               value="<?= $old['prix'] ?? '' ?>" required>
    </label>

    <label>Stock
        <input type="number" name="stock" min="0"
               value="<?= $old['stock'] ?? 0 ?>">
    </label>

    <button type="submit">Creer</button>
    <a href="/produits">Annuler</a>

</form>
+
Old input ($old). Quand la validation echoue, le controller renvoie la vue avec 'old' => $_POST. La vue peut ainsi repopuler les champs avec $old['nom'] ?? ''. L'utilisateur retrouve ses saisies et ne doit corriger que les champs en erreur.
