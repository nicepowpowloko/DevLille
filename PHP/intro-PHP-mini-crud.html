Architecture

CRUD et JSON — le projet

CRUD est l'acronyme des 4 operations fondamentales sur des donnees : Create, Read, Update, Delete. Ce projet gere une liste de contacts stockes dans un fichier data/contacts.json. Aucune BDD, aucune installation — ideal pour apprendre la logique avant PDO.

C — Create Ajouter un contact POST /index.php?action=ajouter R — Read Afficher la liste GET /index.php U — Update Modifier un contact POST /index.php?action=modifier&id=3 D — Delete Supprimer un contact GET /index.php?action=supprimer&id=3 Structure des fichiers : projet/ index.php routeur + affichage liste ajouter.php formulaire + traitement ajout modifier.php formulaire + traitement modif data/ contacts.json base de donnees JSON includes/ fonctions.php lire/ecrire le JSON
i
JSON comme base de donnees temporaire. Ce pattern fonctionne bien pour des petits projets (moins de quelques centaines d'entrees). Pour de vraies applications, on utilise MariaDB + PDO. L'objectif ici est de pratiquer la logique CRUD avant d'aborder SQL.
01
Etape 1 — Persistance

Lire et ecrire le fichier JSON

includes/fonctions.php — lecture et ecriturePHP
<?php
define('FICHIER_JSON', __DIR__ . '/../data/contacts.json');

// Lire tous les contacts depuis le JSON
function lireContacts(): array {
    if (!file_exists(FICHIER_JSON)) {
        return [];  // fichier absent = liste vide
    }
    $contenu = file_get_contents(FICHIER_JSON);
    $data    = json_decode($contenu, true);
    // true = tableau associatif (pas objet stdClass)
    return is_array($data) ? $data : [];
}

// Ecrire tous les contacts dans le JSON
function ecrireContacts(array $contacts): void {
    $dossier = dirname(FICHIER_JSON);
    if (!is_dir($dossier)) {
        mkdir($dossier, 0755, true);
    }
    $json = json_encode($contacts, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE);
    file_put_contents(FICHIER_JSON, $json);
}

// Trouver un contact par ID
function trouverContact(int $id): ?array {
    foreach (lireContacts() as $contact) {
        if ($contact['id'] === $id) return $contact;
    }
    return null;
}

// Generer le prochain ID (max existant + 1)
function prochainId(): int {
    $contacts = lireContacts();
    if (empty($contacts)) return 1;
    return max(array_column($contacts, 'id')) + 1;
}
i
json_decode($str, true) — le deuxieme argument true est essentiel. Sans lui, PHP retourne des objets stdClass qu'on accede avec ->. Avec true, on obtient des tableaux associatifs accessibles avec [] — plus simple et coherent avec le reste du code PHP.

Etape 2 — Create

Ajouter un contact

ajouter.php — formulaire et traitementCREATE
<?php
session_start();
require_once 'includes/fonctions.php';

$erreurs = [];
$nom = $email = $tel = '';

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $nom   = trim($_POST['nom']   ?? '');
    $email = trim($_POST['email'] ?? '');
    $tel   = trim($_POST['tel']   ?? '');

    // Validation
    if (strlen($nom) < 2)
        $erreurs['nom'] = 'Nom obligatoire (2 car. min).';
    if (!filter_var($email, FILTER_VALIDATE_EMAIL))
        $erreurs['email'] = 'Email invalide.';

    if (empty($erreurs)) {
        $contacts = lireContacts();

        // Creer le nouveau contact
        $contacts[] = [
            'id'    => prochainId(),
            'nom'   => $nom,
            'email' => $email,
            'tel'   => $tel,
        ];

        ecrireContacts($contacts);

        // Message flash en session
        $_SESSION['flash'] = 'Contact ajoute avec succes.';
        header('Location: index.php'); exit;
    }
}
?>

Le message flash. Stocker un message en session puis le supprimer immediatement apres affichage est le pattern "flash message". Il affiche une notification apres une redirection POST sans que le message reapparaisse au rechargement.

Etape 4 — Update

Modifier un contact

modifier.php — pre-remplissage et mise a jourUPDATE
<?php
session_start();
require_once 'includes/fonctions.php';

$id = (int)($_GET['id'] ?? 0);
$contact = trouverContact($id);

if (!$contact) {
    header('Location: index.php'); exit;
}

$erreurs = [];

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $nom   = trim($_POST['nom']   ?? '');
    $email = trim($_POST['email'] ?? '');
    $tel   = trim($_POST['tel']   ?? '');

    if (strlen($nom) < 2)
        $erreurs['nom'] = 'Nom obligatoire.';
    if (!filter_var($email, FILTER_VALIDATE_EMAIL))
        $erreurs['email'] = 'Email invalide.';

    if (empty($erreurs)) {
        $contacts = lireContacts();

        // Trouver et modifier le bon contact
        foreach ($contacts as &$c) {  // & = reference
            if ($c['id'] === $id) {
                $c['nom']   = $nom;
                $c['email'] = $email;
                $c['tel']   = $tel;
                break;
            }
        }
        unset($c);  // liberer la reference

        ecrireContacts($contacts);
        $_SESSION['flash'] = 'Contact modifie.';
        header('Location: index.php'); exit;
    }
} else {
    // Pre-remplir le formulaire avec les valeurs actuelles
    $nom   = $contact['nom'];
    $email = $contact['email'];
    $tel   = $contact['tel'] ?? '';
}
!
Le & dans foreach est crucial pour la modification. Sans la reference &$c, foreach travaille sur des copies et les modifications ne sont pas repercutees dans le tableau original. Toujours appeler unset($c) apres la boucle pour eviter les effets de bord.

Etape 5 — Delete

Supprimer un contact

Suppression dans index.php — action=supprimerDELETE
<?php
session_start();
require_once 'includes/fonctions.php';

$action = $_GET['action'] ?? '';

if ($action === 'supprimer') {
    $id = (int)($_GET['id'] ?? 0);

    if ($id > 0) {
        $contacts = lireContacts();

        // Filtrer : garder tous sauf celui a supprimer
        $contacts = array_values(
            array_filter($contacts, fn($c) => $c['id'] !== $id)
        );

        ecrireContacts($contacts);
        $_SESSION['flash'] = 'Contact supprime.';
    }

    header('Location: index.php'); exit;
}

// ... suite : affichage de la liste
!
Ne jamais supprimer via un lien GET en production. Un lien ?action=supprimer&id=3 peut etre declenche accidentellement (prefetch du navigateur, bot de crawl). En production, la suppression doit passer par un formulaire POST avec un token CSRF. Pour ce projet pedagogique, on garde GET pour la simplicite.

Etape 6 — Architecture

Routeur d'actions dans index.php

index.php — routeur completComplet
<?php
session_start();
require_once 'includes/fonctions.php';

$action = $_GET['action'] ?? 'liste';

// Routeur : dispatcher selon l'action
switch ($action) {

    case 'supprimer':
        $id = (int)($_GET['id'] ?? 0);
        if ($id > 0) {
            $contacts = array_values(array_filter(
                lireContacts(), fn($c) => $c['id'] !== $id
            ));
            ecrireContacts($contacts);
            $_SESSION['flash'] = 'Contact supprime.';
        }
        header('Location: index.php'); exit;

    case 'liste':
    default:
        $flash = $_SESSION['flash'] ?? '';
        unset($_SESSION['flash']);
        $contacts = lireContacts();

        $q = trim($_GET['q'] ?? '');
        if ($q) {
            $contacts = array_filter($contacts, fn($c) =>
                stripos($c['nom'], $q) !== false ||
                stripos($c['email'], $q) !== false
            );
        }
        break;
}
// Affichage HTML en dessous...
OK
Pattern PRG systematique. Toutes les actions qui modifient des donnees (ajout, modification, suppression) terminent par un header('Location:') + exit. Cela evite le double envoi au rechargement et suit le pattern Post/Redirect/Get.
