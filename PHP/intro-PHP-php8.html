01
PHP 8.0

match — remplacant de switch

PHP 8.0

match est la version moderne de switch. Il retourne une valeur, utilise la comparaison stricte (===), et lance une UnhandledMatchError si aucun cas ne correspond.

match — remplacant moderne de switchPHP
<?php
// switch — problemes : loose comparison, break oublie, pas de valeur
switch ($status) {
    case 'active':
        $label = 'Actif'; break;
    case 'pending':
        $label = 'En attente'; break;
    default:
        $label = 'Inconnu';
}

// match — retourne une valeur, comparaison stricte, exhaustif
$label = match($status) {
    'active'  => 'Actif',
    'pending' => 'En attente',
    default  => 'Inconnu',
};

// Plusieurs conditions pour un meme bras
$type = match(true) {
    $age < 18              => 'mineur',
    $age >= 18 && $age < 65 => 'adulte',
    $age >= 65             => 'senior',
};

// Plusieurs valeurs pour un meme bras (virgule)
$estFerie = match($jour) {
    'samedi', 'dimanche' => true,
    default              => false,
};

// Sans default : UnhandledMatchError si aucun cas ne correspond
// switch aurait silencieusement retourne null
$tva = match($categorie) {
    'alimentaire' => 0.055,
    'livre'        => 0.055,
    'standard'     => 0.20,
};  // UnhandledMatchError si $categorie est invalide
+
match est exhaustif par defaut. Sans default, si aucun cas ne correspond, PHP lance une UnhandledMatchError. Avec switch, aucune erreur n'est levee : le bug reste silencieux. match force a gerer tous les cas.

PHP 8.0

Named arguments

PHP 8.0

Les arguments nommes permettent de passer les parametres par leur nom plutot que par position. L'ordre n'a plus d'importance et les valeurs par defaut peuvent etre sautees.

Named arguments — appels lisiblesPHP
<?php
// Avant : ordre obligatoire, impossible de sauter des params
array_slice($arr, 0, 3, true);  // que fait "true" ici ?
htmlspecialchars($str, ENT_QUOTES, 'UTF-8', false);

// Avec named arguments : lisible, ordre libre
array_slice(array: $arr, offset: 0, length: 3, preserve_keys: true);

// Sauter les params avec valeur par defaut
htmlspecialchars(string: $str, double_encode: false);
// ENT_COMPAT et UTF-8 ont des valeurs par defaut : on peut les sauter

// Dans ses propres fonctions
function creerProduit(
    string $nom,
    float  $prix,
    int    $stock   = 0,
    bool   $actif   = true,
    ?int   $categId = null,
): array { return compact('nom', 'prix', 'stock', 'actif', 'categId'); }

// Appel clair, ordre libre, params optionnels sautes
creerProduit(nom: 'T-shirt', prix: 19.99, categId: 3);
// stock et actif gardent leurs valeurs par defaut
!
Tres utile avec les fonctions PHP natives. Des fonctions comme setcookie(), array_slice(), str_contains() ont de nombreux parametres. Les named arguments permettent de ne passer que ceux qui nous interessent, rendant l'appel auto-documenté.

PHP 8.0

Nullsafe operator ?->

PHP 8.0

L'operateur ?-> court-circuite la chaine d'appels si une valeur est null. Plus besoin d'imbriquer des if ($x !== null).

Nullsafe operator ?-> — chaines sans null-checkPHP
<?php
// Avant : code defensif verbeux
$ville = null;
if ($user !== null) {
    if ($user->getAdresse() !== null) {
        $ville = $user->getAdresse()->getVille();
    }
}

// Avec ?-> : court-circuite sur null, retourne null
$ville = $user?->getAdresse()?->getVille();

// Chaine complete : si un maillon est null, tout retourne null
$pays = $commande?->getClient()?->getAdresse()?->getPays();

// Combiner avec operateur null coalescing ??
$pays = $commande?->getClient()?->getAdresse()?->getPays() ?? 'France';

// Avec l'ORM dans un controller
$nomCategorie = $produit?->getCategorie()?->getNom() ?? 'Sans categorie';
i
?-> ne modifie rien si la valeur est non-null. Si $user existe, $user?->getAdresse() se comporte exactement comme $user->getAdresse(). Le ? n'a un effet que si la valeur de gauche est null, auquel cas toute la chaine retourne null.

PHP 8.0

Union types et types avances

PHP 8.0

Les union types permettent de declarer qu'un parametre ou un retour peut avoir plusieurs types. Plus besoin de commentaires PHPDoc pour ca.

Union types, mixed, never, intersection typesPHP
<?php
// Union types : string|int, float|null, etc.
function traiterIdentifiant(string|int $id): string {
    return 'ID: ' . $id;
}

// Equivalent de ?string = string|null
function trouver(int $id): string|null { ... }
function trouver(int $id): ?string { ... }  // identique

// mixed — peut etre n'importe quel type (explicite)
function jsonDecode(string $json): mixed {
    return json_decode($json, true);
}

// never — la fonction ne retourne jamais (PHP 8.1)
function abort(int $code): never {
    http_response_code($code);
    exit;  // ou throw, ou une boucle infinie
}

// Intersection types — doit implementer les deux (PHP 8.1)
function sauvegarder(Serializable&Countable $obj): void { ... }

// DNF types — combinaison (PHP 8.2)
function traiter((Serializable&Countable)|null $obj): void { ... }

PHP 8.0

Promotion de proprietes

PHP 8.0

La promotion de proprietes dans le constructeur elimine le code repetitif de declaration + assignation. C'est l'une des ameliorations les plus appreciees de PHP 8.

Promotion de proprietes dans le constructeurPHP
<?php
// Avant PHP 8 : beaucoup de repetition
class Produit {
    private string $nom;
    private float  $prix;
    private int    $stock;

    public function __construct(string $nom, float $prix, int $stock) {
        $this->nom   = $nom;
        $this->prix  = $prix;
        $this->stock = $stock;
    }
}

// PHP 8 : promotion des proprietes — meme resultat, 3x moins de code
class Produit {
    public function __construct(
        private string $nom,
        private float  $prix,
        private int    $stock = 0,
    ) {}
}

// Combinaison avec readonly (PHP 8.1)
class Point {
    public function __construct(
        public readonly float $x,
        public readonly float $y,
    ) {}
}

$p = new Point(3.0, 4.0);
echo $p->x;  // 3.0
// $p->x = 5.0;  ← Fatal error : readonly
+
C'est la syntaxe recommandee en PHP 8+. La promotion de proprietes n'est pas seulement plus courte : elle elimine les bugs de copy-paste entre la declaration et l'assignation. Elle est utilisee par defaut dans Symfony (make:entity) et tous les frameworks modernes.

PHP 8.0

Fibers — coroutines

PHP 8.0

Les Fibers sont des coroutines legeres : des blocs de code qui peuvent etre suspendus et repris. Elles servent de base aux frameworks asynchrones PHP (ReactPHP, Revolt).

Fibers — coroutines PHPPHP
<?php
// Une Fiber = un bloc de code suspendable
$fiber = new Fiber(function(): void {
    echo 'Debut de la fiber' . PHP_EOL;

    // Suspendre la fiber et retourner une valeur a l'appelant
    $recu = Fiber::suspend('valeur depuis la fiber');
    echo 'Reprise avec : ' . $recu . PHP_EOL;

    echo 'Fin de la fiber' . PHP_EOL;
});

// Demarrer la fiber (s'execute jusqu'au premier suspend)
$suspend = $fiber->start();
echo 'Fiber suspendue avec : ' . $suspend . PHP_EOL;

// Reprendre la fiber en lui passant une valeur
$fiber->resume('bonjour depuis l''exterieur');

// Sortie :
// Debut de la fiber
// Fiber suspendue avec : valeur depuis la fiber
// Reprise avec : bonjour depuis l'exterieur
// Fin de la fiber
i
Les Fibers ne font pas de vrai parallélisme. PHP reste mono-thread. Les Fibers permettent la concurrence cooperative : une fiber se suspend volontairement pour laisser d'autres tourner. C'est le meme principe que async/await en JavaScript. Les frameworks comme ReactPHP utilisent les Fibers pour les I/O non-bloquants.

PHP 8.1

Enums

PHP 8.1

Les Enums remplacent les constantes "magic values". Ils definissent un ensemble fini de valeurs valides et sont des types a part entiere : un parametre typee Statut ne peut recevoir que les valeurs de l'enum.

Enums — valeurs finies et typeesPHP
<?php
// Enum pur (sans valeur scalaire)
enum Direction {
    case Nord;
    case Sud;
    case Est;
    case Ouest;
}

// Backed enum : valeur scalaire associee (string ou int)
enum Statut: string {
    case Actif    = 'active';
    case Inactif  = 'inactive';
    case Suspendu = 'suspended';

    // Methodes possibles dans les enums
    public function label(): string {
        return match($this) {
            Statut::Actif    => 'Actif',
            Statut::Inactif  => 'Inactif',
            Statut::Suspendu => 'Suspendu',
        };
    }
}

// Utilisation
$statut = Statut::Actif;
echo $statut->value;       // "active"
echo $statut->label();       // "Actif"
echo $statut->name;        // "Actif" (nom du case)

// Creer depuis la valeur scalaire
$s = Statut::from('active');     // ValueError si invalide
$s = Statut::tryFrom('actif');  // null si invalide (safe)

// Typage dans une fonction
function changerStatut(Statut $statut): void {
    // Impossible de passer "active" en string : doit etre Statut::Actif
}

// Lister toutes les valeurs
Statut::cases();  // [Statut::Actif, Statut::Inactif, Statut::Suspendu]
!
Enum vs constante de classe. Avant les enums, on utilisait const ACTIF = "active". Probleme : changerStatut("n'importe quoi") est accepte. Avec un enum, PHP refuse tout ce qui n'est pas Statut::Actif etc. Les bugs de valeur invalide sont detects a la compilation.

PHP 8.1 / 8.2

readonly properties et readonly class

PHP 8.1

Une propriete readonly ne peut etre assignee qu'une seule fois, lors de l'initialisation. Toute tentative de modification ulterieure genere une erreur fatale.

readonly properties et readonly classPHP
<?php
// Propriete readonly : assignable une seule fois
class User {
    public readonly string $nom;
    public readonly string $email;

    public function __construct(string $nom, string $email) {
        $this->nom   = $nom;    // OK : premiere assignation
        $this->email = $email;  // OK
    }
}

$u = new User('Alice', '[email protected]');
echo $u->nom;        // "Alice"
// $u->nom = "Bob";  ← Fatal error : Cannot modify readonly property

// Avec promotion de proprietes (PHP 8.0 + readonly PHP 8.1)
class Commande {
    public function __construct(
        public readonly int    $id,
        public readonly string $reference,
        public readonly float  $total,
    ) {}
}

// readonly class (PHP 8.2) : toutes les proprietes readonly
readonly class Point {
    public function __construct(
        public float $x,
        public float $y,
    ) {}
    // Cloner avec modification (pattern immuable)
    public function withX(float $x): static {
        return new static($x, $this->y);
    }
}
+
readonly pour les Value Objects et DTOs. Les objets de valeur (Money, Point, Email...) ne devraient jamais changer apres creation. readonly garantit cette immutabilite au niveau du langage, sans ecrire de setters qui lancent des exceptions.

PHP 8.1 / 8.3

Intersection types et PHP 8.3

PHP 8.1

Les intersection types permettent de contraindre un parametre a implementer plusieurs interfaces simultanement.

Intersection types, never, constantes typees, json_validatePHP
<?php
// Intersection types : doit implementer les DEUX
interface Serializable { public function serialize(): string; }
interface Countable    { public function count(): int; }

function traiter(Serializable&Countable $obj): void {
    echo $obj->count() . ' elements : ' . $obj->serialize();
}

// never return type (PHP 8.1)
function redirectEtExit(string $url): never {
    header('Location: ' . $url);
    exit;
}

// Constantes de classe typees (PHP 8.3)
class Config {
    const string VERSION   = '1.0.0';
    const int    MAX_RETRY = 3;
    const array  ROLES     = ['user', 'admin'];
}

// json_validate() (PHP 8.3) — valider sans decoder
if (json_validate($input)) {
    $data = json_decode($input, true);
}

// #[Override] (PHP 8.3) — signale une surcharge
class Enfant extends Parent {
    #[Override]
    public function methode(): void { ... }
    // Erreur si methode() n'existe pas dans le parent
}

PHP 8.2

readonly class et DNF types

PHP 8.2

PHP 8.2 a apporte les classes readonly, les types DNF et la depreciation de null et false comme types autonomes (il faut utiliser les union types).

readonly class — objets immuablesPHP
<?php
// readonly class : toutes les proprietes sont readonly
readonly class Adresse {
    public function __construct(
        public string $rue,
        public string $ville,
        public string $codePostal,
        public string $pays = 'France',
    ) {}
}

$a = new Adresse('12 rue de la Paix', 'Paris', '75001');
// Toutes les proprietes sont readonly : immuable par nature

// DNF types (Disjunctive Normal Form) PHP 8.2
// Combinaison d'intersection et d'union
function traiter((Serializable&Countable)|Iterator|null $obj): void { ... }

// Proprietes non typees dans readonly class : non autorisees
// Toutes les proprietes doivent avoir un type declare

// Cloner avec modifications (pattern immutabilite)
readonly class Money {
    public function __construct(
        public float  $montant,
        public string $devise,
    ) {}

    public function add(float $montant): static {
        return new static($this->montant + $montant, $this->devise);
    }
}

$prix  = new Money(10.00, 'EUR');
$total = $prix->add(5.00);  // nouveau Money(15.00, "EUR")
// $prix est inchange : readonly
!
Value Objects = readonly class. Un Value Object (Money, Email, Point...) represente une valeur, pas une entite. Il ne change jamais : toute "modification" cree un nouvel objet. readonly class garantit cette semantique au niveau du langage.

Synthese

PHP 8 moderne au quotidien

Voici comment toutes ces nouveautes se combinent dans du vrai code moderne.

Synthese — PHP 8.3 au quotidienPHP
<?php
// Code PHP 8.3 : toutes les nouveautes combinées

// Enum backed string
enum Statut: string {
    case Actif    = 'active';
    case Inactif  = 'inactive';

    public function label(): string => match($this) {
        self::Actif   => 'Actif',
        self::Inactif => 'Inactif',
    };
}

// readonly class avec constantes typees
readonly class Produit {
    const int STOCK_MIN = 0;

    public function __construct(
        public string $nom,
        public float  $prix,
        public int    $stock,
        public Statut $statut = Statut::Actif,
    ) {}

    public function estDisponible(): bool {
        return $this->stock > self::STOCK_MIN
            && $this->statut === Statut::Actif;
    }
}

// Factory avec named arguments
function creerProduit(array $data): Produit {
    return new Produit(
        nom:    $data['nom'],
        prix:   (float)$data['prix'],
        stock:  (int)($data['stock'] ?? 0),
        statut: Statut::tryFrom($data['statut'] ?? '') ?? Statut::Inactif,
    );
}

// Nullsafe + named args + match dans la vie reelle
$label = $user?->getProduit()?->statut->label() ?? 'Inconnu';
OK
PHP 8 en resume : match remplace switch, enum remplace les constantes, readonly garantit l'immutabilite, les named arguments rendent le code lisible, le nullsafe operator elimine les if-null-check. Toutes ces fonctionnalites rendent PHP aussi expressif que les langages modernes.
