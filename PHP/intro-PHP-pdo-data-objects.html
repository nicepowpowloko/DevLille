PDO — PHP
Data Objects

PDO est la couche d'abstraction officielle de PHP pour communiquer avec les bases de donnees. Elle protege contre les injections SQL, supporte MariaDB, MySQL, PostgreSQL, SQLite avec la meme API.

Pourquoi PDO

PDO vs mysqli — pourquoi choisir PDO

Il existe deux extensions PHP pour parler a MariaDB/MySQL : mysqli et PDO. PDO est recommande pour les nouveaux projets.

i
Les requetes preparees sont la raison principale d'utiliser PDO. Elles separent le SQL des donnees, rendant les injections SQL impossibles. C'est la protection fondamentale de toute application qui interroge une BDD.
01
Connexion

Se connecter avec PDO

Connexion PDO a MariaDBPHP
<?php
// Parametres de connexion
$host    = 'localhost';
$dbname  = 'boutique';
$user    = 'appuser';
$pass    = 'MotDePasse!';
$charset = 'utf8mb4';

// DSN : Data Source Name
$dsn = "mysql:host=$host;dbname=$dbname;charset=$charset";

// Options recommandees
$options = [
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
    // Lance une PDOException en cas d'erreur
    PDO::ATTR_DEFAULT_FETCH_MODE  => PDO::FETCH_ASSOC,
    // fetch() retourne un tableau associatif par defaut
    PDO::ATTR_EMULATE_PREPARES    => false,
    // Utiliser les vrais prepared statements du serveur
];

try {
    $pdo = new PDO($dsn, $user, $pass, $options);
    echo 'Connexion reussie !';
} catch (PDOException $e) {
    // En production : logger l'erreur, pas l'afficher
    die('Connexion impossible : ' . $e->getMessage());
}
!
Ne jamais afficher les erreurs de connexion en production. Le message d'exception contient des informations sensibles (nom de BDD, utilisateur). En production, logguer l'erreur dans un fichier et afficher un message generique a l'utilisateur.
!
Stocker la connexion dans un fichier config. Creer un fichier config/database.php qui instancie PDO une seule fois et le require_once dans chaque page qui en a besoin. Ne jamais versionner ce fichier dans Git (l'ajouter a .gitignore).
02
Securite fondamentale

Requetes preparees — protection contre les injections SQL

Une injection SQL survient quand une donnee utilisateur est inseree directement dans une requete SQL. Les requetes preparees separent le SQL des donnees : la structure de la requete est envoyee d'abord, les donnees ensuite. Le serveur ne peut pas les confondre.

Injection SQL — le probleme et la solutionSecurite
<?php
// DANGEREUX — concatenation directe
$email = $_POST['email'];
// Si email = "alice@ex.com' OR '1'='1"
$sql = "SELECT * FROM utilisateurs WHERE email = '" . $email . "'";
// Requete resultante : SELECT * FROM utilisateurs WHERE email = 'alice@ex.com' OR '1'='1'
// Retourne TOUS les utilisateurs ! L'attaquant est connecte.

// CORRECT — requete preparee avec placeholder
$stmt = $pdo->prepare("SELECT * FROM utilisateurs WHERE email = :email");
$stmt->execute(['email' => $email]);
// PDO traite $email comme une donnee pure, jamais comme du SQL
// Meme avec la valeur malveillante, l'injection est impossible
Deux styles de placeholdersPHP
<?php
// Style 1 : placeholders nommes (recommande, lisible)
$stmt = $pdo->prepare(
    "SELECT * FROM produits WHERE categorie_id = :cat AND prix < :max"
);
$stmt->execute(['cat' => 1, 'max' => 50]);

// Style 2 : placeholders positionnels ? (ordre important)
$stmt = $pdo->prepare(
    "SELECT * FROM produits WHERE categorie_id = ? AND prix < ?"
);
$stmt->execute([1, 50]);

// bindParam vs execute() — equivalent
$stmt = $pdo->prepare("SELECT * FROM utilisateurs WHERE id = :id");
$stmt->bindParam('id', $id, PDO::PARAM_INT);
$stmt->execute();
03
Read

SELECT — lire des donnees

fetch(), fetchAll() — recuperer les resultatsEssentiel
<?php
// Recuperer UNE seule ligne
$stmt = $pdo->prepare("SELECT * FROM utilisateurs WHERE id = :id");
$stmt->execute(['id' => 3]);
$user = $stmt->fetch();
// $user = ['id' => 3, 'nom' => 'Alice', ...] ou false si absent

if ($user) {
    echo $user['nom'];
}

// Recuperer TOUTES les lignes
$stmt = $pdo->prepare("SELECT * FROM produits WHERE stock > :min ORDER BY prix ASC");
$stmt->execute(['min' => 0]);
$produits = $stmt->fetchAll();
// $produits = tableau de tableaux associatifs

foreach ($produits as $p) {
    echo $p['nom'] . ' : ' . $p['prix'] . '€';
}

// Requete sans parametre : query() est plus court
$produits = $pdo->query("SELECT * FROM produits")->fetchAll();

// Compter les resultats
$stmt = $pdo->prepare("SELECT COUNT(*) FROM utilisateurs WHERE role = :role");
$stmt->execute(['role' => 'admin']);
$nb = $stmt->fetchColumn();  // retourne une valeur scalaire
echo $nb . ' admin(s)';
i
fetch() vs fetchAll(). fetch() recupere la ligne suivante (une a la fois) — utile pour les grands resultats ou quand on cherche un seul enregistrement. fetchAll() recupere toutes les lignes d'un coup en memoire — pratique pour les listes a afficher. fetchColumn() recupere la premiere colonne de la premiere ligne.
04
Create

INSERT — ajouter une ligne

INSERT avec PDO et recuperation de l'IDPHP
<?php
// Inserer un nouvel utilisateur
$stmt = $pdo->prepare(
    "INSERT INTO utilisateurs (nom, email, mot_de_passe)
     VALUES (:nom, :email, :mdp)"
);

$stmt->execute([
    'nom'   => 'Alice Dupont',
    'email' => 'alice@example.com',
    'mdp'   => password_hash('monMotDePasse', PASSWORD_DEFAULT),
    // Ne jamais stocker le mdp en clair !
]);

// Recuperer l'ID auto-incremente de la ligne inseree
$newId = (int) $pdo->lastInsertId();
echo 'Nouvel utilisateur cree avec l'ID : ' . $newId;

// Verifier le nombre de lignes affectees
echo $stmt->rowCount() . ' ligne(s) inseree(s)';

UPDATE avec PDOPHP

$stmt = $pdo->prepare(

     SET nom = :nom, email = :email

$succes = $stmt->execute([

);
$stmt->execute([
    'mdp' => password_hash('nouveauMdp!', PASSWORD_DEFAULT),
    'id'  => 3,
]);

DELETE — supprimer une ligne

DELETE avec PDOPHP
<?php
// Supprimer un utilisateur par ID
$stmt = $pdo->prepare("DELETE FROM utilisateurs WHERE id = :id");
$stmt->execute(['id' => 5]);

if ($stmt->rowCount() > 0) {
    echo 'Utilisateur supprime.';
} else {
    echo 'Utilisateur introuvable.';
}

// Soft delete recommande en production
$stmt = $pdo->prepare(
    "UPDATE utilisateurs SET actif = 0 WHERE id = :id"
);
$stmt->execute(['id' => 5]);
// L'utilisateur existe toujours mais est desactive
// On peut restaurer : UPDATE ... SET actif = 1

Gestion des erreurs PDO

Gestion propre des exceptions PDOPHP
<?php
// Avec ERRMODE_EXCEPTION (configure a la connexion),
// toute erreur SQL lance une PDOException

try {
    $stmt = $pdo->prepare(
        "INSERT INTO utilisateurs (email) VALUES (:email)"
    );
    $stmt->execute(['email' => 'alice@example.com']);
    echo 'Insertion reussie, id = ' . $pdo->lastInsertId();

} catch (PDOException $e) {
    // Code d'erreur SQL (ex: 23000 = contrainte unique violee)
    $code = $e->getCode();

    if ($code == '23000') {
        // Violation de contrainte UNIQUE (email deja pris)
        $erreur = 'Cet email est deja utilise.';
    } else {
        // En dev : afficher le detail
        $erreur = 'Erreur base de donnees : ' . $e->getMessage();
        // En prod : logger et afficher message generique
        // error_log($e->getMessage());
        // $erreur = 'Une erreur est survenue, veuillez reessayer.';
    }
}
08
Atomicite

Transactions — tout ou rien

Une transaction regroupe plusieurs requetes en une seule operation atomique. Si une requete echoue, toutes les precedentes sont annulees (rollback). Indispensable pour les operations qui doivent etre consistantes ensemble.

Transaction PDO — virement bancaireComplet
<?php
// Exemple : transfert de stock entre deux entrepots
try {
    $pdo->beginTransaction();
    // Debut de la transaction

    // Requete 1 : deduire du stock entrepot A
    $stmt1 = $pdo->prepare(
        "UPDATE stock SET quantite = quantite - :qte WHERE entrepot_id = 1 AND produit_id = :pid"
    );
    $stmt1->execute(['qte' => 10, 'pid' => 5]);

    // Requete 2 : ajouter au stock entrepot B
    $stmt2 = $pdo->prepare(
        "UPDATE stock SET quantite = quantite + :qte WHERE entrepot_id = 2 AND produit_id = :pid"
    );
    $stmt2->execute(['qte' => 10, 'pid' => 5]);

    // Tout s'est passe correctement : valider
    $pdo->commit();
    echo 'Transfert effectue.';

} catch (PDOException $e) {
    // Une requete a echoue : annuler tout
    $pdo->rollBack();
    echo 'Erreur, transfert annule : ' . $e->getMessage();
}
09
Bonne pratique

Classe Database — singleton de connexion

config/database.php — connexion centraliseeProduction
<?php
// config/database.php

function getDB(): PDO {
    static $pdo = null;
    // static : instancier une seule fois

    if ($pdo === null) {
        $dsn = "mysql:host=" . getenv('DB_HOST') .
               ";dbname="  . getenv('DB_NAME') .
               ";charset=utf8mb4";
        $pdo = new PDO(
            $dsn,
            getenv('DB_USER'),
            getenv('DB_PASS'),
            [
                PDO::ATTR_ERRMODE           => PDO::ERRMODE_EXCEPTION,
                PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
                PDO::ATTR_EMULATE_PREPARES   => false,
            ]
        );
    }
    return $pdo;
}

// Utilisation dans n'importe quel fichier :
// require_once 'config/database.php';
// $pdo = getDB();

OK
Les 5 etapes PDO a memoriser : (1) new PDO($dsn, $user, $pass) (2) prepare($sql) (3) execute([$params]) (4) fetch() ou fetchAll() (5) lastInsertId() apres INSERT. Toujours dans un try/catch.
