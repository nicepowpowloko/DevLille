Symfony
le framework

Symfony est le framework PHP professionnel le plus utilise en France. Il repose exactement sur les memes principes que notre MVC maison — router, controller, model, vues — mais avec des outils industriels : injection de dependances, ORM Doctrine, moteur de templates Twig.

Comparatif

MVC maison vs Symfony

Vous avez construit un MVC from scratch. Symfony fait exactement la meme chose, avec les memes concepts — mais en version industrielle, testee, maintenue, et extensible.

[ ] MVC maison (PHP 18)

Routing : tableau $routes[] dans index.php
Controller : class Ctrl extends Controller
Model : class Model + PDO maison
Vues : fichiers PHP + extract($data)
Autoloader : Composer PSR-4
Front controller : public/index.php

[S] Symfony

Routing : attribut #[Route('/')] sur le controller
Controller : class Ctrl extends AbstractController
Model : Doctrine ORM (Entity + Repository)
Vues : Twig (.html.twig) avec heritage de template
Autoloader : Composer PSR-4
Front controller : public/index.php (identique)
+
Votre MVC maison ET Symfony ont le meme public/index.php. Les deux creent un objet noyau, lui passent la requete HTTP, le noyau appelle le bon controller qui renvoie une reponse. Symfony industrialise ce que vous avez fait a la main. Comprendre le MVC maison, c'est comprendre Symfony.

Structure du projet

La structure Symfony est standardisee. Chaque dossier a un role precis. src/ contient votre code, templates/ les vues Twig, config/ la configuration.

Structure d'un projet SymfonyDossiers
mon-projet/
  bin/
    console                <-- commandes symfony (make:, doctrine:, etc.)
  config/
    packages/              <-- config doctrine, twig, security...
    routes.yaml            <-- routes globales (optionnel)
    services.yaml          <-- injection de dependances
  public/
    index.php              <-- front controller (identique a notre MVC maison !)
    assets/                <-- CSS, JS, images
  src/
    Controller/            <-- vos controllers
      ProduitController.php
    Entity/                <-- vos entites Doctrine (= les "Models")
      Produit.php
    Repository/            <-- vos repositories PDO auto-generes
      ProduitRepository.php
    Form/                  <-- formulaires Symfony
      ProduitType.php
  templates/
    base.html.twig         <-- layout principal (= notre layout.php)
    produit/
      index.html.twig      <-- liste des produits
      show.html.twig
      _form.html.twig      <-- partiel formulaire
  migrations/              <-- migrations BDD generees par Doctrine
  var/                     <-- cache et logs (ne pas versionner)
  vendor/                  <-- packages Composer
  .env

i
src/Entity/ = vos Models. En Symfony, les classes de la couche donnees s'appellent des Entities (entites). Doctrine les mappe sur les tables SQL. Un ProduitEntity correspond a la table produit. C'est notre Model, version Doctrine.

Etape 3

Routing avec #[Route]

Notre MVC maison declarait les routes dans index.php. Symfony utilise les attributs PHP 8 directement sur les methodes du controller. Plus besoin de fichier de routes separe — le controller documente lui-meme ses URLs.

Comparatif routing — MVC maison vs SymfonyPHP
<?php
// Notre MVC maison — routes declarees dans index.php
$router->get('/produits',        'ProduitController@index');
$router->get('/produits/{id}',  'ProduitController@show');

// Symfony — routes declarees directement sur le controller
// via les attributs PHP 8 #[Route(...)]
src/Controller/ProduitController.php — routing par attributsPHP
<?php
namespace App\Controller;

use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\Routing\Attribute\Route;

#[Route('/produits', name: 'produit_')]
class ProduitController extends AbstractController {

    // GET /produits
    #[Route('/', name: 'index', methods: ['GET'])]
    public function index(): Response { ... }

    // GET /produits/42
    #[Route('/{id}', name: 'show', methods: ['GET'])]
    public function show(int $id): Response { ... }

    // GET /produits/nouveau
    #[Route('/nouveau', name: 'new', methods: ['GET', 'POST'])]
    public function new(Request $request): Response { ... }

    // POST /produits/42/supprimer
    #[Route('/{id}/supprimer', name: 'delete', methods: ['POST'])]
    public function delete(int $id): Response { ... }
}

// Voir toutes les routes generees
php bin/console debug:router

// Generer une URL dans le controller
$this->generateUrl('produit_show', ['id' => $id]);
// Dans Twig : {{ path('produit_show', {id: produit.id}) }}
!
Le prefixe de classe + nom de route = nom complet. Le #[Route('/produits', name: 'produit_')] sur la classe prefixe toutes les routes du controller. La methode index avec name: 'index' genere la route nommee produit_index. debug:router liste tout.

Etape 4

Controller Symfony

AbstractController fournit render(), redirectToRoute(), addFlash() et d'autres methodes utilitaires. La grande nouveaute par rapport a notre MVC maison : l'injection de dependances. Symfony cree et injecte automatiquement les services demandes en constructeur.

src/Controller/ProduitController.phpPHP
<?php
namespace App\Controller;

use App\Entity\Produit;
use App\Repository\ProduitRepository;
use Doctrine\ORM\EntityManagerInterface;
use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\Routing\Attribute\Route;

#[Route('/produits', name: 'produit_')]
class ProduitController extends AbstractController {

    // Injection de dependances : Symfony fournit automatiquement
    // les services declares en parametre du constructeur
    public function __construct(
        private ProduitRepository      $produitRepo,
        private EntityManagerInterface  $em,
    ) {}

    #[Route('/', name: 'index', methods: ['GET'])]
    public function index(): Response {
        $produits = $this->produitRepo->findAll();
        // render() de AbstractController = notre render() maison
        return $this->render('produit/index.html.twig', [
            'produits' => $produits,
        ]);
    }

    #[Route('/{id}', name: 'show', methods: ['GET'])]
    public function show(Produit $produit): Response {
        // ParamConverter : Symfony recupere l'entite depuis l'id automatiquement
        return $this->render('produit/show.html.twig', [
            'produit' => $produit,
        ]);
    }

    #[Route('/{id}/supprimer', name: 'delete', methods: ['POST'])]
    public function delete(Produit $produit): Response {
        $this->em->remove($produit);
        $this->em->flush();
        return $this->redirectToRoute('produit_index');
    }
}
i
ParamConverter — magie de Symfony. Quand la signature est show(Produit $produit) et que la route a {id}, Symfony fait automatiquement SELECT * FROM produit WHERE id = $id et passe l'entite trouvee. S'il n'existe pas, il renvoie une 404. Plus besoin d'ecrire ce code dans le controller.

Etape 6

Doctrine — Entity

Une Entity Doctrine est une classe PHP annotee qui se mappe sur une table SQL. Les annotations #[ORM\Column] decrivent les colonnes. Doctrine genere et execute le SQL a votre place.

src/Entity/Produit.php — entite DoctrinePHP
<?php
namespace App\Entity;

use App\Repository\ProduitRepository;
use Doctrine\ORM\Mapping as ORM;

#[ORM\Entity(repositoryClass: ProduitRepository::class)]
class Produit {

    #[ORM\Id]
    #[ORM\GeneratedValue]
    #[ORM\Column]
    private ?int $id = null;

    #[ORM\Column(length: 200)]
    private string $nom = '';

    #[ORM\Column(type: 'decimal', precision: 10, scale: 2)]
    private string $prix = '0.00';

    #[ORM\Column(type: 'integer')]
    private int $stock = 0;

    #[ORM\Column(nullable: true)]
    private ?string $description = null;

    // Getters et setters (generes par make:entity)
    public function getId(): ?int      { return $this->id; }
    public function getNom(): string    { return $this->nom; }
    public function setNom(string $n): static  { $this->nom = $n; return $this; }
    public function getPrix(): string   { return $this->prix; }
    public function setPrix(string $p): static  { $this->prix = $p; return $this; }
    public function getStock(): int     { return $this->stock; }
    public function setStock(int $s): static  { $this->stock = $s; return $this; }
}
Workflow Entity — make:entity + migrationsTerminal
# Generer l'entite avec la console (recommande)
php bin/console make:entity Produit
# La console pose les questions : nom du champ, type, nullable...
# Genere automatiquement src/Entity/Produit.php

# Generer la migration SQL
php bin/console make:migration
# Cree migrations/Version20241215XXXXXX.php avec le SQL

# Executer la migration (cree la table en BDD)
php bin/console doctrine:migrations:migrate

# Voir l'etat des migrations
php bin/console doctrine:migrations:status
i
Doctrine gere le schema BDD automatiquement. Plus besoin d'ecrire le CREATE TABLE a la main. Vous definissez l'Entity PHP, Doctrine genere le SQL. Quand vous ajoutez une propriete, vous generez une nouvelle migration qui fait l'ALTER TABLE. Le schema suit le code.

Doctrine — Repository et persist

Le Repository Doctrine etend ServiceEntityRepository et herite automatiquement de findAll(), find(), findBy(). Pour les requetes complexes on utilise le QueryBuilder — une API fluide qui genere le DQL.

src/Repository/ProduitRepository.phpPHP
<?php
namespace App\Repository;

use App\Entity\Produit;
use Doctrine\Bundle\DoctrineBundle\Repository\ServiceEntityRepository;
use Doctrine\Persistence\ManagerRegistry;

class ProduitRepository extends ServiceEntityRepository {

    public function __construct(ManagerRegistry $registry) {
        parent::__construct($registry, Produit::class);
    }

    // Methodes heritees automatiquement :
    // findAll(), find($id), findBy([]), findOneBy([]), count([])

    // Methode personnalisee : requete DQL (Doctrine Query Language)
    public function findActifsOrderedByNom(): array {
        return $this->createQueryBuilder('p')
            ->andWhere('p.actif = :actif')
            ->setParameter('actif', true)
            ->orderBy('p.nom', 'ASC')
            ->getQuery()
            ->getResult();
    }

    // Recherche LIKE
    public function search(string $terme): array {
        return $this->createQueryBuilder('p')
            ->andWhere('p.nom LIKE :terme')
            ->setParameter('terme', '%' . $terme . '%')
            ->getQuery()->getResult();
    }

    // Utilisation dans le Controller :
    // $produits = $this->produitRepo->findAll();
    // $produit  = $this->produitRepo->find($id);
    // $produits = $this->produitRepo->findBy(['actif' => true]);
    // $produits = $this->produitRepo->search('t-shirt');
}
!
Persister et supprimer avec EntityManager. Pour creer/modifier/supprimer, on utilise $em->persist($produit) + $em->flush(). persist met l'entite dans la "file d'attente" Doctrine, flush execute le SQL. Sans flush(), rien n'est sauvegarde en BDD.

CRUD complet Symfony

Le workflow CRUD Symfony est tres similaire a notre MVC maison, avec deux differences majeures : le systeme de formulaires gere la validation et la liaison avec l'entite, et addFlash() stocke un message en session pour l'afficher apres la redirection.

Controller new + edit — formulaires SymfonyPHP
<?php
// Controller complet new + edit genere par make:crud

    #[Route('/nouveau', name: 'new', methods: ['GET', 'POST'])]
    public function new(Request $request): Response {
        $produit = new Produit();
        $form = $this->createForm(ProduitType::class, $produit);
        $form->handleRequest($request);

        if ($form->isSubmitted() && $form->isValid()) {
            // Doctrine enregistre l'entite en BDD
            $this->em->persist($produit);
            $this->em->flush();

            // Message flash affiché dans la vue suivante
            $this->addFlash('success', 'Produit cree avec succes !');

            return $this->redirectToRoute('produit_index');
        }

        return $this->render('produit/new.html.twig', [
            'form' => $form,
        ]);
    }

    #[Route('/{id}/modifier', name: 'edit', methods: ['GET', 'POST'])]
    public function edit(Request $request, Produit $produit): Response {
        $form = $this->createForm(ProduitType::class, $produit);
        $form->handleRequest($request);

        if ($form->isSubmitted() && $form->isValid()) {
            $this->em->flush();  // pas de persist car deja suivi
            $this->addFlash('success', 'Produit modifie !');
            return $this->redirectToRoute('produit_show', ['id' => $produit->getId()]);
        }

        return $this->render('produit/edit.html.twig', [
            'produit' => $produit,
            'form'    => $form,
        ]);
    }
