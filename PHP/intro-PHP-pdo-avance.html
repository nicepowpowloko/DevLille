Rappel

PDO — connexion et bases

PDO (PHP Data Objects) est l'abstraction BDD de PHP. On rappelle les bases avant d'aller plus loin.

Rappel — connexion et requetes preparees de basePHP
<?php
// Connexion avec options recommandees
$pdo = new PDO(
    'mysql:host=localhost;port=3306;dbname=boutique;charset=utf8mb4',
    'root', '',
    [
        PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
        PDO::ATTR_DEFAULT_FETCH_MODE  => PDO::FETCH_ASSOC,
        PDO::ATTR_EMULATE_PREPARES   => false,
    ]
);

// Requete simple (sans parametre)
$rows = $pdo->query('SELECT * FROM produits')->fetchAll();

// Requete preparee (avec parametre) — TOUJOURS pour les valeurs externes
$stmt = $pdo->prepare('SELECT * FROM produits WHERE id = :id AND actif = :actif');
$stmt->execute(['id' => 42, 'actif' => 1]);
$produit = $stmt->fetch();

// Modes de fetch
$stmt->fetch(PDO::FETCH_ASSOC);    // tableau associatif (defaut)
$stmt->fetch(PDO::FETCH_OBJ);       // objet stdClass
$stmt->fetchAll(PDO::FETCH_ASSOC); // toutes les lignes
$stmt->fetchColumn();                // une seule valeur (ex: COUNT)
!
Jamais de concatenation avec des valeurs externes. "SELECT * FROM produits WHERE id = " . $_GET["id"] est une injection SQL. Toujours utiliser des requetes preparees avec :parametre ou ? pour toute valeur venant de l'utilisateur ou de la BDD.

Etape 1

Requetes preparees avancees

Les requetes preparees acceptent plusieurs syntaxes de parametre et peuvent etre executees plusieurs fois avec des valeurs differentes, ce qui est tres efficace pour les INSERT en lot.

Parametres nommes vs positionnels — bindValue et bindParamPHP
<?php
// Parametres nommes (recommande : plus lisible)
$stmt = $pdo->prepare(
    'INSERT INTO produits (nom, prix, stock) VALUES (:nom, :prix, :stock)'
);
$stmt->execute(['nom' => 'T-shirt', 'prix' => 19.99, 'stock' => 50]);

// Parametres positionnels (?) — ordre important
$stmt = $pdo->prepare('INSERT INTO produits (nom, prix) VALUES (?, ?)');
$stmt->execute(['Jean', 49.99]);

// bindValue : lie une valeur avec son type explicite
$stmt = $pdo->prepare('SELECT * FROM produits WHERE prix < :max AND stock > :min');
$stmt->bindValue(':max',  50.00, PDO::PARAM_STR);  // PARAM_STR pour les decimaux
$stmt->bindValue(':min',  0,     PDO::PARAM_INT);
$stmt->execute();

// Reutiliser une requete preparee en boucle — tres efficace
$stmt = $pdo->prepare('INSERT INTO produits (nom, prix) VALUES (:nom, :prix)');
$produits = [
    ['nom' => 'Veste',   'prix' => 89.90],
    ['nom' => 'Ceinture', 'prix' => 25.00],
    ['nom' => 'Casquette', 'prix' => 15.00],
];
foreach ($produits as $p) {
    $stmt->execute($p);  // prepare une fois, execute N fois
}
echo $pdo->lastInsertId();  // id du dernier INSERT
!
PARAM_STR pour les DECIMAL/FLOAT. MySQL attend les nombres decimaux sous forme de chaine dans PDO. Utiliser PDO::PARAM_STR (ou laisser PDO deduire) pour les prix. PARAM_INT pour les entiers, PARAM_BOOL pour les booleens.

Etape 2

JOIN — requetes multi-tables

Les jointures SQL permettent de ramener en une seule requete des donnees issues de plusieurs tables liees. PDO recupere le tout sous forme de tableau associatif plat.

JOIN — recuperer produits avec categorie et statsSQL + PHP
-- INNER JOIN : seulement les produits avec categorie
SELECT
    p.id, p.nom, p.prix, p.stock,
    c.nom AS categorie,
    c.slug AS categorie_slug
FROM produits p
INNER JOIN categories c ON p.categorie_id = c.id
WHERE p.actif = 1
ORDER BY c.nom, p.nom;

-- LEFT JOIN : tous les produits, meme sans categorie
SELECT p.*, c.nom AS categorie
FROM produits p
LEFT JOIN categories c ON p.categorie_id = c.id;

-- Agregats : nombre de produits par categorie
SELECT
    c.nom AS categorie,
    COUNT(p.id)   AS nb_produits,
    AVG(p.prix)   AS prix_moyen,
    SUM(p.stock)  AS stock_total
FROM categories c
LEFT JOIN produits p ON p.categorie_id = c.id
GROUP BY c.id, c.nom
HAVING nb_produits > 0
ORDER BY nb_produits DESC;
Executer un JOIN avec PDO — resultat platPHP
<?php
$sql = '
    SELECT p.id, p.nom, p.prix, p.stock,
           c.nom AS categorie, c.slug
    FROM produits p
    LEFT JOIN categories c ON p.categorie_id = c.id
    WHERE p.actif = :actif
    ORDER BY p.nom
';

$stmt = $pdo->prepare($sql);
$stmt->execute(['actif' => 1]);
$produits = $stmt->fetchAll();

// Chaque element contient les colonnes des deux tables
foreach ($produits as $p) {
    echo $p['nom'] . ' — ' . $p['categorie'];
    // $p['categorie'] vient du JOIN grace a l'alias AS
}

Etape 3

Recherche et filtres dynamiques

La difficulte des filtres dynamiques est que le nombre et la nature des conditions SQL varient selon les parametres recus. On construit la requete par concatenation controllee — en gardant les valeurs dans un tableau de parametres.

Recherche avec filtres dynamiques — methode proprePHP
<?php
function rechercherProduits(
    PDO     $pdo,
    string  $terme       = '',
    ?int    $categorieId = null,
    ?float  $prixMax     = null,
    bool    $enStockSeul = false
): array {

    $conditions = ['p.actif = 1'];
    $params     = [];

    // Ajouter les conditions dynamiquement
    if (!empty($terme)) {
        $conditions[] = 'p.nom LIKE :terme';
        $params['terme'] = '%' . $terme . '%';
    }
    if ($categorieId !== null) {
        $conditions[] = 'p.categorie_id = :cat';
        $params['cat'] = $categorieId;
    }
    if ($prixMax !== null) {
        $conditions[] = 'p.prix <= :pmax';
        $params['pmax'] = $prixMax;
    }
    if ($enStockSeul) {
        $conditions[] = 'p.stock > 0';
    }

    $where = implode(' AND ', $conditions);
    $sql   = 'SELECT p.*, c.nom AS categorie'
           . ' FROM produits p'
           . ' LEFT JOIN categories c ON p.categorie_id = c.id'
           . ' WHERE ' . $where
           . ' ORDER BY p.nom';

    $stmt = $pdo->prepare($sql);
    $stmt->execute($params);
    return $stmt->fetchAll();
}

// Appel depuis un formulaire GET
$resultats = rechercherProduits(
    pdo:         $pdo,
    terme:       $_GET['q']   ?? '',
    categorieId: $_GET['cat'] ? (int)$_GET['cat'] : null,
    prixMax:     $_GET['max'] ? (float)$_GET['max'] : null,
    enStockSeul: isset($_GET['stock']),
);
!
Ne jamais concatener directement $_GET dans le SQL. Le LIKE utilise :terme comme parametre, et les % sont ajoutes en PHP avant de les mettre dans $params. Les conditions SQL elles-memes (noms de colonnes, mots-cles SQL) peuvent etre concatenees car elles sont ecrites par le developpeur, pas par l'utilisateur.

Etape 4

Pagination

La pagination limite le nombre de lignes retournees et permet de naviguer par pages. Elle utilise LIMIT et OFFSET en SQL, avec un COUNT pour connaitre le nombre total de pages.

Pagination — LIMIT / OFFSET et calcul de pagesPHP
<?php
function paginer(PDO $pdo, int $page = 1, int $parPage = 10): array {

    // Securiser les valeurs
    $page   = max(1, (int)$page);
    $parPage = max(1, min(100, (int)$parPage));

    // 1. Compter le total (sans LIMIT)
    $total = (int)$pdo->query(
        'SELECT COUNT(*) FROM produits WHERE actif = 1'
    )->fetchColumn();

    // 2. Calculer le nombre de pages
    $nbPages = (int)ceil($total / $parPage);
    $page    = min($page, $nbPages);  // eviter de depasser

    // 3. OFFSET = (page - 1) * parPage
    $offset = ($page - 1) * $parPage;

    // 4. Requete avec LIMIT et OFFSET
    // IMPORTANT : LIMIT et OFFSET ne peuvent pas etre des parametres PDO
    // On les caste en int (securise) et on les concatene
    $sql = 'SELECT p.*, c.nom AS categorie'
         . ' FROM produits p'
         . ' LEFT JOIN categories c ON p.categorie_id = c.id'
         . ' WHERE p.actif = 1 ORDER BY p.nom'
         . ' LIMIT '  . $parPage
         . ' OFFSET ' . $offset;

    $produits = $pdo->query($sql)->fetchAll();

    return [
        'produits'  => $produits,
        'total'     => $total,
        'page'      => $page,
        'nbPages'   => $nbPages,
        'parPage'   => $parPage,
        'suivante'  => $page < $nbPages ? $page + 1 : null,
        'precedente' => $page > 1    ? $page - 1 : null,
    ];
}

// Utilisation
$data = paginer($pdo, page: (int)($_GET['page'] ?? 1), parPage: 10);
// $data['produits'] : tableau de la page courante
// $data['nbPages']  : nombre total de pages
// $data['suivante'] : numero page suivante ou null
i
LIMIT/OFFSET ne sont pas parametrables avec PDO. MySQL n'accepte pas :limit comme parametre pour LIMIT et OFFSET. On les caste en (int) avant de les concatener — le cast garantit qu'il s'agit d'entiers et empeche les injections.

Etape 5

Transactions

Une transaction groupe plusieurs operations SQL en une seule unite atomique. Soit toutes reussissent (COMMIT), soit toutes sont annulees (ROLLBACK). Indispensable pour les operations critiques : transfert d'argent, commande e-commerce, etc.

Transactions PDO — beginTransaction / commit / rollBackPHP
<?php
/**
 * Creer une commande : decremente le stock et insere la commande.
 * Les deux operations doivent reussir ou echouer ensemble.
 */
function passerCommande(PDO $pdo, int $userId, int $produitId, int $qte): int {

    try {
        $pdo->beginTransaction();

        // 1. Verifier et decremente le stock (avec verrouillage FOR UPDATE)
        $stmt = $pdo->prepare('SELECT stock FROM produits WHERE id = :id FOR UPDATE');
        $stmt->execute(['id' => $produitId]);
        $stock = (int)$stmt->fetchColumn();

        if ($stock < $qte) {
            throw new RuntimeException('Stock insuffisant (' . $stock . ' dispo)');
        }

        // 2. Decrementer le stock
        $pdo->prepare('UPDATE produits SET stock = stock - :qte WHERE id = :id')
            ->execute(['qte' => $qte, 'id' => $produitId]);

        // 3. Creer la commande
        $pdo->prepare('INSERT INTO commandes (user_id, produit_id, quantite, total)'
            . ' SELECT :uid, :pid, :qte, prix * :qte FROM produits WHERE id = :pid2')
            ->execute(['uid' => $userId, 'pid' => $produitId, 'qte' => $qte, 'pid2' => $produitId]);

        $commandeId = (int)$pdo->lastInsertId();

        // Tout a reussi : valider
        $pdo->commit();
        return $commandeId;

    } catch (Exception $e) {
        // Une erreur : annuler tout
        $pdo->rollBack();
        throw $e;  // relancer pour gestion en amont
    }
}
+
FOR UPDATE verrouille la ligne. Dans une transaction, SELECT ... FOR UPDATE pose un verrou sur la ligne lue. Si deux commandes arrivent en meme temps pour le dernier article en stock, la seconde attendra que la premiere committe ou rollbacke avant de lire le stock. Indispensable pour eviter la survente.

Etape 6

Pattern Repository

Le patron Repository isole tout le code d'acces aux donnees derriere une interface. Le reste de l'application ne sait pas si les donnees viennent de MySQL, d'un fichier JSON, d'une API ou d'un cache. C'est la separation des preoccupations appliquee a la persistance.

Interface et implementation RepositoryPHP
<?php
namespace App\Repositories;

// Contrat : ce que toute source de donnees doit savoir faire
interface ProduitRepositoryInterface {
    public function findAll(): array;
    public function findById(int $id): ?array;
    public function findByCategorie(int $categorieId): array;
    public function search(string $terme, array $filtres = []): array;
    public function create(array $data): int;
    public function update(int $id, array $data): bool;
    public function delete(int $id): bool;
    public function paginate(int $page, int $perPage): array;
}

// Implementation MySQL avec PDO
class ProduitRepository implements ProduitRepositoryInterface {

    public function __construct(private PDO $pdo) {}

    public function findAll(): array {
        return $this->pdo->query(
            'SELECT p.*, c.nom AS categorie FROM produits p'
            . ' LEFT JOIN categories c ON p.categorie_id = c.id'
            . ' WHERE p.actif = 1 ORDER BY p.nom'
        )->fetchAll();
    }

    public function findById(int $id): ?array {
        $stmt = $this->pdo->prepare('SELECT * FROM produits WHERE id = ?');
        $stmt->execute([$id]);
        return $stmt->fetch() ?: null;
    }

    // findByCategorie, search, create, update, delete, paginate...
    // Chaque methode = une seule responsabilite SQL
}

// Utilisation dans le Controller
$repo = new ProduitRepository($pdo);
$produits = $repo->findAll();
$produit  = $repo->findById(42);
$resultats = $repo->search('t-shirt', ['prix_max' => 30]);
i
Le Controller ne connait pas PDO. Il ne manipule que le Repository via son interface. Si demain on veut stocker les produits dans une API REST ou un fichier JSON, on cree une nouvelle implementation de ProduitRepositoryInterface sans toucher au Controller. C'est le principe d'inversion de dependance.

Etape 7

Singleton de connexion

Creer une nouvelle instance PDO a chaque instantiation de Repository est couteux. Le patron Singleton garantit qu'une seule connexion est creee par requete HTTP et reutilisee partout.

Database — Singleton de connexion PDOPHP
<?php
namespace Core;

use \PDO;

class Database {

    private static ?PDO $instance = null;

    // Empecher l'instanciation directe
    private function __construct() {}

    public static function getConnection(): PDO {
        if (self::$instance === null) {
            $dsn = 'mysql:host='   . getenv('DB_HOST')
                 . ';port='    . getenv('DB_PORT')
                 . ';dbname='  . getenv('DB_NAME')
                 . ';charset=utf8mb4';

            self::$instance = new PDO($dsn,
                getenv('DB_USER'),
                getenv('DB_PASS'),
                [
                    PDO::ATTR_ERRMODE           => PDO::ERRMODE_EXCEPTION,
                    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
                    PDO::ATTR_EMULATE_PREPARES  => false,
                ]
            );
        }
        return self::$instance;
    }
}

// Utilisation depuis les repositories
$pdo  = Database::getConnection();
$repo = new ProduitRepository($pdo);

// Appel multiple : toujours la meme instance PDO
$pdo2 = Database::getConnection();  // retourne $instance existante
var_dump($pdo === $pdo2);  // true : meme objet
!
Une seule connexion par requete HTTP. PHP est sans etat entre les requetes. Dans une meme requete, le Singleton garantit que tous les repositories partagent la meme connexion PDO, evitant l'overhead d'ouvrir plusieurs connexions MySQL en parallele.

Etape 8

Gestion des erreurs PDO

Avec ERRMODE_EXCEPTION, PDO lance une PDOException en cas d'erreur SQL. Il faut la capturer au bon niveau et distinguer les erreurs attendues (doublons, contraintes) des erreurs techniques.

Gerer les erreurs PDO — contraintes et erreurs techniquesPHP
<?php
try {
    $stmt = $pdo->prepare(
        'INSERT INTO utilisateurs (email, nom, mot_de_passe) VALUES (?, ?, ?)'
    );
    $stmt->execute(['alice@ex.com', 'Alice', password_hash('secret', PASSWORD_BCRYPT)]);

} catch (PDOException $e) {

    // SQLSTATE[23000] : violation de contrainte (doublon UNIQUE)
    if ($e->getCode() === '23000') {
        throw new RuntimeException('Cet email est deja utilise', 409, $e);
    }

    // Autre erreur technique : logguer et relancer
    error_log('PDO Error: ' . $e->getMessage());
    throw new RuntimeException('Erreur base de donnees', 500, $e);
}

// Codes SQLSTATE utiles
// 23000 : contrainte d'integrite (UNIQUE, FK)
// 42S02 : table inexistante
// HY000 : erreur generale
// 08006 : echec de connexion

// Afficher des infos debug en dev
if (getenv('APP_ENV') === 'development') {
    echo 'SQLSTATE: ' . $e->getCode() . '<br>';
    echo 'Message: '  . $e->getMessage();
}
!
Ne jamais afficher les erreurs PDO brutes en production. Le message d'erreur peut contenir le nom de la base, la structure des tables, et des infos sensibles. En production : logguer dans un fichier, afficher un message generique. En dev : afficher le SQLSTATE et le message.

Synthese

Repository complet

Voici un ProduitRepository complet integrant la pagination, la recherche, les transactions et la gestion des erreurs. C'est le pattern que vous utiliserez dans vos projets.

ProduitRepository.php — implementation completePHP
<?php
namespace App\Repositories;

use \PDO;
use \PDOException;
use \RuntimeException;

class ProduitRepository implements ProduitRepositoryInterface {

    public function __construct(private PDO $pdo) {}

    public function findAll(): array {
        return $this->pdo->query('SELECT p.*, c.nom AS categorie'
            . ' FROM produits p LEFT JOIN categories c ON p.categorie_id = c.id'
            . ' WHERE p.actif = 1 ORDER BY p.nom'
        )->fetchAll();
    }

    public function findById(int $id): ?array {
        $s = $this->pdo->prepare('SELECT * FROM produits WHERE id = ? AND actif = 1');
        $s->execute([$id]); return $s->fetch() ?: null;
    }

    public function search(string $terme, array $filtres = []): array {
        $conditions = ['p.actif = 1']; $params = [];
        if ($terme) { $conditions[] = 'p.nom LIKE :t'; $params['t'] = '%'.$terme.'%'; }
        if (isset($filtres['prix_max'])) { $conditions[] = 'p.prix <= :pm'; $params['pm'] = $filtres['prix_max']; }
        $s = $this->pdo->prepare('SELECT p.*, c.nom AS categorie FROM produits p'
            . ' LEFT JOIN categories c ON p.categorie_id = c.id'
            . ' WHERE ' . implode(' AND ', $conditions) . ' ORDER BY p.nom');
        $s->execute($params); return $s->fetchAll();
    }

    public function paginate(int $page, int $perPage = 10): array {
        $page    = max(1, $page);
        $total   = (int)$this->pdo->query('SELECT COUNT(*) FROM produits WHERE actif=1')->fetchColumn();
        $nbPages = (int)ceil($total / $perPage);
        $offset  = (min($page,$nbPages) - 1) * $perPage;
        $rows    = $this->pdo->query('SELECT * FROM produits WHERE actif=1 ORDER BY nom'
            . ' LIMIT ' . (int)$perPage . ' OFFSET ' . (int)$offset)->fetchAll();
        return ['data'=>$rows,'total'=>$total,'pages'=>$nbPages,'page'=>$page];
    }

    public function create(array $data): int {
        try {
            $s = $this->pdo->prepare('INSERT INTO produits (nom,prix,stock,categorie_id) VALUES (:nom,:prix,:stock,:cat)');
            $s->execute($data);
            return (int)$this->pdo->lastInsertId();
        } catch (PDOException $e) {
            error_log($e->getMessage());
            throw new RuntimeException('Erreur creation produit', 0, $e);
        }
    }

    public function update(int $id, array $data): bool {
        $data['id'] = $id;
        return $this->pdo->prepare('UPDATE produits SET nom=:nom,prix=:prix,stock=:stock WHERE id=:id')->execute($data);
    }

    public function delete(int $id): bool {
        return $this->pdo->prepare('DELETE FROM produits WHERE id = ?')->execute([$id]);
    }
    public function findByCategorie(int $id): array {
        $s = $this->pdo->prepare('SELECT * FROM produits WHERE categorie_id = ? AND actif = 1');
        $s->execute([$id]); return $s->fetchAll();
    }
}
OK
Pattern complet : Database Singleton fournit le PDO, ProduitRepository l'encapsule, le Controller ne fait que $repo->findAll(). Chaque couche a une seule responsabilite. Pour changer de BDD, seul le Repository change.
