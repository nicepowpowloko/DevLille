Heritage
et interfaces

L'heritage permet a une classe d'heriter des proprietes et methodes d'une autre. Les interfaces definissent des contrats que les classes doivent respecter. Les traits permettent de reutiliser du code sans heritage.

extends abstract interface implements trait
00
Concept

Heritage — la relation "est-un"

L'heritage modele la relation "est-un" : un Chien est un Animal, un AdminUser est un User. La classe enfant herite de tout le code du parent et peut l'etendre ou le modifier.

Animal ← classe parente (base) nom, age manger(), dormir() | |--- Chien ← herite de Animal + ajoute | race | aboyer() | |--- Chat ← herite de Animal + ajoute ronronner()
MecanismeRoleMot-cle PHP
HeritageReutiliser et etendre le code d'une classe parenteextends
Classe abstraiteClasse non instanciable, force l'implementation dans les enfantsabstract
InterfaceContrat : liste de methodes que la classe DOIT implementerinterface / implements
TraitMorceau de code reutilisable sans heritage (mix-in)trait / use
01
Etape 1

extends — heriter d'une classe

Heritage simple — extendsPHP
<?php
// Classe parente
class User {
    public function __construct(
        protected string $nom,
        protected string $email,
    ) {}

    public function sePresenter(): string {
        return "Je suis " . $this->nom;
    }

    public function getEmail(): string { return $this->email; }
}

// Classe enfant : herite de User
class AdminUser extends User {
    // Ajoute une nouvelle propriete
    private array $permissions = [];

    // Ajoute une nouvelle methode
    public function ajouterPermission(string $perm): void {
        $this->permissions[] = $perm;
    }

    public function peutFaire(string $action): bool {
        return in_array($action, $this->permissions);
    }
}

$admin = new AdminUser("Alice", "alice@ex.com");
echo $admin->sePresenter();  // heritee de User : "Je suis Alice"
echo $admin->getEmail();     // heritee de User
$admin->ajouterPermission("supprimer_user");

// instanceof verifie aussi l'heritage
var_dump($admin instanceof AdminUser);  // true
var_dump($admin instanceof User);       // true aussi !
!
PHP n'autorise qu'un seul heritage. Une classe ne peut etendre qu'une seule classe parente (class A extends B). Pour heriter de plusieurs sources, on utilise les interfaces et les traits.

Etape 2

parent:: et surcharge de methodes

parent:: — appeler la methode parentePHP
<?php
class Produit {
    public function __construct(
        protected string $nom,
        protected float  $prix,
    ) {}

    public function calculerTTC(): float {
        return round($this->prix * 1.20, 2);
    }

    public function describe(): string {
        return $this->nom . " - " . $this->prix . " EUR";
    }
}

class ProduitAlimentaire extends Produit {

    public function __construct(
        string $nom,
        float  $prix,
        private string $dateLimite,
    ) {
        // Appeler le constructeur parent AVANT tout
        parent::__construct($nom, $prix);
    }

    // Surcharge (override) : redefinir une methode parente
    public function calculerTTC(): float {
        // Alimentaire : TVA 5.5% au lieu de 20%
        return round($this->prix * 1.055, 2);
    }

    // Etendre la methode parente
    public function describe(): string {
        // Appeler la version parente puis ajouter
        return parent::describe() . " | DLC: " . $this->dateLimite;
    }
}

$p  = new Produit("T-shirt", 20);
$pa = new ProduitAlimentaire("Yaourt", 1.50, "2025-06-01");

echo $p->calculerTTC();     // 24.00 (TVA 20%)
echo $pa->calculerTTC();    // 1.58 (TVA 5.5%)
echo $pa->describe();       // "Yaourt - 1.5 EUR | DLC: 2025-06-01"
!
Toujours appeler parent::__construct() dans le constructeur enfant. Si le parent initialise des proprietes dans son constructeur, l'enfant doit le rappeler pour que ces proprietes soient correctement initialisees. En general, on l'appelle en premiere ligne.

Etape 3

Classes abstraites — modeles non instanciables

Une classe abstraite est un modele incomplet qui ne peut pas etre instancie directement. Elle peut definir des methodes avec implementation (heritees) et des methodes abstraites (sans implementation, que les enfants doivent implementer).

abstract — classe de base incompletePHP
<?php
abstract class Shape {

    // Methode abstraite : DOIT etre implementee par les enfants
    abstract public function aire(): float;
    abstract public function perimetre(): float;

    // Methode concrete : disponible telle quelle dans les enfants
    public function describe(): string {
        return get_class($this) .
               " | aire: " . round($this->aire(), 2) .
               " | perimetre: " . round($this->perimetre(), 2);
    }
}

class Cercle extends Shape {
    public function __construct(private float $rayon) {}

    public function aire(): float      { return M_PI * $this->rayon ** 2; }
    public function perimetre(): float { return 2 * M_PI * $this->rayon; }
}

class Rectangle extends Shape {
    public function __construct(private float $l, private float $h) {}

    public function aire(): float      { return $this->l * $this->h; }
    public function perimetre(): float { return 2 * ($this->l + $this->h); }
}

// new Shape() ← ERREUR : classe abstraite
$c = new Cercle(5);
$r = new Rectangle(4, 3);

echo $c->describe();  // Cercle | aire: 78.54 | perimetre: 31.42
echo $r->describe();  // Rectangle | aire: 12 | perimetre: 14

// Polymorphisme : meme code, comportements differents
$shapes = [new Cercle(3), new Rectangle(5, 2)];
foreach ($shapes as $s) {
    echo $s->aire() . "<br>";  // appel identique, resultat different
}

Etape 4

Interfaces — des contrats a respecter

Une interface definit ce qu'une classe doit pouvoir faire, sans dire comment. Elle ne contient que des signatures de methodes (et des constantes). Une classe qui implements une interface s'engage a implementer toutes ses methodes.

interface — contrat et implementsPHP
<?php
// Definition d'une interface
interface Exportable {
    public function toArray(): array;
    public function toJson(): string;
    public function toCsv(): string;
}

interface Validable {
    public function validate(): bool;
    public function getErrors(): array;
}

// Une classe peut implementer plusieurs interfaces
class Produit implements Exportable, Validable {

    public function __construct(
        private string $nom,
        private float  $prix,
    ) {}

    // Implementation de Exportable
    public function toArray(): array {
        return ["nom" => $this->nom, "prix" => $this->prix];
    }
    public function toJson(): string {
        return json_encode($this->toArray());
    }
    public function toCsv(): string {
        return $this->nom . ";" . $this->prix;
    }

    // Implementation de Validable
    public function validate(): bool {
        return !empty($this->nom) && $this->prix > 0;
    }
    public function getErrors(): array {
        $errors = [];
        if (empty($this->nom))    $errors[] = "Nom requis";
        if ($this->prix <= 0) $errors[] = "Prix invalide";
        return $errors;
    }
}

$p = new Produit("T-shirt", 19.99);
echo $p->toJson();    // {"nom":"T-shirt","prix":19.99}
var_dump($p instanceof Exportable);  // true

Etape 5

Typage par interface — le polymorphisme

Typer avec une interface — code generiqueBonne pratique
<?php
interface Notifiable {
    public function envoyer(string $message): bool;
    public function getDestinataire(): string;
}

class EmailNotification implements Notifiable {
    public function __construct(private string $email) {}
    public function envoyer(string $msg): bool {
        // mail($this->email, 'Notif', $msg);
        return true;
    }
    public function getDestinataire(): string { return $this->email; }
}

class SmsNotification implements Notifiable {
    public function __construct(private string $tel) {}
    public function envoyer(string $msg): bool {
        // SmsGateway::send($this->tel, $msg);
        return true;
    }
    public function getDestinataire(): string { return $this->tel; }
}

// Fonction generique : accepte TOUT ce qui est Notifiable
function notifier(Notifiable $canal, string $message): void {
    if ($canal->envoyer($message)) {
        echo "Envoye a : " . $canal->getDestinataire();
    }
}

// Fonctionne avec Email et SMS sans changer notifier()
notifier(new EmailNotification("alice@ex.com"), "Bonjour !");
notifier(new SmsNotification("0612345678"),     "Bonjour !");
+
Typer par interface, pas par classe concrete. function notifier(Notifiable $canal) accepte n'importe quelle implementation future (WhatsApp, Push...) sans modifier le code. C'est le principe d'inversion de dependance (SOLID).

Etape 6

Traits — reutilisation sans heritage

Un trait est un ensemble de methodes qu'on peut inclure dans n'importe quelle classe avec use. C'est une solution a la limitation de l'heritage simple en PHP.

trait — definition et utilisationPHP
<?php
// Trait : morceau de code reutilisable
trait Horodatable {
    private ?string $creeLe  = null;
    private ?string $modifLe = null;

    public function marquerCreation(): void {
        $this->creeLe = date("Y-m-d H:i:s");
    }
    public function marquerModification(): void {
        $this->modifLe = date("Y-m-d H:i:s");
    }
    public function getCreeLe():  ?string { return $this->creeLe; }
    public function getModifLe(): ?string { return $this->modifLe; }
}

trait Serialisable {
    public function toArray(): array {
        return get_object_vars($this);
    }
    public function toJson(): string {
        return json_encode($this->toArray(), JSON_UNESCAPED_UNICODE);
    }
}

// Inclure plusieurs traits dans une classe
class Article {
    use Horodatable, Serialisable;

    public function __construct(
        public string $titre,
        public string $contenu,
    ) {
        $this->marquerCreation();
    }
}

class User {
    use Horodatable;  // meme trait, autre classe

    public function __construct(public string $nom) {
        $this->marquerCreation();
    }
}

$a = new Article("Titre", "Contenu...");
echo $a->getCreeLe();   // 2024-12-15 14:30:00
echo $a->toJson();       // {"titre":"Titre","contenu":"Contenu...",...}

Synthese

Tout ensemble — exemple complet

Systeme de paiement — abstract + interface + traitComplet
<?php
// Interface : contrat commun
interface Payable {
    public function payer(float $montant): bool;
    public function getNom(): string;
}

// Trait : log reutilisable
trait LoggablePaiement {
    private array $logs = [];
    protected function log(string $msg): void {
        $this->logs[] = date("H:i:s") . " - " . $msg;
    }
    public function getLogs(): array { return $this->logs; }
}

// Classe abstraite : base commune
abstract class MethodePaiement implements Payable {
    use LoggablePaiement;

    protected float $solde = 0;

    public function crediter(float $montant): void {
        $this->solde += $montant;
        $this->log("Credit de " . $montant);
    }
}

// Implementation concrete
class CarteBancaire extends MethodePaiement {
    public function __construct(private string $numeroCarte) {}

    public function payer(float $montant): bool {
        if ($montant > $this->solde) {
            $this->log("ECHEC paiement de " . $montant);
            return false;
        }
        $this->solde -= $montant;
        $this->log("Paiement de " . $montant . " OK");
        return true;
    }

    public function getNom(): string {
        return "CB **** " . substr($this->numeroCarte, -4);
    }
}

$cb = new CarteBancaire("1234567890123456");
$cb->crediter(100);
$cb->payer(30);   // true
$cb->payer(80);   // false (solde insuffisant)
print_r($cb->getLogs());
OK
Quand utiliser quoi : extends pour une relation "est-un" avec reutilisation de code. abstract pour definir une base commune non instanciable. interface pour definir un contrat independant de l'implementation. trait pour du code reutilisable dans des classes sans lien d'heritage.
