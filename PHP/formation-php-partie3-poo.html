Module 19 : Classes & Objets — Rappel et approfondissement

Objectif : Maîtriser la création de classes, les visibilités, les propriétés typées, les méthodes magiques et les méthodes/propriétés statiques.

Pourquoi la POO ?

La Programmation Orientée Objet permet d'organiser le code autour de concepts du monde réel. Plutôt que d'avoir 200 fonctions éparpillées, on regroupe les données et les comportements dans des classes.

Sans POO (procédural)
  • Variables partout dans le fichier
  • Fonctions sans lien logique
  • Difficile à réutiliser
  • Difficile à maintenir
Avec POO
  • Données et méthodes regroupées
  • Code réutilisable (héritage)
  • Facile à tester
  • Standard en entreprise

Structure complète d'une classe

// Une classe représente un concept : ici, un Utilisateur class Utilisateur { // ── PROPRIÉTÉS (variables de la classe) // public → accessible partout public string $nom; // protected → accessible dans la classe ET ses enfants protected string $email; // private → accessible UNIQUEMENT dans cette classe private string $motDePasse; // Propriété avec valeur par défaut public bool $actif = true; // ── CONSTRUCTEUR // Appelé automatiquement lors du "new" public function __construct( string $nom, string $email, string $motDePasse ) { $this->nom = $nom; $this->email = $email; $this->motDePasse = password_hash($motDePasse, PASSWORD_BCRYPT); } // ── GETTERS (accesseurs) public function getEmail(): string { return $this->email; } // ── SETTERS (mutateurs) public function setEmail(string $email): void { // On peut valider avant de modifier if (!filter_var($email, FILTER_VALIDATE_EMAIL)) { throw new InvalidArgumentException("Email invalide"); } $this->email = $email; } // ── MÉTHODES public function sePresenter(): string { return "Je m'appelle {$this->nom}"; } public function verifierMotDePasse(string $mdpSaisi): bool { return password_verify($mdpSaisi, $this->motDePasse); } } // ── UTILISATION $user = new Utilisateur("Alice", "alice@mail.com", "secret123"); echo $user->sePresenter(); // Je m'appelle Alice echo $user->getEmail(); // alice@mail.com var_dump($user->verifierMotDePasse("secret123")); // bool(true)

Promotion de propriétés (PHP 8+)

PHP 8 introduit une syntaxe raccourcie dans le constructeur — plus besoin de déclarer les propriétés séparément :

// Avant PHP 8 (verbeux) class Produit { public string $nom; public float $prix; public function __construct(string $nom, float $prix) { $this->nom = $nom; $this->prix = $prix; } } // PHP 8+ : promotion de propriétés (ÉQUIVALENT, mais court !) class Produit { public function __construct( public readonly string $nom, // readonly = ne peut plus être modifié après construction public float $prix ) {} } $p = new Produit("Clavier", 49.90); echo $p->nom; // Clavier echo $p->prix; // 49.9

Propriétés et méthodes statiques

Une propriété ou méthode statique appartient à la classe elle-même, pas à un objet. On y accède avec :: au lieu de ->.

class Compteur { // Propriété statique : partagée par tous les objets private static int $total = 0; public function __construct() { self::$total++; // "self::" pour accéder au statique depuis la classe } // Méthode statique : pas besoin d'instancier la classe public static function getTotal(): int { return self::$total; } } $a = new Compteur(); $b = new Compteur(); $c = new Compteur(); echo Compteur::getTotal(); // 3 — sans créer un autre objet

class Voiture { private array $donnees = []; public function __construct( public readonly string $marque, public int $annee ) {} // Appelé quand on fait : echo $voiture; public function __toString(): string { return "{$this->marque} ({$this->annee})"; } // Accès dynamique aux propriétés privées $donnees public function __get(string $nom): mixed { return $this->donnees[$nom] ?? null; } public function __set(string $nom, mixed $valeur): void { $this->donnees[$nom] = $valeur; } } $v = new Voiture("Renault", 2023); echo $v; // Renault (2023) → __toString $v->couleur = "rouge"; // → __set echo $v->couleur; // rouge → __get

Module 20 : Héritage

Concept clé : L'héritage permet à une classe enfant de récupérer toutes les propriétés et méthodes d'une classe parent, et de les spécialiser.

Schéma de l'héritage

Animal (classe parente)
→ nom, age, manger()
↙ extends        extends ↘
Chien
→ race, aboyer()
Chat
→ ronronner()

Syntaxe de base

// ── CLASSE PARENTE class Animal { public function __construct( protected string $nom, protected int $age ) {} public function sePresenter(): string { return "Je suis {$this->nom}, j'ai {$this->age} ans."; } public function manger(): string { return "{$this->nom} mange."; } } // ── CLASSE ENFANT class Chien extends Animal { public function __construct( string $nom, int $age, private string $race // propriété spécifique au Chien ) { parent::__construct($nom, $age); // appel du constructeur parent } // Méthode spécifique au Chien public function aboyer(): string { return "{$this->nom} aboie : Waf !"; } // Surcharge (override) : on redéfinit sePresenter() public function sePresenter(): string { // On appelle d'abord la version du parent $base = parent::sePresenter(); return $base . " Je suis un {$this->race}."; } } class Chat extends Animal { public function ronronner(): string { return "{$this->nom} ronronne... Prrr"; } } // ── UTILISATION $rex = new Chien("Rex", 3, "Berger Allemand"); $felix = new Chat("Félix", 5); echo $rex->sePresenter(); // Je suis Rex, j'ai 3 ans. Je suis un Berger Allemand. echo $rex->aboyer(); // Rex aboie : Waf ! echo $rex->manger(); // Rex mange. (hérité du parent) echo $felix->ronronner(); // Félix ronronne...

Le mot-clé final

// Classe final : personne ne peut l'étendre final class Configuration { public static $dbHost = "localhost"; } // Méthode final : personne ne peut la surcharger dans un enfant class Paiement { final public function valider(): bool { // Cette méthode ne PEUT PAS être redéfinie par un enfant return true; } }

instanceof — vérifier le type

$rex = new Chien("Rex", 3, "Labrador"); var_dump($rex instanceof Chien); // true var_dump($rex instanceof Animal); // true (car Chien extends Animal) var_dump($rex instanceof Chat); // false // Utile pour traiter des objets différents dans une liste $animaux = [ new Chien("Rex", 3, "Labrador"), new Chat("Minou", 2), new Chien("Pluto", 5, "Dalmatien"), ]; foreach ($animaux as $animal) { echo $animal->sePresenter() . "\n"; if ($animal instanceof Chien) { echo $animal->aboyer() . "\n"; } }
⚠️ PHP n'a pas d'héritage multiple !
Une classe ne peut étendre qu'une seule classe parent. Pour hériter de plusieurs sources, on utilise les Interfaces et les Traits (voir modules suivants).

Module 21 : Classes abstraites & Interfaces

Classes abstraites

Une classe abstraite est une classe incomplète — elle définit un squelette que les classes enfants doivent compléter. On ne peut pas l'instancier directement.

// abstract = modèle incomplet, non instanciable abstract class Forme { public function __construct( protected string $couleur = "blanc" ) {} // Méthode abstraite : DOIT être implémentée par les enfants abstract public function calculerSurface(): float; abstract public function calculerPerimetre(): float; // Méthode concrète : partagée par tous les enfants public function decrire(): string { return "Forme {$this->couleur} — surface : " . round($this->calculerSurface(), 2) . " cm²"; } } class Cercle extends Forme { public function __construct( private float $rayon, string $couleur = "blanc" ) { parent::__construct($couleur); } public function calculerSurface(): float { return M_PI * $this->rayon ** 2; } public function calculerPerimetre(): float { return 2 * M_PI * $this->rayon; } } class Rectangle extends Forme { public function __construct( private float $largeur, private float $hauteur, string $couleur = "blanc" ) { parent::__construct($couleur); } public function calculerSurface(): float { return $this->largeur * $this->hauteur; } public function calculerPerimetre(): float { return 2 * ($this->largeur + $this->hauteur); } } // new Forme() → ERREUR ! On ne peut pas instancier une classe abstraite $c = new Cercle(5, "rouge"); $r = new Rectangle(4, 6); echo $c->decrire(); // Forme rouge — surface : 78.54 cm² echo $r->decrire(); // Forme blanc — surface : 24 cm²

Interfaces

Une interface est un contrat : elle liste les méthodes que la classe devra obligatoirement implémenter. Une classe peut implémenter plusieurs interfaces.

// Définition des interfaces (contrats) interface Exportable { public function versJSON(): string; public function versCSV(): string; } interface Imprimable { public function imprimer(): void; } // La classe DOIT implémenter TOUTES les méthodes des interfaces class Facture implements Exportable, Imprimable { public function __construct( private int $numero, private float $montant ) {} public function versJSON(): string { return json_encode(['numero' => $this->numero, 'montant' => $this->montant]); } public function versCSV(): string { return "{$this->numero};{$this->montant}"; } public function imprimer(): void { echo "Impression facture #{$this->numero} — {$this->montant}€\n"; } } $f = new Facture(42, 150.00); echo $f->versJSON(); // {"numero":42,"montant":150} $f->imprimer(); // Impression facture #42 — 150€ // instanceof fonctionne aussi avec les interfaces var_dump($f instanceof Exportable); // true var_dump($f instanceof Imprimable); // true

Différences : classe abstraite vs interface

CritèreClasse abstraiteInterface
Peut avoir du code concret Oui Non (sauf constantes)
Peut avoir des propriétés Oui Non
Héritage multiple Une seule Plusieurs
Visibilité des méthodesToutesForcément public
Utilisation typiqueBase commune avec logique partagéeContrat de comportement
🧠 Règle simple :
→ Classe abstraite si tu veux partager du code entre classes liées.
→ Interface si tu veux imposer un contrat sur des classes différentes.

Module 22 : Traits

Un Trait est un ensemble de méthodes qu'on peut injecter dans n'importe quelle classe. C'est la réponse de PHP à l'héritage multiple.

// ── DÉFINITION D'UN TRAIT trait Horodatable { private DateTime $createdAt; private DateTime $updatedAt; public function initDates(): void { $this->createdAt = new DateTime(); $this->updatedAt = new DateTime(); } public function touch(): void { $this->updatedAt = new DateTime(); } public function getCreatedAt(): string { return $this->createdAt->format('d/m/Y H:i'); } } trait Sluggable { private string $slug; public function genererSlug(string $titre): void { $slug = strtolower($titre); $slug = str_replace([' ', 'é', 'è', 'ê', 'à'], ['-', 'e', 'e', 'e', 'a'], $slug); $slug = preg_replace('/[^a-z0-9-]/', '', $slug); $this->slug = trim($slug, '-'); } public function getSlug(): string { return $this->slug; } } // ── UTILISATION DE PLUSIEURS TRAITS ─ class Article { use Horodatable, Sluggable; // on injecte les deux traits public function __construct( private string $titre, private string $contenu ) { $this->initDates(); // méthode du trait Horodatable $this->genererSlug($titre); // méthode du trait Sluggable } } $article = new Article("Mon Premier Article", "Contenu ici..."); echo $article->getSlug(); // mon-premier-article echo $article->getCreatedAt(); // 25/02/2026 14:30
Conflit de méthodes entre traits
Si deux traits ont une méthode du même nom, PHP lève une erreur. On résout le conflit avec insteadof et as.
trait A { public function bonjour() { echo "Bonjour de A"; } } trait B { public function bonjour() { echo "Bonjour de B"; } } class MaClasse { use A, B { A::bonjour insteadof B; // priorité à A pour "bonjour" B::bonjour as bonjourB; // B::bonjour accessible sous un autre nom } } $obj = new MaClasse(); $obj->bonjour(); // Bonjour de A $obj->bonjourB(); // Bonjour de B

Module 23 : Namespaces & Autoloading

Pourquoi les namespaces ?

Quand une application grandit, on peut avoir deux classes nommées User dans deux fichiers différents. Les namespaces évitent les conflits en créant des espaces de noms, comme des dossiers pour les classes.

// ── Fichier : src/Model/User.php namespace App\Model; // TOUJOURS en premier dans le fichier class User { public function __construct(public string $nom) {} } // ── Fichier : src/Auth/User.php namespace App\Auth; class User // même nom, namespace différent → pas de conflit ! { public function login(string $email, string $mdp): bool { return true; } } // ── Fichier : index.php namespace App; use App\Model\User as UserModel; // alias pour éviter la confusion use App\Auth\User as UserAuth; $u1 = new UserModel("Alice"); $u2 = new UserAuth(); $u2->login("alice@mail.com", "secret");

Structure de fichiers recommandée (PSR-4)

mon-projet/
├── src/
│   ├── Model/
│   │   ├── User.php          → namespace App\Model
│   │   └── Article.php       → namespace App\Model
│   ├── Controller/
│   │   └── UserController.php → namespace App\Controller
│   └── Service/
│       └── MailService.php   → namespace App\Service
├── vendor/   (géré par Composer)
├── composer.json
└── index.php

Autoloading avec Composer

Sans autoloading, on doit faire require de chaque fichier manuellement. Composer automatise ce chargement.

// ── composer.json { "autoload": { "psr-4": { "App\\": "src/" // namespace App\ → dossier src/ } } } // Après : composer dump-autoload // ── index.php require 'vendor/autoload.php'; // UNE seule ligne ! use App\Model\User; use App\Controller\UserController; // PHP charge automatiquement src/Model/User.php $user = new User("Alice"); // PHP charge automatiquement src/Controller/UserController.php $ctrl = new UserController();
Retenir : Namespace = chemin du dossier. App\Model\User correspond au fichier src/Model/User.php. C'est la convention PSR-4, utilisée par tous les frameworks PHP (Symfony, Laravel…).

Module 24 : Exceptions personnalisées

Principe des exceptions

Les exceptions permettent de gérer les erreurs de manière propre, sans polluer le code avec des if partout. Quand quelque chose se passe mal, on lance (throw) une exception, et on la attrape (catch) là où on peut la gérer.

// Syntaxe de base : try / catch / finally try { // Code qui peut échouer $resultat = diviser(10, 0); } catch (InvalidArgumentException $e) { // Attrape ce type précis d'exception echo "Argument invalide : " . $e->getMessage(); } catch (Exception $e) { // Attrape toutes les autres exceptions echo "Erreur : " . $e->getMessage() . " (ligne " . $e->getLine() . ")"; } finally { // Toujours exécuté, qu'il y ait eu une erreur ou non echo "Nettoyage effectué."; } function diviser(int $a, int $b): float { if ($b === 0) { throw new InvalidArgumentException("Division par zéro impossible"); } return $a / $b; }

Créer ses propres exceptions

On crée des classes d'exceptions métier pour rendre le code plus lisible et précis.

namespace App\Exception; // Exception de base de l'application class AppException extends \Exception {} // Exceptions spécifiques métier class UtilisateurNonTrouveException extends AppException { public function __construct(int $id) { parent::__construct("Utilisateur #{$id} introuvable", 404); } } class StockInsuffisantException extends AppException { public function __construct(string $produit, int $demande, int $disponible) { parent::__construct( "Stock insuffisant pour '{$produit}' : demandé {$demande}, disponible {$disponible}", 409 ); } } class EmailDejaUtiliseException extends AppException { public function __construct(string $email) { parent::__construct("L'email '{$email}' est déjà utilisé", 422); } } // ── UTILISATION ── function inscrireUtilisateur(string $email): void { // Simulation d'une vérification BDD $emailsExistants = ["alice@mail.com", "bob@mail.com"]; if (in_array($email, $emailsExistants)) { throw new EmailDejaUtiliseException($email); } echo "Inscription réussie !"; } try { inscrireUtilisateur("alice@mail.com"); } catch (EmailDejaUtiliseException $e) { echo $e->getMessage(); // L'email 'alice@mail.com' est déjà utilisé echo $e->getCode(); // 422 } catch (AppException $e) { // Attrape toutes les AppException si pas attrapée avant echo "Erreur applicative : " . $e->getMessage(); }
Hiérarchie d'exceptions recommandée :
\Exception → AppException → MonException métier
Cela permet d'attraper soit l'exception précise, soit toutes les erreurs de l'app d'un coup.

Module 25 : Design Patterns utiles

Qu'est-ce qu'un Design Pattern ?
C'est une solution éprouvée à un problème récurrent en développement. Pas du code à copier, mais une façon de penser. On les retrouve partout dans Symfony, Laravel et les projets professionnels.

Pattern Singleton

Garantit qu'une seule instance d'une classe existe. Utile pour la connexion à la base de données.

class Database { // L'unique instance est stockée ici private static ?Database $instance = null; private PDO $pdo; // Constructeur privé : personne ne peut faire "new Database()" private function __construct() { $this->pdo = new PDO( "mysql:host=localhost;dbname=formation;charset=utf8", "root", "" ); $this->pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION); } // Point d'accès unique public static function getInstance(): static { if (static::$instance === null) { static::$instance = new static(); } return static::$instance; } public function getPdo(): PDO { return $this->pdo; } // Empêcher la copie private function __clone() {} } // Utilisation : toujours la même connexion PDO $db1 = Database::getInstance(); $db2 = Database::getInstance(); var_dump($db1 === $db2); // bool(true) — même objet !

Pattern Repository

Sépare la logique de récupération des données du reste du code. C'est ce qu'on utilise dans MVC pour accéder à la BDD proprement.

// Interface du repository (contrat) interface UserRepositoryInterface { public function findById(int $id): ?array; public function findAll(): array; public function save(array $data): bool; public function delete(int $id): bool; } // Implémentation concrète (PDO + MySQL) class UserRepository implements UserRepositoryInterface { private PDO $pdo; public function __construct() { $this->pdo = Database::getInstance()->getPdo(); } public function findById(int $id): ?array { $stmt = $this->pdo->prepare("SELECT * FROM users WHERE id = ?"); $stmt->execute([$id]); $user = $stmt->fetch(PDO::FETCH_ASSOC); return $user ?: null; } public function findAll(): array { return $this->pdo->query("SELECT * FROM users ORDER BY nom") ->fetchAll(PDO::FETCH_ASSOC); } public function save(array $data): bool { $stmt = $this->pdo->prepare( "INSERT INTO users (nom, email) VALUES (:nom, :email)" ); return $stmt->execute($data); } public function delete(int $id): bool { $stmt = $this->pdo->prepare("DELETE FROM users WHERE id = ?"); return $stmt->execute([$id]); } } // Utilisation propre dans un contrôleur $repo = new UserRepository(); $users = $repo->findAll(); $user = $repo->findById(5);

Pattern Factory

Une Factory crée des objets sans exposer la logique de création. Utile quand le type exact de l'objet dépend d'une condition.

interface Notification { public function envoyer(string $message): void; } class EmailNotification implements Notification { public function envoyer(string $message): void { echo "📧 Email : {$message}\n"; } } class SMSNotification implements Notification { public function envoyer(string $message): void { echo "📱 SMS : {$message}\n"; } } class SlackNotification implements Notification { public function envoyer(string $message): void { echo "Slack : {$message}\n"; } } // La Factory : crée le bon objet selon le canal class NotificationFactory { public static function creer(string $canal): Notification { return match($canal) { 'email' => new EmailNotification(), 'sms' => new SMSNotification(), 'slack' => new SlackNotification(), default => throw new InvalidArgumentException("Canal inconnu : {$canal}") }; } } // Utilisation : on ne sait pas quel objet exact est créé $canal = $_GET['canal'] ?? 'email'; $notif = NotificationFactory::creer($canal); $notif->envoyer("Votre commande est confirmée !");

Module 26 : Projet — Bibliothèque en POO

Objectif : Créer un système de gestion de bibliothèque en POO pure. Ce projet utilise tous les concepts vus dans cette partie : classes, héritage, interfaces, traits, exceptions.

Cahier des charges

  • Gérer des documents : Livre, DVD, Revue (héritage)
  • Un membre peut emprunter un document (max 3 à la fois)
  • Lever des exceptions métier si règles non respectées
  • Les documents ont des dates de création (Trait)
  • Les documents peuvent être exportés en JSON (Interface)

"\n"; } catch (DocumentIndisponibleException $e) { echo "" . $e->getMessage() . "\n"; } $alice->listerEmprunts(); $alice->retourner($livre1); // Export JSON d'un document echo $livre1->versJSON();
Ce projet intègre :
  • Classe abstraite (Document) avec méthode abstraite (getType())
  • Interface (Exportable) et son implémentation
  • Trait (Horodatable) injecté dans la classe abstraite
  • Héritage (Livre, DVD extends Document)
  • Exceptions métier personnalisées
  • Méthode magique __toString()
