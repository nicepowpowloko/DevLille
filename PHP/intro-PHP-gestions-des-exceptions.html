Gestion des
exceptions

Les exceptions permettent de signaler et de gerer les erreurs de facon structuree en PHP. Un bloc try/catch separe le code nominal du traitement des erreurs.

00
Concept

Erreur vs Exception

Avant PHP 5, les erreurs etaient gerees par des codes de retour ou trigger_error(). Les exceptions offrent un mecanisme structurel : elles interrompent le flux normal et remontent la pile d'appels jusqu'a un gestionnaire.

Sans exception — code non structure : $result = diviser(10, 0); if ($result === false) { /* gestion */ } // Chaque appel doit verifier le retour manuellement Avec exception — structure claire : try { $result = diviser(10, 0); // lance une exception echo $result; // jamais execute } catch (DivisionByZeroError $e) { echo "Erreur : " . $e->getMessage(); } // Code nominal et gestion d'erreur bien separes
i
Exception = objet. Une exception est une instance de la classe Exception (ou d'une sous-classe). Elle contient un message, un code, le fichier et la ligne, et la trace d'appel (getTrace()).
01
Etape 1

try / catch — syntaxe de base

try / catch — syntaxe de basePHP
<?php
function diviser(float $a, float $b): float {
    if ($b === 0.0) {
        throw new InvalidArgumentException('Division par zero impossible');
    }
    return $a / $b;
}

// Structure try / catch
try {
    // Code pouvant lancer une exception
    $r1 = diviser(10, 2);    // OK : 5
    $r2 = diviser(10, 0);    // Lance une exception
    $r3 = diviser(8, 4);     // Jamais execute
} catch (InvalidArgumentException $e) {
    // Capture uniquement InvalidArgumentException
    echo 'Erreur : ' . $e->getMessage();  // "Division par zero impossible"
    echo 'Fichier : ' . $e->getFile();
    echo 'Ligne : '  . $e->getLine();
}

// Methodes de l'objet Exception
// getMessage()  : message de l'exception
// getCode()     : code numerique (optionnel)
// getFile()     : fichier ou l'exception a ete lancee
// getLine()     : numero de ligne
// getTrace()    : tableau de la pile d'appels
// getPrevious() : exception precedente (chaining)
!
Le bloc try s'arrete au premier throw. Quand une exception est lancee dans un try, les instructions suivantes du try ne sont pas executees. L'execution reprend dans le catch correspondant.
02
Etape 2

Attraper plusieurs types d'exceptions

Plusieurs catch — du specifique au generalPHP
<?php
function chargerUtilisateur(int $id): array {
    if ($id <= 0) {
        throw new InvalidArgumentException('ID invalide : ' . $id);
    }
    // Simuler une erreur BDD
    if ($id === 999) {
        throw new RuntimeException('Connexion BDD perdue');
    }
    return ['id' => $id, 'nom' => 'Alice'];
}

// Plusieurs catch : du plus specifique au plus general
try {
    $user = chargerUtilisateur($_GET['id'] ?? 0);
    echo $user['nom'];
} catch (InvalidArgumentException $e) {
    // Erreur de validation : afficher a l'utilisateur
    echo 'Saisie incorrecte : ' . $e->getMessage();
} catch (RuntimeException $e) {
    // Erreur technique : logguer
    error_log($e->getMessage());
    echo 'Service temporairement indisponible';
} catch (Exception $e) {
    // Catch-all : toute autre exception
    echo 'Erreur inattendue';
}

// PHP 8+ : catch groupee pour plusieurs types
try {
    chargerUtilisateur($id);
} catch (InvalidArgumentException | RuntimeException $e) {
    echo $e->getMessage();
}
!
Ordre des catch : du plus specifique au plus general. PHP evalue les catch dans l'ordre. Si on met Exception en premier, il capturera tout et les catch suivants ne seront jamais atteints.

Etape 3

throw — lancer une exception

throw — lancer une exceptionPHP
<?php
// throw interrompt l'execution et remonte la pile
throw new Exception('Message');
throw new Exception('Message', 404);  // avec code

// Exceptions standards PHP les plus courantes
throw new InvalidArgumentException('Argument invalide');  // mauvaise valeur
throw new RuntimeException('Erreur runtime');          // erreur technique
throw new LogicException('Erreur de logique');          // bug programmeur
throw new OverflowException('Valeur trop grande');        // depassement
throw new OutOfRangeException('Indice invalide');         // hors limite
throw new DomainException('Valeur hors domaine');        // valeur non autorisee

// PHP 8 : throw comme expression
$valeur = $input ?? throw new InvalidArgumentException('Requis');
$age > 0 || throw new DomainException('Age negatif');
fn($x) => $x > 0 ? $x : throw new InvalidArgumentException('Negatif');

Etape 4

Exceptions personnalisees

Exceptions personnaliseesPHP
<?php
namespace App\Exceptions;

// Exception personnalisee : etend Exception (ou une sous-classe)
class ValidationException extends RuntimeException {
    private array $errors;

    public function __construct(array $errors) {
        $this->errors = $errors;
        parent::__construct('Donnees invalides : ' . implode(', ', $errors));
    }

    public function getErrors(): array { return $this->errors; }
}

class NotFoundException extends RuntimeException {
    public function __construct(string $resource, int $id) {
        parent::__construct($resource . ' introuvable (id: ' . $id . ')', 404);
    }
}

// Utilisation
try {
    $errors = [];
    if (empty($_POST['nom'])) $errors[] = 'Nom requis';
    if (!filter_var($_POST['email'], FILTER_VALIDATE_EMAIL)) $errors[] = 'Email invalide';
    if (!empty($errors)) throw new ValidationException($errors);
} catch (ValidationException $e) {
    foreach ($e->getErrors() as $err) {
        echo '<p class="error">' . $err . '</p>';
    }
}
+
Creez vos propres exceptions. Une exception personnalisee peut transporter des donnees supplementaires (tableau d'erreurs, code HTTP, nom de la ressource). Le catch peut alors acceder a ces donnees via les methodes personnalisees.
05
Etape 5

Hierarchie des exceptions

Les exceptions forment une hierarchie d'heritage. Un catch (Exception $e) attrape toute exception qui herite d'Exception. On peut concevoir une hierarchie pour son domaine metier.

Throwable (interface PHP — attrapable) | |--- Error (erreurs moteur PHP : TypeError, ParseError...) | |--- Exception (base de toutes les exceptions app) | |--- RuntimeException | |--- InvalidArgumentException | |--- OverflowException | |--- PDOException | |--- ValidationException (<-- vos exceptions) | |--- NotFoundException |--- LogicException |--- DomainException |--- OutOfRangeException
Hierarchie — attraper au bon niveauPHP
<?php
// Attraper a differents niveaux de la hierarchie
try {
    operationRisquee();
} catch (ValidationException $e) {
    // Specifique : erreur metier, montrer a l'utilisateur
    echo $e->getMessage();
} catch (RuntimeException $e) {
    // Attrape RuntimeException ET toutes ses sous-classes
    error_log($e->getMessage());
} catch (Throwable $e) {
    // Attrape TOUT : Exception ET Error (TypeError, etc.)
    error_log('Erreur critique : ' . $e->getMessage());
}
!
Catchable via Throwable. Pour attraper absolument tout (exceptions et erreurs PHP moteur comme TypeError), utiliser catch (Throwable $e). En pratique, reserver aux gestionnaires globaux d'erreur.
06
Etape 6

finally — execution garantie

finally — toujours executePHP
<?php
function lireFichier(string $chemin): string {
    $handle = fopen($chemin, 'r');
    if (!$handle) throw new RuntimeException('Impossible d''ouvrir : ' . $chemin);

    try {
        $contenu = fread($handle, filesize($chemin));
        if ($contenu === false) throw new RuntimeException('Erreur lecture');
        return $contenu;
    } catch (RuntimeException $e) {
        echo 'Erreur : ' . $e->getMessage();
        return '';
    } finally {
        // TOUJOURS execute : succes OU exception OU return
        fclose($handle);   // fermer le fichier dans tous les cas
    }
}

// finally : ordre d'execution
try {
    echo '1 - try';
    throw new Exception('test');
    echo 'jamais execute';
} catch (Exception $e) {
    echo '2 - catch';
} finally {
    echo '3 - finally';  // toujours execute en dernier
}
// Sortie : "1 - try" "2 - catch" "3 - finally"
i
finally = nettoyage garanti. Le bloc finally est execute que l'exception ait ete lancee ou non, meme si le try ou le catch contient un return. Parfait pour fermer une connexion BDD, un fichier, ou liberer une ressource.
07
Bonnes pratiques

Ce qu'il faut faire et eviter

Anti-pattern : swallow exceptionPHP
<?php
// MAL : utiliser Exception comme catch-all sans relancer
try {
    operationBDD();
} catch (Exception $e) {
    // Swallow : l'exception est perdue silencieusement
}

// BIEN : attraper le bon type, logguer, et gerer
try {
    operationBDD();
} catch (PDOException $e) {
    error_log('BDD : ' . $e->getMessage());
    throw new RuntimeException('Service indisponible', 503, $e);  // chaining
}
Gestionnaire global et exception chainingPHP
<?php
// set_exception_handler : gestionnaire global
set_exception_handler(function (Throwable $e): void {
    error_log('Uncaught: ' . $e->getMessage() . ' in ' . $e->getFile());
    http_response_code(500);
    echo json_encode(['error' => 'Erreur interne']);
});

// Exception chaining : conserver la cause originale
try {
    connecterBDD();
} catch (PDOException $e) {
    // Troisieme argument = exception precedente (chaining)
    throw new RuntimeException('Impossible de se connecter', 0, $e);
}
// Le catch peut recuperer la cause : $e->getPrevious()
!
Ne jamais avaler une exception silencieusement. Un catch vide ou qui ne loggue pas cache les bugs. Toujours au minimum error_log() le message, puis soit gerer l'erreur, soit relancer (re-throw).
08
Synthese

Exemple complet — UserService

UserService.php — gestion complete des exceptionsgood
<?php
namespace App\Services;

use App\Exceptions\NotFoundException;
use App\Exceptions\ValidationException;
use \PDO;
use \PDOException;

class UserService {
    public function __construct(private PDO $pdo) {}

    public function creer(string $nom, string $email): int {
        // 1. Valider
        $errors = [];
        if (strlen($nom) < 2)    $errors[] = 'Nom trop court';
        if (!filter_var($email, FILTER_VALIDATE_EMAIL)) $errors[] = 'Email invalide';
        if (!empty($errors)) throw new ValidationException($errors);

        // 2. Persister
        try {
            $stmt = $this->pdo->prepare('INSERT INTO users (nom,email) VALUES (?,?)');
            $stmt->execute([$nom, $email]);
            return (int)$this->pdo->lastInsertId();
        } catch (PDOException $e) {
            // Envelopper avec chaining
            throw new RuntimeException('Erreur creation user', 0, $e);
        }
    }

    public function findById(int $id): array {
        $stmt = $this->pdo->prepare('SELECT * FROM users WHERE id=?');
        $stmt->execute([$id]);
        $user = $stmt->fetch(PDO::FETCH_ASSOC);
        if (!$user) throw new NotFoundException('User', $id);
        return $user;
    }
}

// Appel dans le controleur
try {
    $id = $service->creer($_POST['nom'], $_POST['email']);
    echo json_encode(['id' => $id]);
} catch (ValidationException $e) {
    http_response_code(422);
    echo json_encode(['errors' => $e->getErrors()]);
} catch (RuntimeException $e) {
    http_response_code(500);
    error_log($e->getMessage());
    echo json_encode(['error' => 'Erreur interne']);
}
OK
Pattern complet : valider puis throw ValidationException. Envelopper les erreurs BDD (PDOException) dans une RuntimeException avec chaining. Dans le controleur, attraper par type et renvoyer le bon code HTTP.
