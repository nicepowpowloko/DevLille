Modélisation Merise
MCD → MLD

Apprendre à concevoir une base de données proprement : construire un MCD (Modèle Conceptuel), le dessiner dans Looping, puis le transformer en MLD (Modèle Logique) prêt pour SQL.

MCD MLD Looping SQL
01

C'est quoi Merise ?

Merise est une méthode de conception de bases de données française. L'idée : avant d'écrire une seule ligne de SQL, on modélise les données sur papier (ou dans Looping) pour être sûr de la structure.

MCD — Niveau conceptuel
Ce qu'on modélise — proche du monde réel.
On pense en entités (Client, Produit) et en associations (Commande, Appartient).

Pas de technique, pas de SQL. Juste la logique métier.
MLD — Niveau logique
Ce qu'on va créer — proche de la base de données.
On parle de tables, de clés primaires (PK) et de clés étrangères (FK).

Directement traduisible en SQL CREATE TABLE.
L'analogie : le MCD c'est le plan d'architecte — ce qu'on veut construire. Le MLD c'est le plan technique — comment on va le construire concrètement.
02

Entités & Associations — les deux briques

Un MCD n'a que deux types d'éléments : les entités (les choses du monde réel) et les associations (les liens entre ces choses).

Entité — un objet du monde réel dont on veut stocker des infos. Ex : CLIENT, PRODUIT, COMMANDE

Identifier les entités : un nom = une entité candidate. Demande-toi "est-ce que j'ai besoin de stocker plusieurs informations sur ce sujet ?" Si oui, c'est une entité.

L'identifiant (ou clé primaire) est l'attribut souligné — il identifie de manière unique chaque occurrence. Dans Looping, il apparaît automatiquement en gras/souligné.

Les cardinalités — le cœur de Merise

Les cardinalités indiquent combien de fois une entité peut participer à une association. On les lit toujours depuis l'entité vers l'association, avec un minimum et un maximum.

05

Looping — construire le MCD pas à pas

Looping est un logiciel gratuit (Windows/Mac avec Wine) qui permet de dessiner un MCD et de le transformer automatiquement en MLD et en SQL. Voici toutes les manipulations à faire.

1
Créer une entité
Double-clic sur la zone blanche → une entité apparaît.

Nommer l'entité : clic sur le nom → taper en MAJUSCULES par convention (CLIENT, PRODUIT…).

Ajouter des attributs : clic sur le "+" sous l'entité → taper le nom → Entrée.

Définir l'identifiant : double-clic sur l'attribut → cocher "Identifiant" → il passe en gras souligné.
2
Créer une association
Clic sur une entité → maintenir → glisser vers une autre entité → relâcher.

Une association se crée automatiquement entre les deux.

Nommer l'association : clic sur le nom de l'association → taper un verbe à l'infinitif (PASSER, CONTENIR…).

Ajouter un attribut à l'association : clic sur "+" de l'association (ex: quantite pour CONTENIR).
3
Définir les cardinalités
Clic sur le lien entre une entité et une association → un menu apparaît.

Choisir le minimum (0 ou 1) et le maximum (1 ou N).

Répéter pour chaque côté de chaque association.

Vérification : relire chaque cardinalité en français pour confirmer sa logique.
4
Générer le MLD et le SQL
Menu Génération → MLD : Looping transforme automatiquement le MCD en tables relationnelles.

Menu Génération → SQL : génère le code CREATE TABLE prêt à exécuter dans MySQL/PostgreSQL.

Vérifier les clés étrangères générées → elles doivent correspondre aux règles de transformation.
Télécharger Looping : looping-mcd.net — gratuit, pas d'installation sur Mac (utiliser Wine ou une VM Windows). Sinon utiliser DB Designer (en ligne) ou draw.io pour les schémas.
06

Les 3 règles de transformation MCD → MLD

Pour passer du MCD au MLD, il y a exactement 3 règles selon le type de cardinalité de l'association.

1
Association 1,1 — 1,N (ou 0,1 — 1,N)
La clé de l'entité côté "1" migre vers l'entité côté "N"
1,1 ↔ 1,N
MCD
CLIENT (1,N) —PASSER— (1,1) COMMANDE
→
MLD
CLIENT(id_client, nom, …)
COMMANDE(id_commande, date, …, #id_client)
L'identifiant de CLIENT (id_client) devient une clé étrangère (#) dans COMMANDE.
2
Association N,N (ou 0,N — 1,N)
Crée une nouvelle table intermédiaire avec les deux clés
N,N
MCD
COMMANDE (1,N)
—CONTENIR— quantite
(0,N) PRODUIT
→
MLD
COMMANDE(id_commande, …)
PRODUIT(id_produit, …)
CONTENIR(#id_commande, #id_produit, quantite)
👉 Une nouvelle table CONTENIR est créée. Sa clé primaire est la combinaison des deux clés étrangères. Les attributs de l'association (ici quantite) vont dans cette table.
3
Association 1,1 — 1,1 (rare)
Les deux entités fusionnent en une seule table
1,1 ↔ 1,1
Les deux entités peuvent être fusionnées en une seule table. On choisit un des deux identifiants comme clé primaire et on regroupe tous les attributs.
Mémo rapide :
1,1 — 1,N → FK qui migre vers le côté N
N,N → nouvelle table intermédiaire
1,1 — 1,1 → fusion des deux tables

08

Du MLD vers le SQL

Chaque table du MLD donne exactement un CREATE TABLE. Looping peut générer ce code automatiquement, mais voici comment le lire et le comprendre.

boutique.sql — généré depuis LoopingSQL
-- Toujours créer les tables sans FK en premier
CREATE TABLE CLIENT (
    id_client   INTAUTO_INCREMENT PRIMARY KEY,
    nomVARCHAR(100) NOT NULL,
    prenomVARCHAR(100),
    emailVARCHAR(150) UNIQUE NOT NULL,
    adresseTEXT
);

CREATE TABLE CATEGORIE (
    id_categorieINTAUTO_INCREMENT PRIMARY KEY,
    nom_categorieVARCHAR(100) NOT NULL,
    descriptionTEXT
);

-- Ensuite les tables avec FK
CREATE TABLE COMMANDE (
    id_commandeINTAUTO_INCREMENT PRIMARY KEY,
    date_commandeDATENOT NULL,
    statutVARCHAR(50),
    adresse_livraison TEXT,
    id_clientINTNOT NULL,   ← clé étrangère
    FOREIGN KEY (id_client) REFERENCES CLIENT(id_client)
);

CREATE TABLE PRODUIT (
    id_produitINTAUTO_INCREMENT PRIMARY KEY,
    nom_produitVARCHAR(200)NOT NULL,
    prix DECIMAL(10,2)  NOT NULL,
    stock INT  DEFAULT 0,
    description   TEXT,
    id_categorie  INT NOT NULL,
    FOREIGN KEY (id_categorie) REFERENCES CATEGORIE(id_categorie)
);

-- Table issue de l'association N,N — clé primaire composite
CREATE TABLE CONTENIR (
    id_commande  INT  NOT NULL,
    id_produit INT  NOT NULL,
    quantite  INT  NOT NULL DEFAULT 1,
    PRIMARY KEY (id_commande, id_produit),   ← clé composite
    FOREIGN KEY (id_commande) REFERENCES COMMANDE(id_commande),
    FOREIGN KEY (id_produit)  REFERENCES PRODUIT(id_produit)
);
Ordre de création : toujours créer les tables référencées avant les tables qui les référencent. CLIENT avant COMMANDE, CATEGORIE avant PRODUIT, COMMANDE et PRODUIT avant CONTENIR.
