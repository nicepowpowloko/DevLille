1. Le problème — Trop de useState

Avec useState, chaque donnée a son propre state et son propre setter. Quand le composant devient plus complexe — plusieurs données liées entre elles, plusieurs actions possibles — on se retrouve avec une cascade de setXxx() dans chaque handler. Le code devient difficile à lire et à maintenir.

Exemple concret — un formulaire multi-étapes avec useState :
5 champs, 5 states, 5 setters. Et si une action doit modifier plusieurs champs à la fois, on enchaîne plusieurs setters dans le même handler. Un seul oubli, une seule incohérence, et le bug est difficile à tracer.
Le problème — trop de useState
function FormulaireCommande() {
  // 5 states pour 5 données liées
  const [nom, setNom]           = useState('');
  const [email, setEmail]       = useState('');
  const [quantite, setQuantite] = useState(1);
  const [etape, setEtape]       = useState(1);
  const [erreur, setErreur]     = useState('');

  function validerEtape1() {
    if (!nom || !email) {
      setErreur('Champs obligatoires'); // setter 1
      return;
    }
    setErreur('');   // setter 1 encore
    setEtape(2);    // setter 2 — plusieurs setters dans un handler
    // Difficile de savoir dans quel ordre ils s'appliquent
  }

  function annuler() {
    setNom('');       // setter 1
    setEmail('');     // setter 2
    setQuantite(1);  // setter 3
    setEtape(1);      // setter 4
    setErreur('');    // setter 5 — reset en 5 lignes séparées
  }
}
Quand useState devient problématique
Trop de states liés : Quand 3+ données changent toujours ensemble, c'est le signe qu'elles forment un seul "état" à gérer globalement.
Actions complexes : Quand une seule action utilisateur (ex. "annuler") doit modifier plusieurs champs en même temps.
Logique difficile à tester : La logique "quoi faire quand X se passe" est éparpillée dans les handlers. Avec useReducer, toute la logique est dans une seule fonction pure, testable en isolation.
Transitions d'état : Quand le prochain state dépend du state actuel de plusieurs variables (ex. une machine à états finis).

2. Qu'est-ce que useReducer ?

useReducer est un Hook React qui remplace useState quand l'état devient complexe. Au lieu d'appeler un setter directement, on envoie une action (dispatch) qui décrit ce qui s'est passé. Une fonction pure appelée reducer décide comment mettre à jour l'état en réponse à cette action.

C'est le même principe que Redux, mais sans bibliothèque externe. Et c'est inspiré du pattern Command : au lieu de dire "fais ça", on dit "voilà ce qui s'est passé, qu'est-ce qu'on fait ?"

{ }

state

L'état complet — souvent un objet regroupant toutes les données liées. Une seule variable au lieu de plusieurs useState.

→

dispatch

Fonction qui envoie une action au reducer. On ne modifie JAMAIS le state directement — on dispatch une action.

f()

reducer

Fonction pure : (state, action) → nouveauState. Toute la logique de mise à jour est centralisée ici.

Analogie — le distributeur de billets :
Tu ne rentres pas dans le coffre modifier les billets toi-même (mutation directe). Tu insères ta carte, tapes ton code, choisis une action ("retirer 50€"). La machine traite ta demande et te donne le résultat. Le reducer, c'est la machine : il reçoit l'action, applique les règles, retourne le nouvel état.

3. Syntaxe — Les 3 éléments

Hook : useReducer — Syntaxe complète
Syntaxe
import { useReducer } from 'react';

// ── 1. L'état initial ──
const etatInitial = { count: 0, pas: 1 };

// ── 2. La fonction reducer (HORS du composant) ─
// Signature : (state, action) → nouveauState
// Règles :
//   - Fonction PURE : pas de fetch, pas de setTimeout, pas de mutation
//   - Retourner TOUJOURS un nouveau state (jamais undefined)
//   - Jamais muter state directement — toujours un spread ou une copie
function reducer(state, action) {
  switch (action.type) {
    case 'INCREMENTER':
      return { ...state, count: state.count + state.pas };
    case 'DECREMENTER':
      return { ...state, count: state.count - state.pas };
    case 'RESET':
      return etatInitial; // retour à zéro
    case 'SET_PAS':
      return { ...state, pas: action.payload }; // payload = la donnée associée
    default:
      return state; // action inconnue → state inchangé
  }
}

// ── 3. Utilisation dans le composant ──
function Compteur() {
  const [state, dispatch] = useReducer(reducer, etatInitial);
  //          ↑                ↑              ↑
  //       état actuel      fonction       état initial

  return (
    <div>
      <p>Compteur : {state.count} (pas : {state.pas})</p>

      {/* dispatch envoie une action au reducer */}
      <button onClick={() => dispatch({ type: 'INCREMENTER' })}>+</button>
      <button onClick={() => dispatch({ type: 'DECREMENTER' })}>-</button>
      <button onClick={() => dispatch({ type: 'RESET' })}>Reset</button>

      {/* Avec payload — une donnée supplémentaire */}
      <input
        type="number"
        value={state.pas}
        onChange={(e) => dispatch({ type: 'SET_PAS', payload: Number(e.target.value) })}
      />
    </div>
  );
}

3.1 Anatomie d'une action

Structure d'une action
// Une action est un simple objet JavaScript
// Convention : type en MAJUSCULES_UNDERSCORES, payload pour les données

// Action sans donnée supplémentaire
{ type: 'RESET' }
{ type: 'VIDER_PANIER' }
{ type: 'ETAPE_SUIVANTE' }

// Action avec une donnée (payload)
{ type: 'AJOUTER_ARTICLE', payload: { id: 3, nom: 'Souris', prix: 29 } }
{ type: 'SUPPRIMER_ARTICLE', payload: 3 }         // payload = juste l'id
{ type: 'CHANGER_QUANTITE', payload: { id: 3, quantite: 2 } }

// Bonne pratique — nommer les actions avec des constantes
const ACTIONS = {
  AJOUTER:    'AJOUTER_ARTICLE',
  SUPPRIMER:  'SUPPRIMER_ARTICLE',
  VIDER:      'VIDER_PANIER',
};

// Utilisation avec constantes
dispatch({ type: ACTIONS.AJOUTER, payload: produit });

3.2 Les règles du reducer

Règles à respecter
// CORRECT — retourner un NOUVEAU state (spread)
case 'INCREMENTER':
  return { ...state, count: state.count + 1 };

// INTERDIT — muter l'état existant directement
case 'INCREMENTER':
  state.count = state.count + 1; // mutation directe !
  return state;                     // React ne détecte pas le changement

// CORRECT — modifier un tableau de façon immuable
case 'SUPPRIMER_ARTICLE':
  return {
    ...state,
    articles: state.articles.filter(a => a.id !== action.payload)
  };

// INTERDIT — pas d'effets de bord dans le reducer
case 'CHARGER':
  const data = await fetch('...'); //  jamais d'async dans le reducer

// TOUJOURS — gérer le case default
default:
  return state; // action inconnue → state inchangé
Le reducer doit être une fonction pure : Pour un même state + une même action en entrée, il retourne TOUJOURS le même nouveau state en sortie. Pas de fetch, pas de setTimeout, pas de Math.random(), pas de mutation. Toute la logique est prévisible et testable.

4. Exemple 1 — Compteur avec pas variable

Reprenons le compteur classique de useState, mais en ajoutant plusieurs fonctionnalités liées : valeur, pas d'incrémentation, minimum et maximum. Avec useState, ça nécessiterait 4 states séparés. Avec useReducer, un seul objet state suffit.

4.1 Le reducer

compteurReducer.js
// État initial — tout ce qui décrit le compteur
export const etatInitial = {
  count: 0,
  pas:   1,
  min:  -10,
  max:   10,
};

export function compteurReducer(state, action) {
  switch (action.type) {

    case 'INCREMENTER': {
      // Ne pas dépasser le max
      const nouvelleValeur = state.count + state.pas;
      return { ...state, count: Math.min(nouvelleValeur, state.max) };
    }

    case 'DECREMENTER': {
      const nouvelleValeur = state.count - state.pas;
      return { ...state, count: Math.max(nouvelleValeur, state.min) };
    }

    case 'SET_PAS':
      return { ...state, pas: action.payload };

    case 'SET_MIN':
      return { ...state, min: action.payload };

    case 'SET_MAX':
      return { ...state, max: action.payload };

    case 'RESET':
      return etatInitial;

    default:
      return state;
  }
}

4.2 Le composant

Compteur.jsx
import { useReducer } from 'react';
import { compteurReducer, etatInitial } from './compteurReducer';

function Compteur() {
  const [state, dispatch] = useReducer(compteurReducer, etatInitial);

  // Indicateur visuel
  const couleur = state.count > 0
    ? 'green'
    : state.count < 0
    ? 'red'
    : 'black';

  return (
    <div>
      <h2 style={{ color: couleur, fontSize: '3em' }}>
        {state.count}
      </h2>

      <div>
        <button onClick={() => dispatch({ type: 'DECREMENTER' })}>
          − {state.pas}
        </button>
        <button onClick={() => dispatch({ type: 'INCREMENTER' })}>
          + {state.pas}
        </button>
        <button onClick={() => dispatch({ type: 'RESET' })}>
          Reset
        </button>
      </div>

      <div>
        <label>Pas :</label>
        <input
          type="number" value={state.pas} min="1"
          onChange={e => dispatch({ type: 'SET_PAS', payload: Number(e.target.value) })}
        />
      </div>

      <p>Limites : {state.min} / {state.max}</p>
    </div>
  );
}
Ce qu'on a gagné par rapport à useState :
  • Toute la logique (clamp min/max, calcul du pas) est dans le reducer, hors du composant
  • Le composant est devenu "bête" : il dispatche des actions sans connaître la logique
  • On peut tester le reducer indépendamment du composant
  • Ajouter une nouvelle action = ajouter un case dans le switch, rien d'autre

5. Exemple 2 — Todo List

La Todo List est l'exemple parfait pour useReducer : plusieurs actions (ajouter, supprimer, cocher, filtrer) qui opèrent toutes sur le même tableau de tâches.

5.1 Le reducer

todoReducer.js
// État initial
export const etatInitial = {
  taches: [],
  filtre: 'toutes',  // 'toutes' | 'actives' | 'terminees'
  prochainId: 1,
};

export function todoReducer(state, action) {
  switch (action.type) {

    case 'AJOUTER':
      return {
        ...state,
        taches: [
          ...state.taches,
          {
            id:       state.prochainId,
            texte:    action.payload,
            terminee: false,
          }
        ],
        prochainId: state.prochainId + 1,
      };

    case 'SUPPRIMER':
      return {
        ...state,
        taches: state.taches.filter(t => t.id !== action.payload),
      };

    case 'TOGGLE':
      return {
        ...state,
        taches: state.taches.map(t =>
          t.id === action.payload
            ? { ...t, terminee: !t.terminee }
            : t
        ),
      };

    case 'MODIFIER_TEXTE':
      return {
        ...state,
        taches: state.taches.map(t =>
          t.id === action.payload.id
            ? { ...t, texte: action.payload.texte }
            : t
        ),
      };

    case 'SET_FILTRE':
      return { ...state, filtre: action.payload };

    case 'SUPPRIMER_TERMINEES':
      return {
        ...state,
        taches: state.taches.filter(t => !t.terminee),
      };

    default:
      return state;
  }
}

5.2 Le composant principal

TodoApp.jsx
import { useReducer, useState } from 'react';
import { todoReducer, etatInitial } from './todoReducer';

function TodoApp() {
  const [state, dispatch] = useReducer(todoReducer, etatInitial);
  const [saisie, setSaisie] = useState(''); // useState OK pour le champ texte local

  // Variable dérivée — calculée, pas stockée
  const tachesFiltrees = state.taches.filter(t => {
    if (state.filtre === 'actives')   return !t.terminee;
    if (state.filtre === 'terminees') return  t.terminee;
    return true;
  });

  const nombreRestantes = state.taches.filter(t => !t.terminee).length;

  function ajouterTache(e) {
    e.preventDefault();
    if (!saisie.trim()) return;
    dispatch({ type: 'AJOUTER', payload: saisie.trim() });
    setSaisie('');
  }

  return (
    <div>
      <h2>Mes tâches ({nombreRestantes} restantes)</h2>

      {/* Formulaire d'ajout */}
      <form onSubmit={ajouterTache}>
        <input
          value={saisie}
          onChange={e => setSaisie(e.target.value)}
          placeholder="Nouvelle tâche..."
        />
        <button type="submit">Ajouter</button>
      </form>

      {/* Filtres */}
      {['toutes', 'actives', 'terminees'].map(f => (
        <button
          key={f}
          onClick={() => dispatch({ type: 'SET_FILTRE', payload: f })}
          style={{ fontWeight: state.filtre === f ? 'bold' : 'normal' }}
        >
          {f}
        </button>
      ))}

      {/* Liste */}
      {tachesFiltrees.map(tache => (
        <div key={tache.id}>
          <input
            type="checkbox"
            checked={tache.terminee}
            onChange={() => dispatch({ type: 'TOGGLE', payload: tache.id })}
          />
          <span style={{ textDecoration: tache.terminee ? 'line-through' : 'none' }}>
            {tache.texte}
          </span>
          <button onClick={() => dispatch({ type: 'SUPPRIMER', payload: tache.id })}>
            Supprimer
          </button>
        </div>
      ))}

      <button onClick={() => dispatch({ type: 'SUPPRIMER_TERMINEES' })}>
        Effacer les tâches terminées
      </button>
    </div>
  );
}
useState et useReducer ensemble : On peut utiliser useState pour l'input de saisie (donnée locale, simple) ET useReducer pour la liste de tâches (donnée complexe, partagée). Les deux hooks coexistent parfaitement dans le même composant.

6. Exemple 3 — Panier e-commerce

Le panier est le cas d'usage le plus riche pour useReducer. Les actions sont multiples et certaines ont une logique complexe (incrémenter la quantité si l'article existe déjà, calculer le total…).

6.1 Le reducer du panier

panierReducer.js
export const etatInitial = {
  articles: [],
  coupon:   null,  // code promo éventuel
};

export function panierReducer(state, action) {
  switch (action.type) {

    case 'AJOUTER': {
      const existe = state.articles.find(a => a.id === action.payload.id);
      if (existe) {
        // L'article existe → incrémenter la quantité
        return {
          ...state,
          articles: state.articles.map(a =>
            a.id === action.payload.id
              ? { ...a, quantite: a.quantite + 1 }
              : a
          ),
        };
      }
      // Nouvel article → l'ajouter avec quantite: 1
      return {
        ...state,
        articles: [...state.articles, { ...action.payload, quantite: 1 }],
      };
    }

    case 'RETIRER':
      return {
        ...state,
        articles: state.articles.filter(a => a.id !== action.payload),
      };

    case 'SET_QUANTITE': {
      const { id, quantite } = action.payload;
      // Si quantité tombe à 0 → supprimer l'article
      if (quantite <= 0) {
        return {
          ...state,
          articles: state.articles.filter(a => a.id !== id),
        };
      }
      return {
        ...state,
        articles: state.articles.map(a =>
          a.id === id ? { ...a, quantite } : a
        ),
      };
    }

    case 'APPLIQUER_COUPON':
      return { ...state, coupon: action.payload };

    case 'VIDER':
      return etatInitial;

    default:
      return state;
  }
}

6.2 Le composant panier

Panier.jsx
import { useReducer } from 'react';
import { panierReducer, etatInitial } from './panierReducer';

function Panier() {
  const [state, dispatch] = useReducer(panierReducer, etatInitial);

  // Variables dérivées
  const total = state.articles.reduce(
    (acc, a) => acc + a.prix * a.quantite, 0
  );
  const totalApplique = state.coupon === 'PROMO10'
    ? total * 0.9
    : total;

  return (
    <div>
      <h2>Panier ({state.articles.length} articles)</h2>

      {state.articles.map(article => (
        <div key={article.id}>
          <span>{article.nom}</span>
          <input
            type="number"
            value={article.quantite}
            min="0"
            onChange={e => dispatch({
              type: 'SET_QUANTITE',
              payload: { id: article.id, quantite: Number(e.target.value) }
            })}
          />
          <span>{(article.prix * article.quantite).toFixed(2)} €</span>
          <button onClick={() => dispatch({ type: 'RETIRER', payload: article.id })}>
            Retirer
          </button>
        </div>
      ))}

      <p>Total : {totalApplique.toFixed(2)} €
        {state.coupon && <em> (promo -10%)</em>}
      </p>

      <button onClick={() => dispatch({ type: 'APPLIQUER_COUPON', payload: 'PROMO10' })}>
        Appliquer PROMO10
      </button>

      <button onClick={() => dispatch({ type: 'VIDER' })}>
        Vider le panier
      </button>
    </div>
  );
}

7. useState vs useReducer — Comment choisir ?

useState
// Simple, peu de données
const [count, setCount] = useState(0);
const [nom, setNom]     = useState('');
const [ouvert, setOuvert] = useState(false);

// Utiliser useState quand :
// - 1-2 données simples et indépendantes
// - Les mises à jour sont directes
// - Pas de logique complexe
// - Données locales à un seul composant

// Exemples parfaits :
// - Ouverture/fermeture d'un modal
// - Valeur d'un champ texte
// - Toggle d'un menu
// - Compteur simple
useReducer
// Complexe, données liées
const [state, dispatch] = useReducer(
  reducer,
  { articles: [], filtre: 'toutes', total: 0 }
);

// Utiliser useReducer quand :
// - 3+ données qui évoluent ensemble
// - Plusieurs actions possibles
// - La logique est complexe
// - Le prochain state dépend du state actuel

// Exemples parfaits :
// - Panier e-commerce
// - Todo List avec filtres
// - Formulaire multi-étapes
// - Jeu (score, vies, niveau)
Critère useState useReducer
Nombre de variables1 à 23 et plus (souvent un objet)
Complexité de la logiqueDirecte (setVal)Complexe (switch + cas)
Nombre d'actions1 à 2Plusieurs types d'actions

La règle des 3 : Si tu as besoin de 3 useState ou plus pour un même "objet fonctionnel" (un panier, une tâche, un formulaire), c'est le signal pour passer à useReducer et regrouper tout dans un seul state objet.

8. useReducer + useContext — Le duo puissant

Combiné avec useContext (vu au module précédent), useReducer permet de créer un state global géré par actions, accessible dans toute l'application. C'est le pattern qui remplace Redux dans la majorité des cas.

8.1 Le principe

useReducer + useContext = mini-Redux
useReducer : Gère l'état et les transitions. Le state est un objet. Chaque action modifie cet objet de façon prévisible.
useContext : Rend le state ET dispatch accessibles dans toute l'application, sans prop drilling.
Résultat : N'importe quel composant peut lire le state global OU déclencher une action — comme avec Redux, mais en natif React.

8.2 PanierContext avec useReducer

context/PanierContext.jsx — avec useReducer
import { createContext, useContext, useReducer } from 'react';
import { panierReducer, etatInitial } from './panierReducer';

const PanierContext = createContext();

export function usePanier() {
  return useContext(PanierContext);
}

export function PanierProvider({ children }) {
  // useReducer remplace useState ici
  const [state, dispatch] = useReducer(panierReducer, etatInitial);

  // Variables dérivées calculées ici, accessibles partout
  const totalArticles = state.articles.reduce(
    (acc, a) => acc + a.quantite, 0
  );
  const prixTotal = state.articles.reduce(
    (acc, a) => acc + a.prix * a.quantite, 0
  );

  // On expose state, dispatch ET les variables dérivées
  return (
    <PanierContext.Provider value={{
      articles: state.articles,
      coupon:   state.coupon,
      totalArticles,
      prixTotal,
      dispatch,
    }}>
      {children}
    </PanierContext.Provider>
  );
}

components/BoutonAjouter.jsx
import { usePanier } from '../context/PanierContext';

components/BadgePanier.jsx
import { usePanier } from '../context/PanierContext';

function BadgePanier() {

  return <span>🛒 {totalArticles}</span>;

Ce qu'on a gagné :
  • Toute la logique panier est dans panierReducer.js — testable, lisible, isolée
  • N'importe quel composant peut dispatcher une action avec dispatch
  • N'importe quel composant peut lire le state ou les variables dérivées
  • Ajouter une fonctionnalité = ajouter un case dans le reducer, rien d'autre dans les composants

9. Exercices

Exercice 1 — Compteur avancé (débutant)

Objectif : Refactoriser un compteur useState en useReducer.

  1. Partir d'un compteur avec useState (incrémenter, décrémenter, reset).
  2. Créer un fichier compteurReducer.js avec le reducer et l'état initial.
  3. Remplacer les useState par useReducer(compteurReducer, etatInitial).
  4. Remplacer les setCount() par dispatch({ type: '...' }).
  5. Ajouter une action SET_VALEUR qui permet de saisir une valeur directement avec un input.
Résultat attendu : Le composant fait exactement la même chose, mais toute la logique est dans le reducer.

Exercice 2 — Formulaire multi-étapes (intermédiaire)

Objectif : Gérer un formulaire de 3 étapes avec useReducer.

  1. Créer un formulaire avec 3 étapes : Identité (nom, prénom) → Coordonnées (email, téléphone) → Confirmation.
  2. L'état contient : etape, nom, prenom, email, telephone, erreurs.
  3. Actions : ETAPE_SUIVANTE, ETAPE_PRECEDENTE, MODIFIER_CHAMP, SET_ERREURS, RESET.
  4. La navigation entre étapes valide les champs de l'étape courante.
  5. L'étape 3 affiche un résumé de toutes les données saisies.

Exercice 3 — Panier + useContext (avancé)

Objectif : Combiner useReducer et useContext pour un panier global.

  1. Créer panierReducer.js avec les actions : AJOUTER, RETIRER, SET_QUANTITE, VIDER.
  2. Créer PanierContext.jsx avec PanierProvider utilisant useReducer.
  3. Brancher le Provider dans App.jsx.
  4. Créer une page Boutique avec 4 produits fictifs, chacun avec un bouton "Ajouter au panier".
  5. Afficher le badge avec le nombre d'articles dans la navbar.
  6. Créer une page Panier avec la liste, les quantités modifiables et le total.
  7. Bonus : ajouter une action APPLIQUER_COUPON et un input pour saisir un code promo.

10.2 État initial et actions disponibles

export const etatInitial = {
  taches:     [],
  filtre:     'toutes',       // 'toutes' | 'actives' | 'terminees'
  tri:        'date',          // 'date' | 'alpha' | 'priorite'
  prochainId: 1,
};

// SUPPRIMER       payload: id
// TOGGLE          payload: id

10.3 Le contexte Todo

context/TodoContext.jsx
import { createContext, useContext, useReducer } from 'react';
import { todoReducer, etatInitial } from '../reducers/todoReducer';

const TodoContext = createContext();

export function useTodo() {
  return useContext(TodoContext);
}

export function TodoProvider({ children }) {
  const [state, dispatch] = useReducer(todoReducer, etatInitial);

  // Variables dérivées
  const tachesFiltrees = state.taches
    .filter(t => {
      if (state.filtre === 'actives')   return !t.terminee;
      if (state.filtre === 'terminees') return  t.terminee;
      return true;
    })
    .sort((a, b) => {
      if (state.tri === 'alpha') return a.texte.localeCompare(b.texte);
      return 0; // 'date' : ordre d'insertion
    });

  const stats = {
    total:     state.taches.length,
    actives:   state.taches.filter(t => !t.terminee).length,
    terminees: state.taches.filter(t =>  t.terminee).length,
  };

  return (
    <TodoContext.Provider value={{ state, dispatch, tachesFiltrees, stats }}>
      {children}
    </TodoContext.Provider>
  );
}
Fonctionnalités du projet :
  • Ajouter une tâche avec un niveau de priorité (haute / normale / basse)
  • Cocher une tâche (toggle terminée / active)
  • Supprimer une tâche ou effacer toutes les terminées
  • Filtrer par statut et trier par nom ou priorité
  • Stats en temps réel : total, actives, terminées
  • Modifier le texte d'une tâche existante en double-cliquant
