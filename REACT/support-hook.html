1. Le problème — La logique dupliquée

Dans les projets React, on se retrouve souvent à écrire la même logique dans plusieurs composants différents. Par exemple : trois composants qui appellent chacun une URL différente répètent exactement le même code useState + useEffect + fetch, seule l'URL change.

La duplication de code — le vrai problème :
Si le comportement doit changer (ajouter un état d'erreur, gérer un timeout, changer le format des données), il faut modifier chaque composant un par un. Si on en oublie un, on a un bug silencieux.
Avant — logique dupliquée dans 3 composants
// ListeUsers.jsx — fetch répété
function ListeUsers() {
  const [data, setData]       = useState(null);
  const [loading, setLoading] = useState(true);
  const [erreur, setErreur]   = useState(null);

  useEffect(() => {
    fetch('https://api.exemple.com/users')
      .then(r => r.json())
      .then(setData)
      .catch(setErreur)
      .finally(() => setLoading(false));
  }, []);
  // ...
}

// ListeProduits.jsx — MÊME code, URL différente
function ListeProduits() {
  const [data, setData]       = useState(null);
  const [loading, setLoading] = useState(true);
  const [erreur, setErreur]   = useState(null);

  useEffect(() => {
    fetch('https://api.exemple.com/products') // seule différence
      .then(r => r.json())
      .then(setData)
      .catch(setErreur)
      .finally(() => setLoading(false));
  }, []);
  // ...
}

// ListeCommandes.jsx — MÊME code encore
function ListeCommandes() { /* même chose... */ }
La solution — un Custom Hook :
On extrait cette logique dans une fonction useFetch(url). Les 3 composants deviennent chacun une seule ligne. Si on doit modifier le comportement de fetch, on le fait en un seul endroit.

2. Qu'est-ce qu'un Custom Hook ?

Un Custom Hook est une fonction JavaScript ordinaire dont le nom commence par use et qui peut appeler d'autres Hooks React (useState, useEffect, useContext…). Ce n'est pas une magie React — c'est juste une convention de nommage qui permet à React d'appliquer ses règles correctement.

use

Nom en "use"

La seule règle obligatoire. useFetch, useLocalStorage, useForm... React reconnaît les hooks à ce préfixe.

↻

Réutilisable

Le même hook peut être appelé dans autant de composants qu'on veut. Chaque appel crée son propre state isolé — pas de partage accidentel.

{ }

Retourne ce qu'on veut

Un hook peut retourner une valeur, un tableau, un objet, une fonction — ce dont le composant a besoin pour fonctionner.

2.1 Anatomie d'un Custom Hook

Structure type
// Un custom hook = une fonction qui commence par "use"
function useMonHook(parametre) {
  // 1. Peut utiliser tous les hooks React
  const [valeur, setValeur] = useState(parametre);

  // 2. Peut contenir toute la logique nécessaire
  useEffect(() => {
    // effets de bord, subscriptions, API...
  }, [parametre]);

  function modifier(nouvelleValeur) {
    setValeur(nouvelleValeur);
  }

  // 3. Retourne ce dont le composant a besoin
  return { valeur, modifier };
  // ou : return [valeur, modifier];
  // ou : return valeur;
  // Libre choix selon ce qui est le plus pratique
}

// Utilisation dans un composant — comme un hook React natif
function MonComposant() {
  const { valeur, modifier } = useMonHook('initial');
  return <p>{valeur}</p>;
}

3. Les règles des Hooks — Rappel important

Les Custom Hooks suivent exactement les mêmes règles que les hooks React natifs. Ces règles s'appliquent aussi bien à useState qu'à un hook qu'on crée soi-même.

Règle 1 — Appeler les hooks uniquement au niveau supérieur
Ne jamais appeler un hook à l'intérieur d'une condition, d'une boucle ou d'une fonction imbriquée. React doit toujours appeler les hooks dans le même ordre à chaque rendu.
Règles des hooks
//  INTERDIT — hook dans une condition
function MonComposant({ estConnecte }) {
  if (estConnecte) {
    const data = useFetch('/api/profil'); // 
  }
}

// INTERDIT — hook dans une boucle
function MonComposant({ ids }) {
  ids.forEach(id => {
    const data = useFetch(`/api/item/${id}`); // 
  });
}

// CORRECT — hook au niveau supérieur du composant
function MonComposant({ url, estConnecte }) {
  const { data, loading } = useFetch(url); //  toujours appelé

  if (!estConnecte) return null; // la condition APRÈS le hook
}

//  CORRECT — hook dans un custom hook
function useFetch(url) {
  const [data, setData] = useState(null); //  niveau supérieur du hook
  // ...
}

// Règle 2 — Appeler les hooks uniquement depuis :
// → des composants React (fonctions qui retournent du JSX)
// → d'autres custom hooks (fonctions dont le nom commence par "use")
Pourquoi ces règles ? React mémorise l'état de chaque hook dans un tableau interne, dans l'ordre où ils sont appelés. Si l'ordre change d'un rendu à l'autre (à cause d'une condition), React perd la correspondance entre les hooks et leurs états. Cela provoque des bugs imprévisibles.

4. useFetch — Récupérer des données depuis une API

Le hook le plus utile à connaître. Il encapsule le pattern useState + useEffect + fetch et le rend réutilisable pour n'importe quelle URL.

4.1 Version simple

hooks/useFetch.js — version de base
import { useState, useEffect } from 'react';

function useFetch(url) {
  const [data, setData]       = useState(null);
  const [loading, setLoading] = useState(true);
  const [erreur, setErreur]   = useState(null);

  useEffect(() => {
    // Réinitialiser à chaque changement d'URL
    setLoading(true);
    setErreur(null);

    fetch(url)
      .then(response => {
        if (!response.ok) {
          throw new Error(`Erreur HTTP : ${response.status}`);
        }
        return response.json();
      })
      .then(setData)
      .catch(err => setErreur(err.message))
      .finally(() => setLoading(false));
  }, [url]); // se relance si l'URL change

  return { data, loading, erreur };
}

export default useFetch;

4.3 Version avancée — avec AbortController

hooks/useFetch.js — version complète
import { useState, useEffect } from 'react';

function useFetch(url) {
  const [data, setData]       = useState(null);
  const [loading, setLoading] = useState(true);
  const [erreur, setErreur]   = useState(null);

  useEffect(() => {
    // AbortController : annule la requête si le composant se démonte
    // ou si l'URL change avant la fin du fetch
    const controller = new AbortController();

    setLoading(true);
    setErreur(null);

    fetch(url, { signal: controller.signal })
      .then(response => {
        if (!response.ok) throw new Error(`Erreur ${response.status}`);
        return response.json();
      })
      .then(json => {
        setData(json);
        setLoading(false);
      })
      .catch(err => {
        // Ignorer l'erreur d'annulation — c'est intentionnel
        if (err.name !== 'AbortError') {
          setErreur(err.message);
          setLoading(false);
        }
      });

    // Fonction de nettoyage — appelée avant le prochain effet
    return () => controller.abort();
  }, [url]);

  return { data, loading, erreur };
}

export default useFetch;
Pourquoi AbortController ? Si l'utilisateur navigue vers une autre page avant que le fetch soit terminé, React va essayer de mettre à jour un composant démonté et afficher un avertissement. L'AbortController annule proprement la requête et le nettoyage dans le return de useEffect est automatiquement appelé.

5. useLocalStorage — Persister l'état

Ce hook remplace useState mais synchronise automatiquement la valeur avec le localStorage du navigateur. L'état persiste même après un rechargement de page.

hooks/useLocalStorage.js
import { useState } from 'react';

function useLocalStorage(cle, valeurInitiale) {
  // Initialiser depuis le localStorage si la clé existe déjà
  const [valeur, setValeur] = useState(() => {
    try {
      const stockee = localStorage.getItem(cle);
      return stockee !== null
        ? JSON.parse(stockee)
        : valeurInitiale;
    } catch {
      return valeurInitiale;
    }
  });

  // Setter qui met à jour state ET localStorage en même temps
  const setValeurStockee = (nouvelleValeur) => {
    try {
      // Accepte une valeur directe OU une fonction (comme useState)
      const valeurAStorer = nouvelleValeur instanceof Function
        ? nouvelleValeur(valeur)
        : nouvelleValeur;

      setValeur(valeurAStorer);
      localStorage.setItem(cle, JSON.stringify(valeurAStorer));
    } catch (err) {
      console.error('useLocalStorage — erreur écriture :', err);
    }
  };

  return [valeur, setValeurStockee];
  // Même signature que useState — facile à remplacer
}

export default useLocalStorage;

5.1 Utilisation

Exemples d'utilisation
import useLocalStorage from '../hooks/useLocalStorage';

// Thème persistant — survit au rechargement
function App() {
  const [theme, setTheme] = useLocalStorage('theme', 'clair');
  // Même API que useState — juste la clé en plus
}

// Préférences utilisateur
function Parametres() {
  const [langue, setLangue] =
    useLocalStorage('langue', 'fr');

  const [notifs, setNotifs] =
    useLocalStorage('notifications', true);
}

// Panier persistant

  const [articles, setArticles] =
    useLocalStorage('panier', []);
  // Le panier survive au rechargement de la page !
}

// Setter fonctionnel — comme useState
setArticles(prev => [...prev, nouvelArticle]);
Avantage clé : Le hook a exactement la même signature que useState. Pour rendre un state persistant, il suffit de remplacer useState('clair') par useLocalStorage('theme', 'clair'). Zéro refactorisation du reste du composant.

6. useDebounce — Retarder les mises à jour

Le debounce retarde l'exécution d'une action jusqu'à ce que l'utilisateur s'arrête de taper. Indispensable pour les champs de recherche : sans ça, on envoie une requête API à chaque lettre frappée.

hooks/useDebounce.js
import { useState, useEffect } from 'react';

// Retourne la valeur "retardée" — mise à jour seulement
// si l'utilisateur ne modifie plus pendant "delai" ms
function useDebounce(valeur, delai = 400) {
  const [valeurRetardee, setValeurRetardee] = useState(valeur);

  useEffect(() => {
    // Programmer la mise à jour après "delai" ms
    const timer = setTimeout(() => {
      setValeurRetardee(valeur);
    }, delai);

    // Si "valeur" change avant la fin du timer → annuler et repartir
    return () => clearTimeout(timer);
  }, [valeur, delai]);

  return valeurRetardee;
}

export default useDebounce;

6.1 Utilisation avec la recherche

Recherche avec debounce + useFetch
import useDebounce from '../hooks/useDebounce';
import useFetch    from '../hooks/useFetch';

function RechercheAvancee() {
  const [saisie, setSaisie] = useState('');

  // saisie change à chaque frappe
  // rechercheDebounced ne change qu'après 500ms sans frappe
  const rechercheDebounced = useDebounce(saisie, 500);

  // useFetch ne se relance que quand rechercheDebounced change
  const { data, loading } = useFetch(
    rechercheDebounced
      ? `https://api.exemple.com/search?q=${rechercheDebounced}`
      : null
  );

  return (
    <div>
      <input
        value={saisie}
        onChange={e => setSaisie(e.target.value)}
        placeholder="Rechercher..."
      />
      {/* Indicateur visuel */}
      {saisie !== rechercheDebounced && <span>En attente...</span>}
      {loading && <span>Recherche...</span>}
      {data && <p>{data.length} résultats</p>}
    </div>
  );
}

// Sans debounce : 10 frappes = 10 requêtes API
// Avec debounce 500ms : 10 frappes rapides = 1 requête

7. useForm — Gérer un formulaire

Un hook qui centralise la gestion d'un formulaire multi-champs : état, modification et réinitialisation en une seule ligne dans le composant.

hooks/useForm.js
import { useState } from 'react';

function useForm(valeursInitiales) {
  const [values, setValues] = useState(valeursInitiales);
  const [erreurs, setErreurs] = useState({});

  // Gestionnaire générique pour tous les champs
  // Utilise e.target.name pour cibler le bon champ
  const handleChange = (e) => {
    const { name, value, type, checked } = e.target;
    setValues(prev => ({
      ...prev,
      [name]: type === 'checkbox' ? checked : value,
    }));
    // Effacer l'erreur du champ modifié
    if (erreurs[name]) {
      setErreurs(prev => ({ ...prev, [name]: undefined }));
    }
  };

  // Réinitialiser le formulaire
  const reset = () => {
    setValues(valeursInitiales);
    setErreurs({});
  };

  // Définir des erreurs manuellement (après validation)
  const setErreur = (name, message) => {
    setErreurs(prev => ({ ...prev, [name]: message }));
  };

  return { values, erreurs, handleChange, reset, setErreur };
}

export default useForm;

7.1 Utilisation dans un composant

FormulaireContact.jsx
import useForm from '../hooks/useForm';

function FormulaireContact() {
  const { values, erreurs, handleChange, reset, setErreur } =
    useForm({ nom: '', email: '', message: '' });

  const handleSubmit = (e) => {
    e.preventDefault();

    // Validation
    if (!values.nom.trim()) {
      setErreur('nom', 'Le nom est obligatoire');
      return;
    }
    if (!values.email.includes('@')) {
      setErreur('email', 'Email invalide');
      return;
    }

    // Envoi
    console.log('Envoi :', values);
    reset();
  };

  return (
    <form onSubmit={handleSubmit}>
      <div>
        <input
          name="nom"
          value={values.nom}
          onChange={handleChange}
          placeholder="Votre nom"
        />
        {erreurs.nom && <span style={{ color: 'red' }}>{erreurs.nom}</span>}
      </div>

      <div>
        <input
          name="email"
          type="email"
          value={values.email}
          onChange={handleChange}
          placeholder="Votre email"
        />
        {erreurs.email && <span style={{ color: 'red' }}>{erreurs.email}</span>}
      </div>

      <textarea
        name="message"
        value={values.message}
        onChange={handleChange}
        placeholder="Votre message"
      />

      <button type="submit">Envoyer</button>
      <button type="button" onClick={reset}>Réinitialiser</button>
    </form>
  );
}

// Un seul handleChange pour tous les champs — grâce à name + computed property
La clé — [name]: value : La notation [e.target.name]: e.target.value utilise le nom de l'attribut name du champ comme clé de l'objet. Un seul handleChange gère tous les champs, peu importe leur nombre. Plus jamais de setNom, setEmail, setMessage séparés.

8. useWindowSize — Réagir à la taille de la fenêtre

Un hook utile pour adapter le rendu selon la taille de l'écran directement en JavaScript — utile quand du CSS seul ne suffit pas (ex. changer le nombre de colonnes dans un composant, masquer du contenu complexe).

hooks/useWindowSize.js
import { useState, useEffect } from 'react';

function useWindowSize() {
  const [taille, setTaille] = useState({
    largeur:  window.innerWidth,
    hauteur: window.innerHeight,
  });

  useEffect(() => {
    const mettreAJour = () => {
      setTaille({
        largeur:  window.innerWidth,
        hauteur: window.innerHeight,
      });
    };

    window.addEventListener('resize', mettreAJour);

    // Nettoyage — retire le listener quand le composant se démonte
    return () => window.removeEventListener('resize', mettreAJour);
  }, []); // [] = une seule fois au montage

  return taille;
}

export default useWindowSize;

8.1 Utilisation et dérivation

Utilisation dans un composant
import useWindowSize from '../hooks/useWindowSize';

function GrilleProduits({ produits }) {
  const { largeur } = useWindowSize();

  // Nombre de colonnes selon la largeur
  const colonnes = largeur > 1024 ? 4
                  : largeur >  768 ? 3
                  : largeur >  480 ? 2
                  : 1;

  return (
    <div style={{
      display: 'grid',
      gridTemplateColumns: `repeat(${colonnes}, 1fr)`,
      gap: '16px',
    }}>
      {produits.map(p => <CarteProduit key={p.id} produit={p} />)}
    </div>
  );
}

// Hook dérivé — isMobile basé sur useWindowSize
function useIsMobile(breakpoint = 768) {
  const { largeur } = useWindowSize();
  return largeur < breakpoint;
}

// Un custom hook peut appeler un autre custom hook !
function Navigation() {
  const isMobile = useIsMobile();
  return isMobile ? <NavMobile /> : <NavDesktop />;
}
Un custom hook peut appeler un autre custom hook. useIsMobile appelle useWindowSize — c'est parfaitement valide et même encouragé. On compose les hooks comme des briques LEGO pour construire des abstractions de plus en plus spécialisées.

import useLocalStorage  from '../hooks/useLocalStorage';

function Accueil() {
  const [recherche, setRecherche] = useState('');
  const [favoris, setFavoris]     = useLocalStorage('favoris', []);

  const rechercheDebounced = useDebounce(recherche, 400);

  const url = rechercheDebounced
    ? `https://api.themoviedb.org/3/search/movie?query=${rechercheDebounced}&api_key=VOTRE_CLE`
    : `https://api.themoviedb.org/3/movie/popular?api_key=VOTRE_CLE`;

  const { data, loading, erreur } = useFetch(url);

  const toggleFavori = (film) => {
    setFavoris(prev =>
      prev.find(f => f.id === film.id)
        ? prev.filter(f => f.id !== film.id)
        : [...prev, film]
    );
  };

  return (
    <div>
      <input
        value={recherche}
        onChange={e => setRecherche(e.target.value)}
        placeholder="Rechercher un film..."
      />
      {loading && <p>Chargement...</p>}
      {erreur  && <p>Erreur : {erreur}</p>}
      <GrilleFilms
        films={data?.results || []}
        favoris={favoris}
        onToggleFavori={toggleFavori}
      />
    </div>
  );
}
Ce que le projet démontre :
  • Chaque hook est indépendant et réutilisable dans n'importe quel composant
  • Modifier useFetch améliore tous les composants qui l'utilisent en même temps
  • Les composants sont épurés : ils orchestrent des hooks, ils ne contiennent plus de logique technique
  • Les hooks peuvent être testés en isolation — ce sont des fonctions pures ou quasi-pures
