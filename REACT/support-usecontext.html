1. Le problème — Prop Drilling

Avec les props, les données descendent toujours de parent vers enfant. C'est parfait pour des composants proches. Mais quand la donnée doit traverser 3, 4 ou 5 niveaux de composants, on se retrouve à passer les mêmes props partout — même dans les composants qui n'en ont pas besoin. Ce phénomène s'appelle le prop drilling.

Le prop drilling en action :
App possède utilisateur. Seul ProfilBouton (5 niveaux plus bas) en a besoin. On est obligé de passer la prop à travers tous les composants intermédiaires, même s'ils ne l'utilisent pas.
Le problème
// App.jsx — la donnée "utilisateur" vit ici
function App() {
  const [utilisateur] = useState({ nom: 'Thomas', role: 'admin' });

  return <Page utilisateur={utilisateur} />;
}

// Page.jsx — passe la prop sans l'utiliser
function Page({ utilisateur }) {
  return <Header utilisateur={utilisateur} />;
}

// Header.jsx — passe la prop sans l'utiliser
function Header({ utilisateur }) {
  return <NavBar utilisateur={utilisateur} />;
}

// NavBar.jsx — passe la prop sans l'utiliser
function NavBar({ utilisateur }) {
  return <ProfilBouton utilisateur={utilisateur} />;
}

// ProfilBouton.jsx — enfin ! C'est lui qui en avait besoin
function ProfilBouton({ utilisateur }) {
  return <button>{utilisateur.nom}</button>;
}
Prop Drilling vs useContext
Prop Drilling : App → Page → Header → NavBar → ProfilBouton. La prop "utilisateur" traverse 4 composants inutilement.
Avec useContext : App crée un contexte. ProfilBouton le lit directement. Les composants intermédiaires ne savent même pas que la donnée existe.
Analogie : Les props, c'est passer un colis de main en main dans une chaîne humaine. Le Context, c'est Amazon : tu commandes directement, le colis arrive chez toi sans passer par tes voisins.

2. Qu'est-ce que useContext ?

useContext est un Hook React qui permet de partager des données à travers toute une arborescence de composants sans passer de props manuellement à chaque niveau. On parle de state global — une donnée accessible partout dans l'application.

{ }

createContext

Crée la boîte qui va contenir et distribuer la donnée. S'écrit une seule fois, souvent dans un fichier dédié.

▼

Provider

Enveloppe les composants qui ont besoin de la donnée. Tout ce qui est à l'intérieur peut y accéder.

↳

useContext

Le Hook qui permet à un composant de lire la valeur du contexte, peu importe sa profondeur dans l'arbre.

2.1 Cas d'usage typiques

Quand utiliser useContext ?
Thème (clair / sombre) : Le thème doit être accessible dans tous les composants, du bouton jusqu'à la page entière.
Utilisateur connecté : Le nom, le rôle et l'avatar de l'utilisateur sont nécessaires dans la nav, le profil, le dashboard…
Langue / i18n : La langue choisie doit être connue de tous les composants qui affichent du texte.
Panier e-commerce : Le contenu du panier est consulté depuis la nav (badge) et la page panier (liste).
Notifications : Un système de toast/alert accessible depuis n'importe quel composant.
useContext n'est pas la solution à tout. Pour des données locales à un seul composant ou à une petite branche, les props restent la bonne approche. useContext brille quand la donnée est vraiment globale ou partagée entre des composants éloignés dans l'arbre.

3. Les 3 étapes — Mécanisme complet

useContext fonctionne toujours en 3 étapes dans le même ordre. Apprendre ces 3 étapes, c'est maîtriser useContext à 90%.

1Créer le contexte — createContext()

On crée la boîte qui va contenir la donnée. Cette ligne s'écrit en dehors de tout composant, souvent dans un fichier dédié (ex. ThemeContext.js).

ThemeContext.js
import { createContext } from 'react';

// Crée le contexte avec une valeur par défaut (optionnel)
export const ThemeContext = createContext('clair');

// La valeur par défaut est utilisée si un composant
// utilise useContext SANS être enveloppé par un Provider

2Fournir la valeur — Provider

On enveloppe les composants qui ont besoin de la donnée avec le Provider. Tous les composants à l'intérieur auront accès à la valeur fournie via value={...}.

App.jsx
import { useState } from 'react';
import { ThemeContext } from './ThemeContext';
import Page from './Page';

function App() {
  const [theme, setTheme] = useState('clair');

  return (
    {/* Tout ce qui est DANS le Provider reçoit "theme" */}
    <ThemeContext.Provider value={theme}>
      <Page />
      <button onClick={() => setTheme(theme === 'clair' ? 'sombre' : 'clair')}>
        Basculer le thème
      </button>
    </ThemeContext.Provider>
  );
}

3Consommer la valeur — useContext()

N'importe quel composant à l'intérieur du Provider peut lire la valeur avec useContext(ThemeContext) — sans recevoir de props, peu importe sa profondeur.

ProfilBouton.jsx
import { useContext } from 'react';
import { ThemeContext } from './ThemeContext';

function ProfilBouton() {
  // Lit la valeur du contexte — aucune prop nécessaire !
  const theme = useContext(ThemeContext);

  return (
    <button className={`btn-${theme}`}>
      Mon profil ({theme})
    </button>
  );
}

// ProfilBouton ne reçoit AUCUNE prop
// Il lit directement depuis le contexte
Hook : useContext — Résumé syntaxe
Syntaxe complète
import { createContext, useContext, useState } from 'react';

// Étape 1 — Créer (dans un fichier dédié)
export const MonContexte = createContext(valeurParDefaut);

// Étape 2 — Fournir (dans App.jsx ou un composant parent)
<MonContexte.Provider value={laDonnee}>
  <TousLesComposantsEnfants />
</MonContexte.Provider>

// Étape 3 — Consommer (dans n'importe quel composant enfant)
const laDonnee = useContext(MonContexte);

4. Exemple 1 — Thème Jour / Nuit

Le cas d'usage le plus classique pour apprendre useContext. L'utilisateur bascule entre un thème clair et sombre. Tous les composants adaptent leur style sans qu'on leur passe une prop theme.

4.1 Structure du projet

Structure
src/
├── context/
│   └── ThemeContext.jsx   ← Étape 1 : création du contexte
├── components/
│   ├── Navbar.jsx         ← utilise useContext
│   ├── Carte.jsx          ← utilise useContext
│   └── BoutonTheme.jsx    ← modifie le thème via le contexte
└── App.jsx                ← Étape 2 : Provider

4.2 ThemeContext.jsx

context/ThemeContext.jsx
import { createContext, useState } from 'react';

// On exporte le contexte pour que les composants puissent l'importer
export const ThemeContext = createContext();

// On crée un composant "Provider personnalisé"
// C'est une bonne pratique : ça cache la logique
export function ThemeProvider({ children }) {
  const [theme, setTheme] = useState('clair');

  const toggleTheme = () => {
    setTheme(prev => prev === 'clair' ? 'sombre' : 'clair');
  };

  // On passe les deux : la valeur ET la fonction pour la modifier
  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}
Astuce — passer un objet dans value : On peut passer plusieurs valeurs dans le contexte en les regroupant dans un objet : value={{ theme, toggleTheme }}. Le composant consommateur les déstructure ensuite avec const { theme, toggleTheme } = useContext(ThemeContext).

4.3 App.jsx — Brancher le Provider

App.jsx
import { ThemeProvider } from './context/ThemeContext';
import Navbar from './components/Navbar';
import Carte  from './components/Carte';

function App() {
  return (
    {/* ThemeProvider enveloppe TOUT — tout le monde a accès au thème */}
    <ThemeProvider>
      <Navbar />
      <main>
        <Carte />
      </main>
    </ThemeProvider>
  );
}

export default App;

5. Exemple 2 — Utilisateur connecté global

Deuxième cas d'usage très courant : rendre les infos de l'utilisateur connecté (nom, avatar, rôle) accessibles partout dans l'app — dans la nav, le dashboard, le profil — sans prop drilling.

5.1 AuthContext.jsx

context/AuthContext.jsx
import { createContext, useState, useContext } from 'react';

const AuthContext = createContext();

// Hook personnalisé — bonne pratique pour simplifier l'usage
export function useAuth() {
  return useContext(AuthContext);
}

export function AuthProvider({ children }) {
  const [utilisateur, setUtilisateur] = useState(null);

  const connexion = (nom, role) => {
    setUtilisateur({ nom, role });
  };

  const deconnexion = () => {
    setUtilisateur(null);
  };

  return (
    <AuthContext.Provider value={{ utilisateur, connexion, deconnexion }}>
      {children}
    </AuthContext.Provider>
  );
}
Le hook personnalisé useAuth() : Plutôt que d'écrire useContext(AuthContext) dans chaque composant, on crée un hook useAuth() qui fait ce travail. Le code des composants est plus lisible et si on change l'implémentation un jour, on ne modifie qu'un seul endroit.

5.2 Utilisation dans les composants

components/Navbar.jsx
import { useAuth } from '../context/AuthContext';

function Navbar() {
  const { utilisateur, deconnexion } = useAuth();

  return (
    <nav>
      <span>Mon App</span>

      {utilisateur ? (
        <div>
          <span>Bonjour, {utilisateur.nom} ({utilisateur.role})</span>
          <button onClick={deconnexion}>Se déconnecter</button>
        </div>
      ) : (
        <span>Non connecté</span>
      )}
    </nav>
  );
}

export default Navbar;
pages/Dashboard.jsx
import { useAuth } from '../context/AuthContext';

function Dashboard() {
  const { utilisateur } = useAuth();

  // Redirection si non connecté

  return (
    <div>
      <h1>Dashboard de {utilisateur.nom}</h1>

      {utilisateur.role === 'admin' && (
        <button>Panneau d'administration</button>
      )}
    </div>
  );
}

export default Dashboard;

      </button>
      <button onClick={() => connexion('Alice', 'user')}>

      </button>

6. Exemple 3 — Panier e-commerce

Cas d'usage avancé : un panier accessible depuis la barre de navigation (badge avec le nombre d'articles) ET depuis la page panier (liste des articles). Deux composants éloignés dans l'arbre qui partagent le même state.

6.1 PanierContext.jsx

context/PanierContext.jsx
import { createContext, useContext, useState } from 'react';

const PanierContext = createContext();

export function usePanier() {
  return useContext(PanierContext);
}

export function PanierProvider({ children }) {
  const [articles, setArticles] = useState([]);

  // Ajouter un article (ou incrémenter la quantité)
  const ajouterAuPanier = (produit) => {
    setArticles(prev => {
      const existe = prev.find(a => a.id === produit.id);
      if (existe) {
        return prev.map(a =>
          a.id === produit.id ? { ...a, quantite: a.quantite + 1 } : a
        );
      }
      return [...prev, { ...produit, quantite: 1 }];
    });
  };

  // Retirer un article
  const retirerDuPanier = (id) => {
    setArticles(prev => prev.filter(a => a.id !== id));
  };

  // Vider le panier
  const viderPanier = () => setArticles([]);

  // Total calculé (variable dérivée — pas un state)
  const totalArticles = articles.reduce((acc, a) => acc + a.quantite, 0);
  const prixTotal = articles.reduce((acc, a) => acc + a.prix * a.quantite, 0);

  return (
    <PanierContext.Provider value={{
      articles,
      ajouterAuPanier,
      retirerDuPanier,
      viderPanier,
      totalArticles,
      prixTotal
    }}>
      {children}
    </PanierContext.Provider>
  );
}

6.4 Page panier complète

pages/PagePanier.jsx
import { usePanier } from '../context/PanierContext';

function PagePanier() {
  const { articles, retirerDuPanier, viderPanier, prixTotal } = usePanier();

  if (articles.length === 0) {
    return <p>Votre panier est vide.</p>;
  }

  return (
    <div>
      <h2>Mon panier</h2>

      {articles.map(article => (
        <div key={article.id}>
          <span>{article.nom} x{article.quantite}</span>
          <span>{article.prix * article.quantite} €</span>
          <button onClick={() => retirerDuPanier(article.id)}>
            Supprimer
          </button>
        </div>
      ))}

      <hr />
      <strong>Total : {prixTotal.toFixed(2)} €</strong>
      <button onClick={viderPanier}>Vider le panier</button>
    </div>
  );
}

export default PagePanier;

7. Bonnes pratiques

7.1 Un fichier par contexte

Toujours créer un fichier dédié pour chaque contexte dans un dossier src/context/. Ne pas créer le contexte directement dans App.jsx.

Structure recommandée :
  • src/context/ThemeContext.jsx → contexte du thème
  • src/context/AuthContext.jsx → contexte d'authentification
  • src/context/PanierContext.jsx → contexte du panier

7.2 Exporter un hook personnalisé

Plutôt que d'exporter le contexte brut, exporter un hook useMon Contexte() qui encapsule useContext(). Les composants n'ont plus besoin d'importer le contexte, seulement le hook.

Bonne pratique
//  Moins bien — les composants doivent importer AuthContext ET useContext
export const AuthContext = createContext();
// Dans les composants : import { AuthContext } from '...' + useContext(AuthContext)

//  Mieux — les composants importent juste useAuth()
const AuthContext = createContext(); // pas exporté
export function useAuth() {
  return useContext(AuthContext);
}
// Dans les composants : import { useAuth } from '...' + useAuth()

7.3 Ajouter une vérification d'utilisation

Si un composant appelle useAuth() sans être enveloppé par AuthProvider, React ne produira pas d'erreur claire. On peut ajouter une vérification explicite.

Hook avec vérification
export function useAuth() {
  const ctx = useContext(AuthContext);

  if (ctx === undefined) {
    throw new Error('useAuth doit être utilisé à l\'intérieur de AuthProvider');
  }

  return ctx;
}

7.4 Ne pas surcharger un seul contexte

Éviter le "God Context" : Ne pas mettre toutes les données de l'app dans un seul contexte. Un contexte par domaine fonctionnel : un pour l'auth, un pour le thème, un pour le panier. Cela évite que tous les composants se re-rendent quand une seule donnée change.

8. Props vs useContext — quand choisir ?

9. Exercices

Exercice 1 — Thème jour/nuit (débutant)

Objectif : Créer un contexte de thème et l'utiliser dans 3 composants.

  1. Créer ThemeContext.jsx avec ThemeProvider et useTheme().
  2. Le Provider gère un state theme ('clair' ou 'sombre') et une fonction toggleTheme().
  3. Créer un composant BoutonTheme qui appelle toggleTheme() au clic.
  4. Créer un composant Carte qui adapte son background selon le thème.
  5. Brancher le Provider dans App.jsx.
Résultat attendu : Un clic sur BoutonTheme change l'apparence de toute l'app sans prop drilling.

Exercice 2 — Utilisateur connecté (intermédiaire)

Objectif : Simuler un système d'authentification avec useContext.

  1. Créer AuthContext.jsx avec AuthProvider et useAuth().
  2. Le state contient utilisateur (null si déconnecté, objet si connecté).
  3. Créer une page Login avec deux boutons : "Admin" et "Utilisateur".
  4. Dans la Navbar, afficher le nom de l'utilisateur connecté ou "Non connecté".
  5. Créer un composant PageProtegee qui affiche un message d'erreur si non connecté.

Exercice 3 — Combiner deux contextes (avancé)

Objectif : Utiliser deux contextes dans la même application.

  1. Reprendre l'exercice 1 (ThemeContext) et l'exercice 2 (AuthContext).
  2. Brancher les deux Providers dans App.jsx (l'un dans l'autre).
  3. Créer un composant Profil qui utilise useAuth() ET useTheme() simultanément.
  4. Le profil adapte son style au thème et affiche les infos de l'utilisateur connecté.
Indice — App.jsx
function App() {
  return (
    <AuthProvider>
      <ThemeProvider>
        <Navbar />
        <Profil />
      </ThemeProvider>
    </AuthProvider>
  );
}

10. Projet fil rouge — Mini e-commerce

Construire une mini boutique en ligne qui utilise deux contextes : un pour le thème et un pour le panier. Le projet reprend tous les concepts du cours.

10.1 Structure complète

Structure du projet
src/
├── context/
│   ├── ThemeContext.jsx   ← thème jour/nuit
│   └── PanierContext.jsx  ← panier partagé
├── components/
│   ├── Navbar.jsx         ← badge panier + bouton thème
│   ├── CarteProduit.jsx   ← affiche un produit + bouton ajout
│   └── ListeProduits.jsx  ← grille de CarteProduit
├── pages/
│   ├── Boutique.jsx       ← page principale
│   └── Panier.jsx         ← page panier avec résumé
└── App.jsx                ← Providers + Router

10.2 App.jsx final

App.jsx
import { BrowserRouter, Routes, Route } from 'react-router-dom';
import { ThemeProvider }  from './context/ThemeContext';
import { PanierProvider } from './context/PanierContext';
import Navbar    from './components/Navbar';
import Boutique  from './pages/Boutique';
import Panier    from './pages/Panier';

function App() {
  return (
    <ThemeProvider>
      <PanierProvider>
        <BrowserRouter>
          <Navbar />
          <Routes>
            <Route path="/"       element={<Boutique />} />
            <Route path="/panier" element={<Panier />}  />
          </Routes>
        </BrowserRouter>
      </PanierProvider>
    </ThemeProvider>
  );
}

export default App;
Fonctionnalités à implémenter :
  • Basculer le thème depuis la navbar — toute l'app change d'apparence
  • Ajouter un produit au panier — le badge dans la navbar se met à jour instantanément
  • Naviguer vers /panier — voir la liste des articles, quantités et total
  • Retirer un article ou vider le panier
  • Le panier persiste lors de la navigation entre les pages
Pour aller plus loin :
  • Ajouter localStorage dans PanierContext pour persister le panier après rechargement
  • Combiner avec AuthContext pour protéger la page /panier si non connecté
  • Remplacer useContext par useReducer dans PanierContext pour les actions complexes (prochain module)
