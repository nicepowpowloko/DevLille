Ce guide explique comment le projet est organisé, comment les fichiers s'emboîtent, et toutes les manipulations à faire pour le modifier.

01

Structure du projet

Voici tous les fichiers du projet et leur rôle. Comprendre ça, c'est comprendre 80% de React.

react-boutique/ │ ├── index.html POINT D'ENTRÉE ← le seul vrai fichier HTML ├── package.json ← liste les dépendances npm ├── vite.config.js ← configuration de Vite │ └── src/ ← tout le code React est ici │ ├── main.jsx MONTAGE REACT ← branche React sur index.html ├── App.jsx STATE GLOBAL ← chef d'orchestre │ ├── data/ │ └── produits.js DONNÉES ← les 6 produits │ ├── components/ ← un fichier = un composant │ ├── Header.jsx COMPOSANT ← barre de navigation │ ├── Hero.jsx COMPOSANT ← section d'accroche │ ├── Filtres.jsx COMPOSANT ← boutons de filtre │ ├── GrilleProduits.jsx COMPOSANT ← grille de cartes │ ├── CarteProduit.jsx COMPOSANT ← une carte │ ├── PanierSidebar.jsx COMPOSANT ← panneau panier │ ├── APropos.jsx COMPOSANT ← section à propos │ ├── Contact.jsx COMPOSANT ← formulaire │ └── Footer.jsx COMPOSANT ← pied de page │ └── styles/ └── index.css ← tous les styles
Règle d'or : tu ne touches jamais à index.html, main.jsx ou vite.config.js. Tout ton travail se passe dans src/.
02

Le flux React — qui appelle qui ?

React fonctionne comme une cascade. Chaque fichier appelle le suivant. Voici l'ordre exact de ce qui se passe quand le navigateur charge la page.

index.html
Le navigateur charge ce fichier en premier. Il contient juste <div id="root"></div>
Étape 1
↓ charge le script
⚙️
main.jsx
Trouve le #root et y injecte <App /> dedans
Étape 2
↓ rend les composants
App.jsx
Gère le STATE (panier, filtre). Assemble et affiche tous les composants dans l'ordre
STATE ici
↓ affiche dans l'ordre du return
<Header />
Reçoit : panier (nombre) + onOuvrirPanier (fonction)
props
↓
<Hero />
Aucune prop — contenu statique
statique
↓
<GrilleProduits />
Reçoit les produits, fait le .filter() et le .map() → génère des CarteProduit
props
↓ .map() crée une CarteProduit par produit
<CarteProduit /> × 6
Reçoit un objet produit complet + la fonction panier
props
À retenir : L'ordre des composants dans le return de App.jsx = l'ordre d'affichage sur la page. Si tu veux changer l'ordre des sections, tu bouges les lignes dans App.jsx.
03

Props & State — les deux moteurs

📦 Props — données reçues
Viennent du parent.
En lecture seule — l'enfant ne peut pas les modifier.

Exemple : CarteProduit reçoit nom, prix, image depuis GrilleProduits.
🔄 State — données internes
Vie dans le composant.
Quand il change → React re-rend automatiquement.

Exemple : App.jsx gère panier et categorie avec useState.
App.jsx — le state global
// Les données qui "pilotent" toute l'interface
const [panier,      setPanier]      = useState([])       // tableau d'articles
const [categorie,   setCategorie]   = useState('Toutes') // filtre actif
const [panierOuvert,setPanierOuvert] = useState(false)    // sidebar ouvert ?

// Ces données descendent vers les composants via les props ↓
<Header   panier={panier.length}  onOuvrirPanier={() => setPanierOuvert(true)} />
<Filtres  actif={categorie}       onChange={setCategorie}               />

05 — Manipulation 2

Ajouter un nouveau produit

2
Ajouter un objet dans le tableau src/data/produits.js

Copie-colle un objet existant à la fin du tableau, change l'id et les valeurs. Une nouvelle carte apparaît automatiquement.

produits.js — ajouter à la finnouveau
export const produits = [
  // ... produits existants ...

  // ← Ajoute cet objet à la fin, avant le ]
  {
    id: 7,                          ← id unique
    nom: "Tapis de souris XXL",
    categorie: "Accessoires",       ← doit correspondre à categories[]
    prix: 34,
    description: "80x40cm, surface lisse, bords cousus.",

    stock: 15,
    nouveaute: true,
  },
]
Une 7ème carte apparaît dans la grille — le .map() la génère automatiquement
Pourquoi ça marche tout seul ? Dans GrilleProduits.jsx, le .map() parcourt tout le tableau produits. Chaque objet devient une CarteProduit. Plus d'objets dans le tableau = plus de cartes.

08 — Manipulation 5

Ajouter du state à un composant

On va ajouter un bouton "Like" sur chaque carte produit. Chaque carte gère son propre compteur de likes indépendamment.

5
Ajouter useState dans CarteProduit src/components/CarteProduit.jsx
CarteProduit.jsxà modifier
// 1. Importer useState en haut du fichier
import { useState } from 'react'

function CarteProduit({ produit, onAjouterPanier }) {
  const { nom, prix, image, ... } = produit

  // 2. Créer le state "likes" propre à cette carte
  const [likes, setLikes] = useState(0)

  return (
    <div className="carte">
      {/* ... contenu existant ... */}

      // 3. Ajouter le bouton Like dans le JSX
      <button onClick={() => setLikes(likes + 1)}>
        {likes}
      </button>
    </div>
  )
}
Chaque carte a son propre compteur de likes — ils sont indépendants
Important : chaque instance de CarteProduit a son propre likes. Cliquer sur la carte 1 ne change pas le compteur de la carte 2. C'est le principe du state local.

Toutes les commandes terminal

Voici toutes les commandes à connaître, dans quel ordre les taper, et ce qu'elles font. Le terminal s'ouvre dans VSCode avec Ctrl+ù (ou Terminal → Nouveau terminal).

⚡ La toute première fois — installation

1️⃣
Se placer dans le bon dossier
Avant tout, le terminal doit être "dans" le projet react-boutique
1 fois
Terminal VSCode
$ cd ~/DevLille/REACT/react-boutique
↳ cd = "change directory" — se déplacer dans un dossier
↳ ~ = ton dossier personnel (/Users/thomasdarras)
↳ Le prompt affiche maintenant "react-boutique $"
Astuce Mac : tape cd (avec un espace) puis fais glisser le dossier react-boutique depuis l'explorateur VSCode directement dans le terminal. Le chemin s'écrit tout seul.
2️⃣
Installer les dépendances
Télécharge React, Vite et tous les packages listés dans package.json
1 fois par projet
Terminal VSCode
$ npm install

↳ Crée le dossier node_modules/ — ne jamais le modifier
Si tu vois "npm: command not found" → Node.js n'est pas installé. Ouvre le Terminal Mac (CMD+Espace → Terminal) et tape brew install node. Ensuite ferme et réouvre VSCode.
