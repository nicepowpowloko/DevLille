SQL & Bases de données

Maîtrise la conception, la création et l'interrogation de bases de données relationnelles — au cœur du CCP2 DWWM.

CCP2 — Back-end MySQL / MariaDB Débutant → Intermédiaire
01

C'est quoi une base de données ?

Fondamentaux

Une base de données relationnelle organise les informations dans des tables (comme des feuilles Excel), reliées entre elles par des clés. Le langage SQL (Structured Query Language) permet de créer, lire, modifier et supprimer ces données.

Analogie : une base de données, c'est comme un classeur Excel ultra-puissant. Chaque feuille = une table. Les colonnes = les champs. Les lignes = les enregistrements. SQL est le langage pour interroger et manipuler tout ça.
Table
Stocke des données du même type. Ex : table utilisateurs, table produits. Composée de lignes (enregistrements) et colonnes (champs).
Clé primaire (PRIMARY KEY)
Identifiant unique de chaque ligne. Généralement un id entier auto-incrémenté. Aucune valeur dupliquée ni NULL.
Clé étrangère (FOREIGN KEY)
Colonne qui référence la clé primaire d'une autre table. Crée le lien entre deux tables. Ex : commandes.utilisateur_id → utilisateurs.id.
CRUD
Les 4 opérations de base : Create (INSERT), Read (SELECT), Update (UPDATE), Delete (DELETE).

02

Modélisation & MCD

Avant d'écrire du SQL, on conçoit la structure des données. Le MCD (Modèle Conceptuel de Données) représente les entités et leurs relations. On distingue 3 types de cardinalités.

1️⃣ Relation 1-1 (one-to-one)
Un utilisateur a exactement un profil. Une clé étrangère dans l'une des deux tables suffit.
Relation 1-N (one-to-many)
Un auteur écrit plusieurs articles. La clé étrangère auteur_id est dans la table articles. La plus courante.
Relation N-N (many-to-many)
Un étudiant suit plusieurs cours, un cours a plusieurs étudiants. Nécessite une table de jonction : inscriptions (etudiant_id, cours_id).

03

Créer tables & base de données

SQL — création de la base et des tables 
-- Créer et sélectionner une base de données
CREATE DATABASE blog_dwwm
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

USE blog_dwwm;

Table utilisateurs
CREATE TABLE utilisateurs (
    id   INTAUTO_INCREMENT PRIMARY KEY,
    nom  VARCHAR(100)  NOT NULL,
    emailVARCHAR(255)  NOT NULL UNIQUE,
    mot_de_passe VARCHAR(255) NOT NULL,
    roleENUM('admin','user') DEFAULT 'user',
    created_at DATETIME      DEFAULT NOW()
);

-- ─── Table articles (avec clé étrangère) ───
CREATE TABLE articles (
    idINTAUTO_INCREMENT PRIMARY KEY,
    titreVARCHAR(255)  NOT NULL,
    contenuTEXT,
    utilisateur_id INTNOT NULL,
    publieBOOLEANDEFAULT FALSE,
    created_atDATETIMEDEFAULT NOW(),
    FOREIGN KEY (utilisateur_id) REFERENCES utilisateurs(id)
        ON DELETE CASCADE
);

 Types courants 
-- INT / BIGINT        → nombres entiers
-- VARCHAR(n)          → texte court (max n caractères)
-- TEXT                → texte long (articles, descriptions)
-- BOOLEAN / TINYINT(1)→ vrai/faux
-- DATETIME / TIMESTAMP→ date + heure
-- DECIMAL(10,2)       → nombres décimaux (prix)
ON DELETE CASCADE supprime automatiquement les articles quand l'utilisateur est supprimé. Utilise ON DELETE SET NULL pour conserver les enregistrements orphelins, ou ON DELETE RESTRICT pour interdire la suppression si des enregistrements liés existent.
SQL — modifier une table existante 
-- Ajouter une colonne
ALTER TABLE utilisateurs ADD COLUMN age INT;

-- Modifier le type d'une colonne
ALTER TABLE utilisateurs MODIFY COLUMN nom VARCHAR(150) NOT NULL;

-- Renommer une colonne
ALTER TABLE utilisateurs RENAME COLUMN age TO annee_naissance;

-- Supprimer une colonne
ALTER TABLE utilisateurs DROP COLUMN annee_naissance;

-- Supprimer une table entière (rréversible)
DROP TABLE IF EXISTS articles;
04

SELECT & WHERE — Lire les données

Essentiel

SELECT est la commande la plus utilisée. Elle permet de lire des données dans une ou plusieurs tables.

SQL — SELECT de base 
-- Sélectionner toutes les colonnes
SELECT * FROM utilisateurs;

-- Sélectionner des colonnes précises
SELECT nom, email FROM utilisateurs;

-- Renommer une colonne dans le résultat (alias)
SELECT nom AS "Nom complet", email AS "Adresse mail"
FROM utilisateurs;

-- Filtrer avec WHERE
SELECT * FROM utilisateurs WHERE age > 25;
SELECT * FROM utilisateurs WHERE nom = 'Alice Martin';

-- Opérateurs logiques
SELECT * FROM utilisateurs
WHERE age > 18 AND role = 'admin';

SELECT * FROM utilisateurs
WHERE role = 'admin' OR role = 'moderateur';

-- IN : plusieurs valeurs possibles
SELECT * FROM utilisateurs
WHERE role IN ('admin', 'moderateur');

-- LIKE : recherche partielle
SELECT * FROM utilisateurs
WHERE email LIKE '%@gmail.com';  -- se termine par @gmail.com

-- BETWEEN : intervalle
SELECT * FROM utilisateurs
WHERE age BETWEEN 20 AND 35;

-- IS NULL / IS NOT NULL
SELECT * FROM utilisateurs WHERE age IS NULL;

-- Trier les résultats
SELECT * FROM utilisateurs ORDER BY nom ASC;
SELECT * FROM utilisateurs ORDER BY created_at DESC;

-- Limiter le nombre de résultats
SELECT * FROM articles ORDER BY created_at DESC LIMIT 10;

-- Pagination (page 2, 10 résultats par page)
SELECT * FROM articles LIMIT 10 OFFSET 10;
05

Fonctions d'agrégation & GROUP BY

Les fonctions d'agrégation calculent une valeur à partir d'un ensemble de lignes. GROUP BY regroupe les lignes par valeur d'une colonne pour appliquer ces fonctions par groupe.

SQL — fonctions et groupements 
-- Fonctions d'agrégation de base
SELECT
    COUNT(*)       AS total_utilisateurs,
    COUNT(age)    AS utilisateurs_avec_age,  -- ignore les NULL
    AVG(age)      AS age_moyen,
    MIN(age)      AS age_min,
    MAX(age)      AS age_max,
    SUM(age)      AS somme_ages
FROM utilisateurs;

-- GROUP BY : compter les articles par utilisateur
SELECT
    utilisateur_id,
    COUNT(*) AS nb_articles
FROM articles
GROUP BY utilisateur_id;

-- HAVING : filtrer APRÈS regroupement (≠ WHERE qui filtre avant)
SELECT
    utilisateur_id,
    COUNT(*) AS nb_articles
FROM articles
GROUP BY utilisateur_id
HAVING COUNT(*) > 5;   -- uniquement les auteurs prolixes

-- Fonctions sur les chaînes
SELECT
    UPPER(nom)                AS nom_majuscule,
    LOWER(email)              AS email_minuscule,
    LENGTH(nom)               AS longueur_nom,
    CONCAT(prenom, ' ', nom) AS nom_complet
FROM utilisateurs;

-- Fonctions sur les dates
SELECT
    NOW()                            AS maintenant,
    DATE_FORMAT(created_at, '%d/%m/%Y') AS date_fr,
    YEAR(created_at)                 AS annee
FROM articles;
06

Les jointures (JOIN)

Clé du CCP2

Les jointures permettent de combiner des données de plusieurs tables en une seule requête. C'est le cœur des bases de données relationnelles. Comprendre les JOIN est indispensable pour l'examen CCP2.

// Types de JOIN les plus courants
⬤ ∩ ⬤
INNER JOIN
Uniquement les lignes qui correspondent dans les deux tables
⬛ ∩ ⬤
LEFT JOIN
Toutes les lignes de la table gauche + correspondances droite (NULL si absent)
⬤ ∩ ⬛
RIGHT JOIN
Toutes les lignes de la table droite + correspondances gauche (NULL si absent)
SQL — exemples de JOIN 
-- INNER JOIN : articles avec le nom de leur auteur
SELECT
    articles.titre,
    utilisateurs.nom AS auteur,
    articles.created_at
FROM articles
INNER JOIN utilisateurs
    ON articles.utilisateur_id = utilisateurs.id;

-- Version avec alias de tables (plus lisible)
SELECT
    a.titre,
    u.nom   AS auteur,
    a.created_at
FROM articles   a
INNER JOIN utilisateurs u
    ON a.utilisateur_id = u.id
WHERE a.publie = TRUE
ORDER BY a.created_at DESC;

-- LEFT JOIN : TOUS les utilisateurs, même sans articles
SELECT
    u.nom,
    COUNT(a.id) AS nb_articles
FROM utilisateurs u
LEFT JOIN articles a
    ON u.id = a.utilisateur_id
GROUP BY u.id, u.nom
ORDER BY nb_articles DESC;

-- JOIN sur 3 tables (commandes, clients, produits)
SELECT
    c.id AS commande,
    u.nom AS client,
    p.nom AS produit,
    c.quantite
FROM commandes       c
INNER JOIN utilisateurs u ON c.utilisateur_id = u.id
INNER JOIN produits    p ON c.produit_id     = p.id;
🧠
Astuce mémoire : commence toujours par la table principale (FROM), puis joins les tables liées. Le ON relie toujours une clé étrangère à sa clé primaire. LEFT JOIN = "je veux TOUT de la gauche, même si rien à droite".

INSERT — Insérer des données

SQL — INSERT 
-- Insérer une seule ligne
INSERT INTO utilisateurs (nom, email, mot_de_passe, role)
VALUES ('Alice Martin', 'alice@mail.fr', 'hash_bcrypt_ici', 'user');

-- Insérer plusieurs lignes en une seule requête
INSERT INTO utilisateurs (nom, email, mot_de_passe)
VALUES
    ('Bob Dupont',    'bob@mail.fr',    'hash1'),
    ('Claire Blanc', 'claire@mail.fr', 'hash2'),
    ('David Roy',    'david@mail.fr',  'hash3');

-- Récupérer l'id du dernier INSERT
SELECT LAST_INSERT_ID();
-- En PHP/PDO : $pdo->lastInsertId()

-- INSERT ou UPDATE si doublon (clé unique)
INSERT INTO utilisateurs (email, nom)
VALUES ('alice@mail.fr', 'Alice Dupont')
ON DUPLICATE KEY UPDATE nom = 'Alice Dupont';
08

UPDATE & DELETE

SQL — modifier et supprimer des données 
-- Modifier un enregistrement
UPDATE utilisateurs
SET nom = 'Alice Dupont', role = 'admin'
WHERE id = 1;

-- Modifier plusieurs enregistrements
UPDATE articles
SET publie = TRUE
WHERE created_at < '2024-01-01';

-- Supprimer un enregistrement
DELETE FROM utilisateurs WHERE id = 3;

-- Vider une table (plus rapide que DELETE sans WHERE)
TRUNCATE TABLE sessions;
🚨
DANGER : ne jamais faire UPDATE ou DELETE sans WHERE ! DELETE FROM utilisateurs; supprime TOUS les enregistrements. Bonne pratique : toujours tester le WHERE avec un SELECT avant de lancer l'UPDATE/DELETE.
09

Relations & clés étrangères

Les clés étrangères garantissent l'intégrité référentielle : on ne peut pas créer un article avec un utilisateur_id qui n'existe pas. Voici un exemple de schéma complet e-commerce.

SQL — schéma e-commerce avec N-N via table de jonction 
CREATE TABLE clients (
    id    INT AUTO_INCREMENT PRIMARY KEY,
    nom   VARCHAR(100) NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL
);

CREATE TABLE produits (
    id    INT AUTO_INCREMENT PRIMARY KEY,
    nom   VARCHAR(255) NOT NULL,
    prix  DECIMAL(10,2) NOT NULL
);

CREATE TABLE commandes (
    id         INT AUTO_INCREMENT PRIMARY KEY,
    client_id  INT NOT NULL,
    created_at DATETIME DEFAULT NOW(),
    FOREIGN KEY (client_id) REFERENCES clients(id) ON DELETE CASCADE
);

-- Table de jonction N-N : une commande a plusieurs produits
CREATE TABLE commande_produits (
    commande_id INT NOT NULL,
    produit_id  INT NOT NULL,
    quantite    INT DEFAULT 1,
    PRIMARY KEY (commande_id, produit_id),  -- clé composée
    FOREIGN KEY (commande_id) REFERENCES commandes(id) ON DELETE CASCADE,
    FOREIGN KEY (produit_id)  REFERENCES produits(id)
);

Sous-requêtes

Une sous-requête est une requête SQL imbriquée dans une autre. Utile quand un JOIN devient trop complexe ou qu'on veut filtrer sur un résultat calculé.

SQL — sous-requêtes 
-- Trouver les utilisateurs qui ont écrit au moins un article
SELECT nom FROM utilisateurs
WHERE id IN (
    SELECT DISTINCT utilisateur_id FROM articles
);

-- Utilisateurs qui ont plus d'articles que la moyenne
SELECT utilisateur_id, COUNT(*) AS nb
FROM articles
GROUP BY utilisateur_id
HAVING COUNT(*) > (
    SELECT AVG(cnt)
    FROM (SELECT COUNT(*) AS cnt FROM articles GROUP BY utilisateur_id) sub
);

-- EXISTS : vérifier qu'au moins une ligne correspond
SELECT nom FROM utilisateurs u
WHERE EXISTS (
    SELECT 1 FROM articles a
    WHERE a.utilisateur_id = u.id
    AND a.publie = TRUE
);

PHP & PDO — Connecter sa BDD

Pont vers le PHP

PDO (PHP Data Objects) est la façon moderne et sécurisée de communiquer avec une base de données depuis PHP. Les requêtes préparées protègent contre les injections SQL.

🔒
JAMAIS ça : $sql = "SELECT * FROM users WHERE id = " . $_GET['id']; → injection SQL garantie ! Utilise TOUJOURS les requêtes préparées avec des ? ou des paramètres nommés.
PHP — connexion PDO et requêtes préparées 
// ─── Connexion ───
<?php
$dsn = 'mysql:host=localhost;dbname=blog_dwwm;charset=utf8mb4';
$options = [
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
    PDO::ATTR_EMULATE_PREPARES   => false,
];

try {
    $pdo = new PDO($dsn, 'root', 'mot_de_passe', $options);
} catch (PDOException $e) {
    die('Connexion échouée : ' . $e->getMessage());
}

// ─── SELECT avec paramètre ───
$stmt = $pdo->prepare(
    "SELECT * FROM utilisateurs WHERE role = :role ORDER BY nom"
);
$stmt->execute([':role' => 'admin']);
$admins = $stmt->fetchAll();  // tableau de tous les résultats

// ─── SELECT une seule ligne ───
$stmt = $pdo->prepare("SELECT * FROM utilisateurs WHERE id = ?");
$stmt->execute([$_GET['id']]);
$user = $stmt->fetch();  // une seule ligne (false si introuvable)

// ─── INSERT ───
$stmt = $pdo->prepare(
    "INSERT INTO utilisateurs (nom, email, mot_de_passe)
     VALUES (:nom, :email, :mdp)"
);
$stmt->execute([
    ':nom'   => $_POST['nom'],
    ':email' => $_POST['email'],
    ':mdp'   => password_hash($_POST['mdp'], PASSWORD_BCRYPT),
]);
$newId = $pdo->lastInsertId();

// ─── UPDATE ───
$stmt = $pdo->prepare(
    "UPDATE utilisateurs SET nom = :nom WHERE id = :id"
);
$stmt->execute([':nom' => 'Nouveau nom', ':id' => 1]);
$nbLignes = $stmt->rowCount();  // nombre de lignes affectées

// ─── DELETE ───
$stmt = $pdo->prepare("DELETE FROM utilisateurs WHERE id = ?");
$stmt->execute([$id]);
📁
Bonne pratique : mets ta connexion PDO dans un fichier séparé config/database.php et utilise require_once pour l'inclure. N'oublie pas de mettre ce fichier dans ton .gitignore et d'utiliser des variables d'environnement pour les identifiants.
