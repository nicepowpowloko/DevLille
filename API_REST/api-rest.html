1. Qu'est-ce qu'une API REST ?

1.1 Définitions

API = Application Programming Interface

Une interface qui permet à deux applications de communiquer entre elles.

REST = Representational State Transfer

Un style d'architecture pour créer des services web basés sur le protocole HTTP.

Analogie du Restaurant

Le menu = la documentation de l'API

Le serveur = l'API REST (intermédiaire)

La cuisine = le serveur/base de données

Ta commande = ta requête HTTP

Le plat servi = la réponse JSON

1.2 Caractéristiques d'une API REST

  • Utilise les méthodes HTTP (GET, POST, PUT, DELETE)
  • Retourne des données au format JSON (ou XML)
  • Est stateless (sans état) : chaque requête est indépendante
  • Utilise des URLs pour identifier les ressources
  • Les données sont organisées en ressources

1.3 Anatomie d'une requête API

Structure d'une URL d'API
https://api.example.com/v1/users/123
https:// Protocole sécurisé
api.example.com Domaine de l'API
/v1 Version de l'API
/users Ressource (collection)
/123 Identifiant unique de la ressource

2. Les Méthodes HTTP (Verbes REST)

2.1 Vue d'ensemble

Méthode Action Exemple Idempotent
GET Lire des données Récupérer la liste des utilisateurs Oui
POST Créer des données Ajouter un nouvel utilisateur Non
PUT Modifier complètement Remplacer tous les champs d'un utilisateur Oui
PATCH Modifier partiellement Modifier uniquement l'email Non
DELETE Supprimer Supprimer un utilisateur Oui
Idempotent : Une opération est idempotente si elle produit le même résultat peu importe le nombre de fois qu'elle est exécutée.

2.2 Correspondance CRUD

CRUD et Méthodes HTTP
Create (Créer) : POST
Read (Lire) : GET
Update (Mettre à jour) : PUT / PATCH
Delete (Supprimer) : DELETE

2.3 Codes de statut HTTP

Code Signification Description
200 OK Requête réussie
201 Created Ressource créée avec succès
204 No Content Succès mais pas de contenu à retourner
400 Bad Request Requête invalide (erreur de syntaxe)
401 Unauthorized Authentification requise
403 Forbidden Accès interdit (pas les droits)
404 Not Found Ressource introuvable
500 Internal Server Error Erreur du serveur

3. L'API Fetch en JavaScript

3.1 Syntaxe de base

fetch(url, options)
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error('Erreur:', error));

3.2 Méthode GET (Récupérer des données)

Syntaxe simple

// GET est la méthode par défaut
fetch('https://jsonplaceholder.typicode.com/users')
  .then(response => response.json())
  .then(users => {
    console.log(users);
  })
  .catch(error => {
    console.error('Erreur:', error);
  });

Avec async/await (recommandé)

async function getUsers() {
  try {
    const response = await fetch('https://jsonplaceholder.typicode.com/users');
    
    // Vérifier si la requête a réussi
    if (!response.ok) {
      throw new Error(`Erreur HTTP: ${response.status}`);
    }
    
    const users = await response.json();
    console.log(users);
  } catch (error) {
    console.error('Erreur:', error);
  }
}

getUsers();
Flux d'exécution de fetch()
1. Envoi : fetch() envoie la requête HTTP au serveur
2. Réception : Le serveur traite la requête et renvoie une réponse
3. Response : fetch() retourne un objet Response
4. Conversion : response.json() convertit les données en objet JavaScript
5. Utilisation : Les données sont exploitables dans le code

3.3 Méthode POST (Créer des données)

async function createUser() {
  const newUser = {
    name: 'Thomas',
    email: '[email protected]',
    phone: '0123456789'
  };

  try {
    const response = await fetch('https://jsonplaceholder.typicode.com/users', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json'
      },
      body: JSON.stringify(newUser)
    });

    if (!response.ok) {
      throw new Error(`Erreur HTTP: ${response.status}`);
    }

    const data = await response.json();
    console.log('Utilisateur créé:', data);
  } catch (error) {
    console.error('Erreur:', error);
  }
}

createUser();
Important :
  • headers : Indique que nous envoyons du JSON
  • JSON.stringify() : Convertit l'objet JavaScript en chaîne JSON
  • body : Contient les données à envoyer

6. Gestion des Erreurs

6.1 Vérification du statut HTTP

async function fetchWithErrorHandling(url) {
    try {
        const response = await fetch(url);
        
        // Vérifier le statut HTTP
        if (!response.ok) {
            throw new Error(`Erreur HTTP: ${response.status} - ${response.statusText}`);
        }
        
        const data = await response.json();
        return data;
        
    } catch (error) {
        // Différents types d'erreurs
        if (error.name === 'TypeError') {
            console.error('Erreur réseau ou CORS:', error.message);
        } else {
            console.error('Erreur:', error.message);
        }
        throw error;
    }
}

6.2 Gestion des timeouts

async function fetchWithTimeout(url, timeout = 5000) {
    const controller = new AbortController();
    const timeoutId = setTimeout(() => controller.abort(), timeout);
    
    try {
        const response = await fetch(url, {
            signal: controller.signal
        });
        
        clearTimeout(timeoutId);
        
        if (!response.ok) {
            throw new Error(`Erreur HTTP: ${response.status}`);
        }
        
        return await response.json();
        
    } catch (error) {
        if (error.name === 'AbortError') {
            throw new Error('Délai d\'attente dépassé');
        }
        throw error;
    }
}

6.3 Pattern de gestion d'erreur complet

async function safeAPICall(url, options = {}) {
    const defaultOptions = {
        method: 'GET',
        headers: {
            'Content-Type': 'application/json'
        },
        timeout: 10000
    };
    
    const finalOptions = { ...defaultOptions, ...options };
    const controller = new AbortController();
    const timeoutId = setTimeout(() => controller.abort(), finalOptions.timeout);
    
    try {
        const response = await fetch(url, {
            ...finalOptions,
            signal: controller.signal
        });
        
        clearTimeout(timeoutId);
        
        // Vérifier le statut
        if (!response.ok) {
            const errorData = await response.json().catch(() => ({}));
            throw new Error(errorData.message || `Erreur HTTP: ${response.status}`);
        }
        
        // Parser la réponse
        const contentType = response.headers.get('content-type');
        if (contentType && contentType.includes('application/json')) {
            return await response.json();
        } else {
            return await response.text();
        }
        
    } catch (error) {
        if (error.name === 'AbortError') {
            throw new Error('Requête annulée : délai dépassé');
        }
        if (error.name === 'TypeError') {
            throw new Error('Erreur réseau : impossible de contacter le serveur');
        }
        throw error;
    }
}

// Utilisation
try {
    const data = await safeAPICall('https://api.example.com/data');
    console.log(data);
} catch (error) {
    console.error('Erreur lors de l\'appel API:', error.message);
}

6.4 Affichage des erreurs à l'utilisateur

function displayError(container, error) {
    const errorMessages = {
        400: 'Requête invalide. Vérifiez les données envoyées.',
        401: 'Vous devez vous connecter pour accéder à cette ressource.',
        403: 'Accès refusé. Vous n\'avez pas les droits nécessaires.',
        404: 'Ressource introuvable.',
        500: 'Erreur serveur. Réessayez plus tard.',
        default: 'Une erreur est survenue. Veuillez réessayer.'
    };
    
    const statusCode = parseInt(error.message.match(/\d{3}/)?.[0]);
    const message = errorMessages[statusCode] || errorMessages.default;
    
    container.innerHTML = `
        <div style="background-color: #f8d7da; 
                    border: 1px solid #dc3545; 
                    padding: 15px; 
                    border-radius: 5px; 
                    color: #721c24;">
            <strong>Erreur</strong>
            <p>${message}</p>
            <p style="font-size: 0.9em; margin-top: 10px;">
                Détails techniques : ${error.message}
            </p>
        </div>
    `;
}

8. Récapitulatif

Points clés à retenir

  • Une API REST permet la communication entre applications via HTTP
  • Les méthodes HTTP correspondent aux opérations CRUD
  • fetch() est l'API native JavaScript pour consommer des APIs
  • Toujours utiliser async/await pour un code plus lisible
  • Toujours gérer les erreurs avec try/catch
  • Vérifier le statut HTTP avec response.ok
  • Convertir la réponse avec response.json()
  • Utiliser JSON.stringify() pour envoyer des données

Template réutilisable

// Template générique pour consommer une API
async function callAPI(url, method = 'GET', data = null) {
    const options = {
        method: method,
        headers: {
            'Content-Type': 'application/json'
        }
    };
    
    if (data && method !== 'GET') {
        options.body = JSON.stringify(data);
    }
    
    try {
        const response = await fetch(url, options);
        
        if (!response.ok) {
            throw new Error(`Erreur HTTP: ${response.status}`);
        }
        
        // Vérifier s'il y a un contenu (204 No Content)
        if (response.status === 204) {
            return null;
        }
        
        return await response.json();
        
    } catch (error) {
        console.error('Erreur API:', error);
        throw error;
    }
}

// Exemples d'utilisation
const users = await callAPI('https://api.example.com/users');
const newUser = await callAPI('https://api.example.com/users', 'POST', { name: 'Thomas' });
const updatedUser = await callAPI('https://api.example.com/users/1', 'PUT', { name: 'Thomas D.' });
await callAPI('https://api.example.com/users/1', 'DELETE');

9. Schémas Fonctionnels : Comprendre le Flux d'une API

9.1 Vue d'ensemble : De la requête à la réponse

Flux complet d'une requête API
Étape 1 : CLIENT L'utilisateur clique sur un bouton ou remplit un formulaire dans votre application web
Étape 2 : JAVASCRIPT Votre code JavaScript utilise fetch() pour créer une requête HTTP
Étape 3 : NAVIGATEUR Le navigateur envoie la requête HTTP à travers Internet vers le serveur API
Étape 4 : SERVEUR API Le serveur reçoit la requête et l'analyse (méthode, URL, headers, body)
Étape 5 : TRAITEMENT Le serveur traite la requête : vérifie les droits, accède à la base de données
Étape 6 : BASE DE DONNÉES La base de données retourne les données demandées au serveur
Étape 7 : FORMATAGE Le serveur formate les données en JSON et prépare la réponse HTTP
Étape 8 : RÉPONSE HTTP Le serveur envoie la réponse (code statut + données JSON) au client
Étape 9 : RÉCEPTION Le navigateur reçoit la réponse et la transmet à JavaScript
Étape 10 : PARSING JavaScript convertit le JSON en objet JavaScript (.json())
Étape 11 : AFFICHAGE Votre code utilise les données pour mettre à jour l'interface utilisateur

9.3 Schéma : Méthodes HTTP et leurs actions

Cycle de vie d'une ressource avec les méthodes HTTP
CRÉATION (POST) : Client envoie des données → Serveur crée une ressource → Retourne statut 201 + nouvelle ressource
LECTURE (GET) : Client demande une ressource → Serveur cherche dans la BDD → Retourne statut 200 + ressource
MODIFICATION (PUT/PATCH) : Client envoie modifications → Serveur met à jour la BDD → Retourne statut 200 + ressource modifiée
SUPPRESSION (DELETE) : Client demande suppression → Serveur supprime de la BDD → Retourne statut 204 (pas de contenu)

9.4 Schéma : Gestion des erreurs

Parcours d'une requête avec gestion d'erreurs
Point de départ : fetch() est appelé avec une URL
Vérification 1 : Le serveur est-il accessible ? NON → Erreur réseau (TypeError)
Vérification 2 : Le serveur répond ? OUI → On reçoit un objet Response
Vérification 3 : Le statut HTTP est-il OK (200-299) ? NON → Erreur métier (400, 404, 500...)
Vérification 4 : Le contenu est-il du JSON valide ? NON → Erreur de parsing
Succès : Toutes les vérifications passent → Données utilisables

9.5 Schéma : Anatomie d'une requête POST

fetch('https://api.example.com/users', {
    method: 'POST',           // Indique qu'on CRÉE
    headers: {                // Métadonnées de la requête
        'Content-Type': 'application/json'  // Format des données
    },
    body: JSON.stringify({    // Données à envoyer (converties en JSON)
        name: 'Thomas',
        email: '[email protected]'
    })
})
Décomposition d'une requête POST
URL : Identifie la ressource (collection /users)
Méthode (POST) : Indique l'action à effectuer (créer)
Headers : Informations sur la requête (type de contenu, authentification)
Body : Les données à envoyer au serveur (objet JavaScript converti en JSON)
Serveur traite : Validation → Sauvegarde en BDD → Génération d'un ID
Réponse : Statut 201 Created + objet créé avec son nouvel ID

9.6 Schéma : Authentification avec API

Flux d'authentification typique
1. Inscription/Connexion : L'utilisateur s'authentifie avec email/mot de passe
2. Génération du token : Le serveur valide les identifiants et génère un JWT (token)
3. Stockage client : Le client stocke le token (localStorage, sessionStorage, cookie)
4. Requêtes sécurisées : Chaque requête inclut le token dans le header Authorization
5. Vérification serveur : Le serveur vérifie le token avant de traiter la requête
6. Réponse : Si token valide → Données, sinon → Erreur 401 Unauthorized 
// Exemple de requête avec authentification
const token = localStorage.getItem('authToken');

fetch('https://api.example.com/profile', {
    method: 'GET',
    headers: {
        'Authorization': `Bearer ${token}`,
        'Content-Type': 'application/json'
    }
})

9.7 Schéma : Cycle complet d'une application CRUD

Application de gestion d'utilisateurs - Cycle complet
Chargement initial : GET /users → Affiche liste des utilisateurs
Action : Créer : Utilisateur remplit formulaire → POST /users → Nouvel utilisateur ajouté → Rafraîchir liste
Action : Consulter : Utilisateur clique sur un nom → GET /users/123 → Affiche détails
Action : Modifier : Utilisateur édite formulaire → PUT /users/123 → Utilisateur modifié → Rafraîchir affichage
Action : Supprimer : Utilisateur confirme suppression → DELETE /users/123 → Utilisateur supprimé → Rafraîchir liste
À retenir : Chaque action de l'utilisateur déclenche une requête HTTP appropriée, le serveur traite la requête, modifie la base de données si nécessaire, et renvoie une réponse. Votre JavaScript met ensuite à jour l'interface en fonction de cette réponse.
