Introduction à Linux

Qu'est-ce que Linux ?

Linux est un système d'exploitation open-source basé sur Unix, largement utilisé pour les serveurs, le cloud computing et les systèmes embarqués.

Architecture Linux

Structure du système

  • Kernel (Noyau) : Cœur du système, gère matériel et ressources
  • Shell : Interface en ligne de commande (bash, zsh, fish)
  • Système de fichiers : Tout est fichier sous Linux
  • Processus : Programmes en cours d'exécution

Comprendre les permissions

Format des permissions

-rwxr-xr-- 1 thomas developpeurs 4096 Jan 15 10:30 script.sh │││││││││ │└┬┘└┬┘└┬┘ │ │ │ └─> Autres (others) : r-- (lecture seulement) │ │ └────> Groupe : r-x (lecture + exécution) │ └───────> Propriétaire : rwx (lecture + écriture + exécution) └─────────> Type : - (fichier), d (dossier), l (lien)

Types de permissions

Permission Symbole Valeur Fichier Dossier
Lecture r 4 Lire le contenu Lister les fichiers
Écriture w 2 Modifier le fichier Créer/supprimer fichiers
Exécution x 1 Exécuter le fichier Entrer dans le dossier

Notation octale

# Calcul : r(4) + w(2) + x(1) rwx = 4 + 2 + 1 = 7 rw- = 4 + 2 + 0 = 6 r-x = 4 + 0 + 1 = 5 r-- = 4 + 0 + 0 = 4 -wx = 0 + 2 + 1 = 3 -w- = 0 + 2 + 0 = 2 --x = 0 + 0 + 1 = 1 --- = 0 + 0 + 0 = 0 # Exemples de chmod chmod 755 script.sh # rwxr-xr-x (propriétaire tout, autres lecture+exec) chmod 644 fichier.txt # rw-r--r-- (propriétaire rw, autres lecture) chmod 600 cle.pem # rw------- (propriétaire seulement) chmod 777 public/ # rwxrwxrwx (tout le monde tout - DANGEREUX!)

Modifier les permissions

# Notation symbolique chmod u+x script.sh # Ajouter exécution pour user chmod g+w fichier.txt # Ajouter écriture pour groupe chmod o-r secret.txt # Retirer lecture pour others chmod a+x script.sh # Ajouter exécution pour all # Notation octale chmod 755 script.sh # rwxr-xr-x chmod 644 config.txt # rw-r--r-- # Récursif chmod -R 755 /var/www/html/ # Tous les fichiers/dossiers # Combinaisons chmod u=rwx,g=rx,o=r fichier # Définir précisément

Changer propriétaire et groupe

# Changer le propriétaire sudo chown thomas fichier.txt # Changer propriétaire et groupe sudo chown thomas:developpeurs fichier.txt # Changer seulement le groupe sudo chgrp developpeurs fichier.txt # Récursif sudo chown -R www-data:www-data /var/www/html/ # Exemples pratiques sudo chown thomas:www-data /var/www/monsite/ sudo chmod 755 /var/www/monsite/

Permissions spéciales

SUID (Set User ID) - 4xxx

Le fichier s'exécute avec les droits du propriétaire

chmod 4755 /usr/bin/passwd # -rwsr-xr-x (le 's' remplace le 'x')

SGID (Set Group ID) - 2xxx

Les fichiers créés héritent du groupe du dossier

chmod 2775 /var/www/shared/ # drwxrwsr-x

Sticky Bit - 1xxx

Seul le propriétaire peut supprimer ses fichiers

chmod 1777 /tmp/ # drwxrwxrwt (le 't' à la fin)

Scénarios pratiques

Serveur web (Nginx/Apache)

# Structure sudo chown -R www-data:www-data /var/www/html/ sudo find /var/www/html/ -type d -exec chmod 755 {} \; sudo find /var/www/html/ -type f -exec chmod 644 {} \; # Dossier uploads (écriture web) sudo chmod 775 /var/www/html/uploads/

Scripts d'administration

# Propriétaire seulement chmod 700 ~/scripts/backup.sh # Exécutable par le groupe chmod 750 /opt/scripts/deploy.sh sudo chown root:admins /opt/scripts/deploy.sh

Fichiers de configuration sensibles

# Lecture seule propriétaire chmod 600 ~/.ssh/id_rsa chmod 600 /etc/mysql/mysql.conf.d/credentials.cnf # Lecture propriétaire et groupe chmod 640 /etc/nginx/sites-available/default

Vérifier les permissions

# Permissions détaillées ls -l fichier.txt # Voir qui peut accéder namei -l /var/www/html/index.php # Permissions effectives getfacl fichier.txt

Erreurs courantes à éviter :

  • chmod 777 : JAMAIS en production ! Risque de sécurité majeur
  • chown -R root:root / : Ne JAMAIS faire sur la racine !
  • Permissions trop restrictives sur les clés SSH (doivent être 600 ou 400)
  • Oublier le -R pour les changements récursifs

Bonnes pratiques :

  • Principe du moindre privilège : donner uniquement les droits nécessaires
  • Documenter les permissions spéciales
  • Utiliser des groupes pour gérer les accès collectifs
  • Vérifier régulièrement les permissions des fichiers sensibles
  • Utiliser sudo au lieu de se connecter en root

Windows Server 2022

Qu'est-ce que Windows Server ?

Windows Server est un système d'exploitation serveur de Microsoft, optimisé pour gérer des réseaux d'entreprise, héberger des applications et services, et administrer des infrastructures IT.

Éditions Windows Server 2022

Édition Caractéristiques Usage

  • File and Storage Services : Partage de fichiers et stockage
  • Web Server (IIS) : Hébergement de sites web
  • Remote Desktop Services : Accès distant aux applications
  • Hyper-V : Virtualisation

Active Directory (AD DS)

Qu'est-ce qu'Active Directory ?

Active Directory Domain Services (AD DS) est un service d'annuaire de Microsoft permettant la gestion centralisée des utilisateurs, ordinateurs, groupes et ressources réseau dans un domaine Windows.

Concepts fondamentaux

  • Domaine : Unité administrative de base (ex: entreprise.local)
  • Forêt : Collection de domaines partageant le même schéma
  • Arbre : Hiérarchie de domaines partageant un espace de noms
  • OU (Organizational Unit) : Container pour organiser objets
  • Contrôleur de domaine (DC) : Serveur hébergeant AD
  • GPO (Group Policy Object) : Politique de groupe
  • Schema : Définition des objets et attributs

Installation d'Active Directory

# PowerShell - Installer le rôle AD DS Install-WindowsFeature -Name AD-Domain-Services -IncludeManagementTools # Promouvoir le serveur en contrôleur de domaine Install-ADDSForest ` -DomainName "entreprise.local" ` -DomainNetbiosName "ENTREPRISE" ` -ForestMode "WinThreshold" ` -DomainMode "WinThreshold" ` -InstallDns:$true ` -Force:$true # Le serveur redémarre automatiquement

Recommandations :

  • Utilisez une IP fixe pour le contrôleur de domaine
  • Configurez DNS correctement (critique pour AD)
  • Choisissez un nom de domaine en .local ou .lan (pas .com en interne)
  • Planifiez toujours au moins 2 DC pour la redondance

Protocoles couche Transport

TCP (Transmission Control Protocol)

  • Fiable : Garantit la livraison des paquets
  • Orienté connexion : Établit une connexion (3-way handshake)
  • Contrôle de flux : Adapte le débit
  • Ordre garanti : Les données arrivent dans l'ordre
  • Plus lent qu'UDP
  • Usage : HTTP, HTTPS, FTP, SSH, SMTP
# 3-Way Handshake TCP Client → Serveur : SYN (demande de connexion) Serveur → Client : SYN-ACK (acceptation) Client → Serveur : ACK (confirmation) → Connexion établie

UDP (User Datagram Protocol)

  • Rapide : Pas de vérification
  • Léger : Faible overhead
  • Non fiable : Pas de garantie de livraison
  • Sans connexion : Envoie directement
  • Pas d'ordre : Peut arriver dans le désordre
  • Usage : DNS, DHCP, streaming vidéo, jeux en ligne

Kubernetes - Orchestration de conteneurs

Qu'est-ce que Kubernetes (K8s) ?

Kubernetes est une plateforme open-source d'orchestration de conteneurs qui automatise le déploiement, la mise à l'échelle et la gestion d'applications conteneurisées.

Pourquoi Kubernetes ?

Problèmes sans orchestration

  • Déploiement manuel de conteneurs sur plusieurs serveurs
  • Pas de redémarrage automatique en cas de crash
  • Mise à l'échelle manuelle fastidieuse
  • Pas de load balancing automatique
  • Gestion des mises à jour complexe

Solutions avec Kubernetes

  • Déploiement automatisé et déclaratif
  • Auto-healing (redémarre les conteneurs crashés)
  • Auto-scaling horizontal
  • Load balancing intégré
  • Rolling updates et rollbacks
  • Gestion des secrets et configurations

Architecture Kubernetes

Control Plane (Master)

  • API Server : Point d'entrée, gère les requêtes
  • etcd : Base de données clé-valeur (état du cluster)
  • Scheduler : Place les pods sur les nœuds
  • Controller Manager : Gère les contrôleurs (Deployment, ReplicaSet, etc.)

Worker Nodes

  • Kubelet : Agent sur chaque nœud, gère les pods
  • Kube-proxy : Gère le réseau et load balancing
  • Container Runtime : Docker, containerd, CRI-O

Objets Kubernetes fondamentaux

Objet Description Usage
Pod Plus petite unité déployable (1+ conteneurs) Conteneur(s) applicatif
Deployment Gère des ReplicaSets (pods répliqués) Applications stateless
Service Expose les pods sur le réseau Load balancing, DNS
ConfigMap Stocke configuration non sensible Fichiers config, variables
Secret Stocke données sensibles (mots de passe) Credentials, tokens
Namespace Isolation logique des ressources Multi-tenancy, environnements
Ingress Gère l'accès externe HTTP/HTTPS Routing, SSL termination

Qu'est-ce que DevOps ?

DevOps est une culture, un ensemble de pratiques et d'outils qui visent à unifier le développement logiciel (Dev) et l'administration système (Ops) pour livrer des applications plus rapidement et de manière plus fiable.

Principes DevOps

  • Culture de collaboration : Dev et Ops travaillent ensemble
  • Automatisation : Tests, déploiements, infrastructure
  • Mesure : Métriques et monitoring continus
  • Partage : Connaissance, responsabilités, succès/échecs
  • Amélioration continue : Itération, feedback, apprentissage

Pare-feu (Firewall)

Qu'est-ce qu'un pare-feu ?

Un pare-feu filtre le trafic réseau entrant et sortant selon des règles de sécurité définies, protégeant ainsi le système des accès non autorisés.

Types de pare-feu

Type Niveau OSI Fonction
Packet Filtering 3 (Réseau) Filtre par IP, port, protocole
Stateful 3-4 Suit les connexions établies
Application 7 (Application) Inspecte contenu applicatif
Next-Gen (NGFW) Toutes DPI, IPS, anti-malware intégrés

iptables (Linux)

# Voir les règles actuelles sudo iptables -L -n -v # Politique par défaut (BLOQUER tout) sudo iptables -P INPUT DROP sudo iptables -P FORWARD DROP sudo iptables -P OUTPUT ACCEPT # Autoriser loopback sudo iptables -A INPUT -i lo -j ACCEPT # Autoriser connexions établies sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT # Autoriser SSH (port 22) sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT # Autoriser HTTP et HTTPS sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT # Autoriser ping (ICMP) sudo iptables -A INPUT -p icmp --icmp-type echo-request -j ACCEPT # Bloquer une IP spécifique sudo iptables -A INPUT -s 192.168.1.100 -j DROP # Limiter les connexions SSH (anti brute-force) sudo iptables -A INPUT -p tcp --dport 22 -m state --state NEW -m recent --set sudo iptables -A INPUT -p tcp --dport 22 -m state --state NEW -m recent --update --seconds 60 --hitcount 4 -j DROP # Sauvegarder les règles # Ubuntu/Debian sudo apt install iptables-persistent sudo netfilter-persistent save # CentOS/RHEL sudo service iptables save # Supprimer une règle sudo iptables -D INPUT 3 # Supprimer règle n°3 sudo iptables -F # Vider toutes les règles

VPN (Virtual Private Network)

Qu'est-ce qu'un VPN ?

Un VPN crée un tunnel chiffré entre deux points sur un réseau public (Internet), permettant une communication sécurisée et privée.

Usages des VPN

  • Accès distant : Employés se connectant au réseau d'entreprise
  • Site-to-Site : Connecter deux bureaux/datacenters
  • Confidentialité : Masquer son IP et chiffrer le trafic
  • Sécurité Wi-Fi public : Protection sur réseaux non fiables
  • Contournement géo-blocage : Accès à contenus restreints

Types de VPN

Type Protocole Usage Sécurité
OpenVPN SSL/TLS Accès distant, flexible Très élevée
WireGuard Moderne, léger Performances, simplicité Très élevée
IPsec Natif IP Site-to-Site, entreprise Élevée
L2TP/IPsec Layer 2 + IPsec Mobile, compatible Moyenne
PPTP Point-to-Point Ancien, déprécié Faible (à éviter)

  • Majuscules, minuscules, chiffres, symboles

  • Utiliser un gestionnaire de mots de passe

Docker - Conteneurisation

Qu'est-ce que Docker ?

Docker est une plateforme de conteneurisation qui permet d'empaqueter des applications avec toutes leurs dépendances dans des conteneurs légers, portables et isolés.

Avantages de Docker

  • Portabilité : "Fonctionne sur ma machine" → Fonctionne partout
  • Isolation : Chaque conteneur est isolé
  • Légèreté : Plus léger qu'une VM (secondes vs minutes)
  • Reproductibilité : Même environnement dev/prod
  • Scalabilité : Déployer rapidement plusieurs instances

Concepts clés

  • Image : Template en lecture seule (ex: ubuntu:22.04, nginx:latest)
  • Conteneur : Instance en cours d'exécution d'une image
  • Dockerfile : Recette pour créer une image
  • Registry : Dépôt d'images (Docker Hub, GitHub Container Registry)
  • Volume : Stockage persistant pour les données
  • Network : Réseau pour connecter les conteneurs

Bonnes pratiques

  • Utilisez des images officielles de Docker Hub
  • Versionnez vos images (évitez `:latest` en production)
  • Un processus par conteneur (principe Unix)
  • Utilisez des images Alpine pour réduire la taille
  • Ne stockez jamais de secrets dans les images
  • Utilisez .dockerignore pour exclure les fichiers inutiles
  • Optimisez les couches du Dockerfile (mettez les moins changeantes en premier)

À éviter :

  • Exécuter en tant que root dans le conteneur
  • Installer des outils de développement en production
  • Utiliser `docker commit` (préférer Dockerfile)
  • Stockez des données importantes sans volumes
