01

.filter() — La syntaxe

Array → Array filtré

.filter() parcourt chaque élément du tableau et retourne un nouveau tableau contenant uniquement les éléments pour lesquels la fonction retourne true. Le tableau d'origine n'est jamais modifié.
syntaxe-filter.js
// ── Syntaxe complète ───
const resultat = tableau.filter(function(element, index, array) {
  return /* condition true/false */;
});

// ── Avec arrow function (la forme la plus courante) ──
const resultat = tableau.filter(element => /* condition */);

// ── Exemple concret ──
const nombres = [1, 8, 3, 12, 5, 20, 7];

const grands = nombres.filter(n => n > 6);
// → [8, 12, 20, 7]   ← nouveau tableau, nombres intact

// ── Les 3 paramètres disponibles ──
nombres.filter((element, index, array) => {
  console.log(element); // valeur courante : 1, 8, 3...
  console.log(index);   // indice courant  : 0, 1, 2...
  console.log(array);   // tableau entier (rarement utile)
  return element > 6;
});
// résultat : [8, 12, 20, 7]
Règle d'or : .filter() ne modifie jamais le tableau d'origine. Il retourne toujours un nouveau tableau — vide [] si aucun élément ne passe le test.
02

Filtrer des nombres

Les cas les plus fréquents

nombres-pairs.js
const nums = [1,2,3,4,5,6,7,8];

// Pairs
const pairs = nums.filter(n => n % 2 === 0);
// → [2, 4, 6, 8]

// Impairs
const impairs = nums.filter(n => n % 2 !== 0);
// → [1, 3, 5, 7]

// Entre deux valeurs
const entre = nums.filter(n => n >= 3 && n <= 6);
// → [3, 4, 5, 6]

// Positifs uniquement
const liste = [-3, 5, -1, 8, -2, 4];
const positifs = liste.filter(n => n > 0);
// → [5, 8, 4]
doublons-uniques.js
// Supprimer les doublons avec filter + indexOf
const avecDoublons = [1,2,2,3,3,3,4];

const uniques = avecDoublons.filter(
  (val, index, arr) => arr.indexOf(val) === index
);
// → [1, 2, 3, 4]
// indexOf retourne le 1er index trouvé
// si index !== 1er index → c'est un doublon

// Alternative moderne avec Set
const uniques2 = [...new Set(avecDoublons)];
// → [1, 2, 3, 4]

// Filtrer les valeurs falsy (0, null, '', undefined)
const messy = [1, null, '', 2, undefined, 0, 3];
const clean = messy.filter(Boolean);
// → [1, 2, 3]
03

Filtrer des tableaux d'objets

Le cas le plus fréquent en vrai projet

En projet réel, tu filtreras presque toujours des tableaux d'objets : utilisateurs, produits, commandes, articles... C'est le cas le plus important à maîtriser.
filter-objets.js
const users = [
  { id: 1, nom: 'Alice',  age: 28, role: 'admin',  actif: true  },
  { id: 2, nom: 'Bob',    age: 34, role: 'user',   actif: false },
  { id: 3, nom: 'Clara', age: 22, role: 'user',   actif: true  },
  { id: 4, nom: 'David', age: 45, role: 'admin',  actif: true  },
  { id: 5, nom: 'Eva',   age: 19, role: 'user',   actif: false },
];

// ── Filtrer par propriété booléenne ──
const actifs = users.filter(u => u.actif);
// → [Alice, Clara, David]

// ── Filtrer par valeur de propriété ───
const admins = users.filter(u => u.role === 'admin');
// → [Alice, David]

// ── Filtrer par condition numérique ──
const majeursActifs = users.filter(u => u.age >= 18 && u.actif);
// → [Alice, Clara, David]

// ── Filtrer en excluant un élément par id ────
const sansBob = users.filter(u => u.id !== 2);
// → [Alice, Clara, David, Eva]   ← simule un "delete"
recherche-temps-reel.js
// ── Pattern classique : barre de recherche temps réel ───
const produits = [
  { nom: 'MacBook Pro',  prix: 2499, stock: 5  },
  { nom: 'iPad Air',     prix: 799,  stock: 12 },
  { nom: 'iPhone 15',    prix: 1129, stock: 0  },
  { nom: 'AirPods Pro',  prix: 279,  stock: 30 },
];

function rechercherProduits(query) {
  const q = query.toLowerCase();
  return produits.filter(p =>
    p.nom.toLowerCase().includes(q)
  );
}

rechercherProduits('ipad');    // → [{ nom: 'iPad Air', ... }]
rechercherProduits('pro');     // → [MacBook Pro, AirPods Pro]

// ── Multi-filtres combinés ─────
function filtrerProduits({ query = '', maxPrix = Infinity, enStock = false }) {
  return produits.filter(p => {
    const matchNom   = p.nom.toLowerCase().includes(query.toLowerCase());
    const matchPrix  = p.prix <= maxPrix;
    const matchStock = enStock ? p.stock > 0 : true;
    return matchNom && matchPrix && matchStock;
  });
}

filtrerProduits({ maxPrix: 1000, enStock: true });
// → [iPad Air, AirPods Pro]
04

.find() et .findIndex()

Trouver un seul élément

Différence clé : .filter() retourne un tableau. .find() retourne le premier élément qui correspond (ou undefined). .findIndex() retourne l'index de cet élément (ou -1).
find.js
const users = [
  { id: 1, nom: 'Alice', age: 28 },
  { id: 2, nom: 'Bob',   age: 34 },
  { id: 3, nom: 'Clara', age: 22 },
];

// .find() → retourne l'OBJET directement
const user = users.find(u => u.id === 2);
// → { id: 2, nom: 'Bob', age: 34 }

// Si rien trouvé → undefined
const inconnu = users.find(u => u.id === 99);
// → undefined

// Toujours vérifier avant d'utiliser !
const found = users.find(u => u.age > 30);
if (found) {
  console.log(found.nom); // 'Bob'
}
findIndex.js
const fruits = ['pomme', 'banane', 'cerise', 'datte'];

// .findIndex() → retourne l'INDEX
const idx = fruits.findIndex(f => f === 'cerise');
// → 2

// Si rien trouvé → -1
const idx2 = fruits.findIndex(f => f === 'kiwi');
// → -1

// Cas d'usage : modifier un élément dans le tableau
const panier = [
  { id: 1, qte: 2 },
  { id: 2, qte: 1 },
  { id: 3, qte: 5 },
];

const i = panier.findIndex(p => p.id === 2);
if (i !== -1) {
  panier[i] = { ...panier[i], qte: 3 };
  // Mise à jour immuable
}
comparatif-methodes.js
Méthode Retourne Quand l'utiliser Si rien trouvé
.filter() Array (nouveau) Plusieurs éléments attendus [] (tableau vide)
.find() Élément Un seul élément attendu undefined
.findIndex() Number (index) Modifier/supprimer par index -1
.some() Boolean Vérifier si AU MOINS un correspond false
.every() Boolean Vérifier si TOUS correspondent true (tableau vide)
05

.some() et .every()

Tests booléens sur tableau

some.js
// .some() → true si AU MOINS 1 élément passe
const ages = [14, 17, 21, 16];

const unMajeur = ages.some(a => a >= 18);
// → true  (21 passe le test)

// Cas d'usage : stock disponible ?
const produits = [
  { nom: 'A', stock: 0 },
  { nom: 'B', stock: 5 },
  { nom: 'C', stock: 0 },
];

const stockDispo = produits.some(p => p.stock > 0);
// → true

// Email déjà utilisé ?
const users = [{ email: 'a@b.com' }, { email: 'c@d.com' }];
const emailExiste = users.some(u => u.email === 'a@b.com');
// → true ← email déjà pris !
every.js
// .every() → true SEULEMENT si TOUS passent
const notes = [15, 18, 12, 14];

const tousAdmis = notes.every(n => n >= 10);
// → true  (toutes les notes >= 10)

const tousMentionBien = notes.every(n => n >= 16);
// → false  (12 et 14 ne passent pas)

// Cas d'usage : formulaire valide ?
const champs = [
  { nom: 'prenom', valeur: 'Alice'  },
  { nom: 'email',  valeur: 'a@b.com' },
  { nom: 'tel',    valeur: ''       },
];

const formuValide = champs.every(c => c.valeur.trim() !== '');
// → false  (tel est vide)

Chaîner les méthodes

filter + map + sort + reduce

Le chaînage est l'une des techniques les plus puissantes en JavaScript. Chaque méthode retourne un tableau, ce qui permet d'enchaîner les opérations en une seule expression lisible.
chaining.js
const employes = [
  { nom: 'Alice',  dept: 'tech', salaire: 3200, actif: true  },
  { nom: 'Bob',    dept: 'rh',   salaire: 2800, actif: false },
  { nom: 'Clara',  dept: 'tech', salaire: 3800, actif: true  },
  { nom: 'David',  dept: 'tech', salaire: 2900, actif: true  },
  { nom: 'Eva',    dept: 'rh',   salaire: 3100, actif: true  },
];

// ── filter + map ───
// Noms des techniciens actifs
const nomsTech = employes
  .filter(e => e.dept === 'tech' && e.actif)
  .map(e => e.nom);
// → ['Alice', 'Clara', 'David']

// ── filter + sort + map ──
// Actifs triés par salaire décroissant
const topSalaires = employes
  .filter(e => e.actif)
  .sort((a, b) => b.salaire - a.salaire)
  .map(e => `${e.nom} (${e.salaire}€)`);
// → ['Clara (3800€)', 'Eva (3100€)', 'Alice (3200€)', 'David (2900€)']

// ── filter + reduce : total salaires tech actifs ───
const massesTech = employes
  .filter(e => e.dept === 'tech' && e.actif)
  .reduce((total, e) => total + e.salaire, 0);
// → 9900  (3200 + 3800 + 2900)
// nomsTech : ['Alice', 'Clara', 'David']

Cas avancés

Regex, imbriqué, async

filter-avance.js
// ── Filtrer avec une regex ─
const emails = ['alice@gmail.com', 'bob@yahoo.fr', 'clara@gmail.com', 'noreply@'];

const validEmails = emails.filter(e => /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(e));
// → ['alice@gmail.com', 'bob@yahoo.fr', 'clara@gmail.com']

const gmailSeulement = emails.filter(e => e.endsWith('@gmail.com'));
// → ['alice@gmail.com', 'clara@gmail.com']

// ── Filtrer sur propriété imbriquée ─
const commandes = [
  { id: 1, client: { ville: 'Paris'  }, total: 120 },
  { id: 2, client: { ville: 'Lyon'   }, total: 85  },
  { id: 3, client: { ville: 'Paris'  }, total: 220 },
];

const parisiens = commandes.filter(c => c.client?.ville === 'Paris');
// → [{ id: 1 ... }, { id: 3 ... }]
// ?.  = optional chaining → évite le crash si client est null

// ── Filtrer un tableau dans un tableau ──
const articles = [
  { titre: 'JS Basics',  tags: ['js', 'débutant']        },
  { titre: 'React Hooks', tags: ['react', 'js', 'avancé'] },
  { titre: 'CSS Grid',    tags: ['css', 'débutant']       },
];

const articlesJS = articles.filter(a => a.tags.includes('js'));
// → [JS Basics, React Hooks]
filter-async.js
// .filter() ne supporte PAS les callbacks async directement !
// Ce code NE fonctionne PAS :
const result = ids.filter(async id => {
  const user = await fetchUser(id); // ← .filter reçoit une Promise, pas true/false
  return user.actif;
});

//  Solution correcte : Promise.all + filter
async function filtrerActifs(ids) {
  // 1. Récupérer toutes les données d'abord
  const users = await Promise.all(ids.map(id => fetchUser(id)));
  // 2. Ensuite filtrer de façon synchrone
  return users.filter(u => u.actif);
}

// Alternative avec reduce async
async function filterAsync(arr, asyncPredicate) {
  const results = await Promise.all(arr.map(asyncPredicate));
  return arr.filter((_, i) => results[i]);
}

// Utilisation :
const actifs = await filterAsync(users, async u => {
  const data = await checkStatus(u.id);
  return data.actif;
});
// Règle : toujours résoudre les Promises AVANT de filter()

Erreurs fréquentes

Pièges à éviter absolument

erreurs.js
// Oublier le return dans un bloc {}
const mauvais = nums.filter(n => {
  n > 5; // ← pas de return → retourne undefined = false
});
// → [] ← tableau toujours vide !

// Correct
const bon = nums.filter(n => {
  return n > 5; // ← avec return
});

// Confondre filter et find
const user = users.filter(u => u.id === 1);
user.nom; // undefined — filter retourne un ARRAY !

// Utiliser find pour un seul objet
const user2 = users.find(u => u.id === 1);
user2.nom; // 'Alice'
autres-pieges.js
// Modifier le tableau original dans filter
const arr = [1, 2, 3, 4];
arr.filter((n, i, a) => {
  a.splice(i, 1); // mutation pendant l'itération → comportement imprévisible
  return n > 2;
});

// Comparer des objets avec ===
const cible = { id: 1 };
users.filter(u => u === cible);
// → [] toujours ! Deux objets ne sont jamais === sauf référence identique

// Comparer une propriété
users.filter(u => u.id === cible.id); // 

//  Ne pas gérer undefined après find
const u = users.find(x => x.id === 99);
u.nom; //  TypeError: Cannot read properties of undefined

// Toujours vérifier
u?.nom;         // undefined (pas de crash)
u && u.nom;     // undefined
10

À retenir

Les règles d'or

Jamais de mutation

.filter() retourne toujours un nouveau tableau. Ne jamais modifier l'original dans le callback.

filter vs find

Tu attends plusieurs résultats → .filter(). Tu attends UN résultat → .find().

Chaîne sans peur

filter → map → sort → reduce. Chaque méthode retourne un tableau, tu peux enchaîner indéfiniment.

Toujours vérifier find()

Si .find() ne trouve rien il retourne undefined. Utilise ?. ou un if avant d'accéder aux propriétés.

Pas d'async dans filter

Résous toutes tes Promises avec Promise.all() avant de filtrer. Jamais de callback async direct.

Nettoyer avec Boolean

.filter(Boolean) supprime tous les null, undefined, 0, '' en une seule ligne.
