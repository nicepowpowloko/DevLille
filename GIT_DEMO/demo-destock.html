Ce que tu dis aux stagiaires
Je suis Alice. Je cree le projet sur GitHub et j'invite mon equipier Bob. On commence toujours par creer le repo en ligne avant de toucher a quoi que ce soit en local.
GitHub Web — github.com/new
1 Repository name : mon-projet-duo
2 Visibilite : Public
3 Cocher "Add a README file" — indispensable
4 .gitignore template : choisir Node
5 Cliquer "Create repository"
GitHub Desktop — cloner le repo
1 File > Clone repository
2 Onglet GitHub.com — trouver mon-projet-duo
3 Choisir le dossier local puis Clone
Montrer : "Current Branch: main" apparait en haut de GitHub Desktop apres le clone.
Piege a expliquer
Sans "Add README" coche, le repo est vide — pas de commit initial, pas de branche main. GitHub Desktop affiche une erreur au clone. Toujours cocher cette case.
Ce que tu dis
Bob peut lire le repo, mais pas ecrire dedans. Sans invitation, son push sera refuse avec une erreur 403 Forbidden. Il faut l'ajouter comme collaborateur.
GitHub Web — Settings du repo
1 Sur la page du repo — onglet Settings dans la barre en haut
2 Menu gauche — Collaborators
3 Bouton "Add people"
4 Taper le pseudo GitHub de Bob — confirmer l'ajout
Montrer : la page affiche "Invitation sent" avec l'email de Bob en attente.
Bob — accepter l'invitation
1 Bob recoit un email — cliquer "View invitation"
2 Ou aller sur github.com/notifications
3 Cliquer "Accept invitation"
Piege classique
Settings du repo (dans la barre d'onglets du repo) est different du Settings du compte (avatar en haut a droite). Erreur tres frequente chez les debutants.
Ce que tu dis
Maintenant je suis Bob. J'ai accepte l'invitation. Je clone le projet sur ma machine. Le clone copie tout l'historique Git en local.
GitHub Desktop — Bob clone
1 File > Clone repository
2 Onglet GitHub.com — chercher alice-dev/mon-projet-duo
3 Choisir un dossier different du dossier d'Alice
4 Clone — Bob est sur main
Montrer les deux fenetres GitHub Desktop cote a cote — meme repo, meme etat initial.
VSCode — ouvrir le projet
1 Dans GitHub Desktop — bouton "Open in Visual Studio Code"
2 VSCode s'ouvre avec le dossier du projet
3 En bas a gauche : la branche courante main est visible
OK
Checkpoint
Alice et Bob ont tous les deux le projet en local sur main. Etape suivante : chacun cree sa propre branche avant de coder.
Ce que tu dis
Regle absolue : on ne code jamais directement sur main. Chacun cree une branche pour sa fonctionnalite. On peut travailler en parallele sans se bloquer mutuellement.
Alice — sa branche
1 Cliquer sur "Current Branch: main"
2 "New Branch"
3 Nom : feature/navbar
4 "Create Branch"
Bob — sa branche
1 Meme chose de son cote
2 Nom : feature/login
3 "Create Branch"
VSCode confirme le changement
1 En bas a gauche de VSCode : main est passe a feature/navbar
2 GitHub Desktop et VSCode sont synchronises en temps reel
Moment fort : montrer que le badge de branche en bas de VSCode change en meme temps que dans GitHub Desktop.
Convention de nommage
feature/ nouvelle fonctionnalite  ·  fix/ correction  ·  chore/ config — toujours en minuscules avec tirets, sans espaces.
Ce que tu dis
Je cree mon fichier Navbar dans VSCode. Regardez GitHub Desktop en meme temps — il detecte le fichier automatiquement des la sauvegarde. C'est le moment le plus parlant de toute la demo.
VSCode — creer le fichier
1 Creer le dossier src/ dans l'explorateur VSCode
2 Creer le fichier src/Navbar.jsx
3 Taper ce code minimal :
export default function Navbar() {
  return <nav>Ma Navbar</nav>
}
4 Cmd+S (Mac) ou Ctrl+S (Windows) pour sauvegarder
Passer IMMEDIATEMENT dans GitHub Desktop apres la sauvegarde — l'effet est instantane.
GitHub Desktop — detection automatique
1 Panneau gauche : src/Navbar.jsx apparait avec un + vert
2 Panneau droit : le diff montre les lignes ajoutees en vert
3 Champ Summary en bas : taper feat: ajout composant Navbar
4 Bouton bleu "Commit to feature/navbar"
5 Bouton en haut "Publish branch" = git push
Montrer le diff vert dans le panneau droit — c'est ce que Bob verra dans la PR pour relire le code.
Convention messages de commit
feat: nouvelle fonctionnalite  ·  fix: correction  ·  style: mise en forme  ·  docs: documentation  ·  refac: refactoring
Ce que tu dis
J'ai pushe ma branche. Je demande maintenant a Bob de relire mon code avant de le fusionner dans main. C'est ca une Pull Request — une demande formelle de validation.
GitHub Desktop — creer la PR en 1 clic
1 Apres le push, une banniere apparait : "Create Pull Request"
2 Cliquer dessus — GitHub s'ouvre sur le bon formulaire automatiquement
La banniere disparait apres quelques secondes — cliquer vite ou aller dans Branch > Create Pull Request.
GitHub Web — remplir le formulaire de PR
1 Titre : feat: ajout navbar responsive
2 Description : ce qui a ete fait, pourquoi
3 Reviewers — cliquer l'engrenage — ajouter bob-dev
4 Bouton vert "Create pull request"
Montrer : "base: main <-- compare: feature/navbar". Expliquer le sens de la fleche — c'est ce qui va ou.
OK
Checkpoint
La PR est ouverte. Bob recoit une notification. main n'a PAS encore change — le code d'Alice est en attente de validation.
Ce que tu dis
Je suis maintenant Bob. J'ai recu la notification. Je vais relire le code d'Alice avant de valider. On ne merge jamais sans relire — meme en formation.
Bob relit la PR — GitHub Web
1 Aller sur la PR — onglet "Files changed"
2 Lire les lignes vertes (+) ajoutees, rouges (-) supprimees
3 Cliquer sur le + d'une ligne pour laisser un commentaire inline
4 Bouton "Review changes" — Approve — "Submit review"
Faire un vrai commentaire en live — les stagiaires voient l'utilite du code review.
Alice merge
1 Apres approbation de Bob — bouton vert "Merge pull request"
2 "Confirm merge"
3 "Delete branch" — garder le repo propre
Les deux — recuperer main a jour
1 Dans GitHub Desktop : switcher sur la branche main
2 Bouton "Fetch origin" puis "Pull origin"
3 VSCode se met a jour — Navbar.jsx apparait dans l'arborescence
Moment final : Navbar.jsx est dans VSCode sur main. Il est arrive via le merge, pas par copie manuelle.
FIN
Workflow complet
branch > commit > push > PR > review > merge > pull
C'est ce cycle que les stagiaires repeteront tous les jours en entreprise.
